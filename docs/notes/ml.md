## 第1章 引言

![机器学习工作流与 scikit-learn 估计器接口](/ml/ml-workflow.svg)

### 1.1 为什么需要机器学习

早期「智能」应用靠人工编写 `if / else` 规则（例如垃圾邮件关键词黑名单）。这种专家规则体系有两个根本缺点：

1. 逻辑只适用于**单一领域、单项任务**，任务稍变就要重写整个系统；
2. 需要**深刻理解人类专家的决策过程**，而很多感知任务（如人脸检测）人类根本无法把判定规则显式写出来。

机器学习把「从已知示例中**泛化**」这一步自动化：给算法输入 / 输出对，算法自己找出映射，并能对前所未见的输入给出预测。

| 类型 | 数据 | 目标 | 示例 |
| --- | --- | --- | --- |
| **监督学习** | 输入 + 预期输出（有标签） | 对新输入预测输出 | 手写邮编识别、肿瘤良恶性判断、信用卡欺诈检测 |
| **无监督学习** | 只有输入，无输出 | 发现结构、表示或分组 | 博客主题归纳、客户分群、异常访问检测 |

**术语**：表格中的每一行是一个**样本（sample）/ 数据点**，每一列是一个**特征（feature）**；把数据整理成合适表示的过程叫**特征提取 / 特征工程**。书中反复强调：如果数据里根本不含某信息（例如只有姓氏想预测性别），任何算法都无能为力；**理解数据与任务的关系，比随机挑一个算法重要得多**。

建模前应先回答：想回答什么问题？已有数据能否回答？怎样把问题表述成机器学习问题？数据是否足够？收集数据会有什么伦理与隐私成本？

### 1.3 scikit-learn 估计器接口（★）

所有算法（预处理、监督、无监督）都实现为**估计器（Estimator）类**：

```python
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier

X_train, X_test, y_train, y_test = train_test_split(
    iris['data'], iris['target'], random_state=0)   # 默认 75% 训练 / 25% 测试

knn = KNeighborsClassifier(n_neighbors=1)           # 1. 实例化并设参数
knn.fit(X_train, y_train)                           # 2. 用训练数据构建模型
y_pred = knn.predict(X_new)                         # 3. 预测（输入必须是二维数组）
print(knn.score(X_test, y_test))                    # 4. 评估：分类默认精度
```

**接口约定**：

| 方法 | 作用 |
| --- | --- |
| `fit(X, y)` | 学习模型；`X` 为二维连续值数组 / 稀疏矩阵，`y` 为一维目标（监督学习需要） |
| `predict(X)` | 产生新输出（分类标签、回归值、簇标签） |
| `transform(X)` | 产生输入数据的**新表示**（缩放、降维、特征提取） |
| `fit_transform(X)` | `fit` 与 `transform` 合并 |
| `score(X, y)` | 评估；分类默认**精度**，回归默认 **R²** |

> **调用 `fit` 会重置模型之前学到的全部内容**——对同一对象再次 `fit`，等同于在一个全新模型上 `fit`。

### 1.4 第一个应用：鸢尾花分类

1. **初识数据**：`load_iris()` 有 150 朵花、4 个特征（花萼/花瓣长宽）、3 个类别，是**三分类**监督问题；数据通常是 `Bunch` 对象（含 `data`、`target`、`target_names`、`DESCR`）。
2. **划分数据**：不能用训练数据评估模型——模型会「记住」整个训练集，这种记忆无法说明**泛化能力**。`train_test_split` 先用伪随机数打乱再切分（默认 75% / 25%），否则按标签排序的数据会让测试集只剩一个类别。
3. **观察数据**：先可视化（散点图 / 散点图矩阵），不要一上来就建模。散点图矩阵两两查看特征，但**无法同时显示多个特征间的联合关系**。
4. **建模**：k 近邻取训练集中距离最近的 k 个邻居，用多数类别投票；`KNeighborsClassifier(n_neighbors=1)`。
5. **评估**：测试集精度约 **0.97**（97%），意味着对新鸢尾花的预测约 97% 正确。

### 1.5 易错点

- `train_test_split` 必须**先打乱**再切分；`random_state` 只影响可复现性，不影响打乱本身。
- 预测单条数据时也要构造成**二维数组**（`X_new.reshape(1, -1)` 或 `[[...]]`），scikit-learn 不接受一维输入。
- 精度高不等于模型可用：第 5 章会说明类别不平衡时 90% 精度可能来自「永远预测多数类」。

## 第2章 监督学习

![泛化、欠拟合与过拟合](/ml/ml-overfitting.svg)

### 2.1 分类与回归

**每当想要根据给定输入预测某个结果，且有输入 / 输出对的示例时，就用监督学习**。这些对构成训练集，目标是对未见过的新数据准确预测。

| 任务 | 输出 | 例子 | `score` 默认指标 |
| --- | --- | --- | --- |
| **分类** | 离散的**类别**（class） | 鸢尾花品种、 spam / 非 spam | 精度 accuracy |
| **回归** | 连续值 | 房价、内存价格、租车数量 | **R²（决定系数）** |

R² = 1 为完美预测，R² = 0 相当于「总预测训练集平均值」的常数模型，也可能为负（比常数模型更差）。二分类是最容易理解的情形，但书中大多数算法**既能分类也能回归**，且分类算法都能用于多分类。

### 2.2 泛化、过拟合与欠拟合（★）

| 概念 | 含义 | 典型信号 |
| --- | --- | --- |
| **泛化** | 模型在**前所未见的新数据**上表现良好的能力 | 训练集与测试集分数接近且都高 |
| **过拟合** | 过分关注训练数据，把噪声也拟合进去 | 训练集分数很高、测试集明显更低 |
| **欠拟合** | 模型太简单，连训练数据中的变化都抓不住 | 训练集与测试集分数**都低且接近** |

**模型复杂度与数据集大小**：存在一个最佳复杂度使泛化性能最好。数据集越大，可容纳的模型复杂度越高——**增大数据量往往比反复调参更有效**。注意「训练集和测试集分数都很接近且偏低」通常说明**欠拟合**而非过拟合（一维线性回归就是例子）。

**常用样本数据集**：`forge`（二分类玩具数据）、`wave`（一维回归）、`cancer`（乳腺癌，569 样本 / 30 特征）、`boston_housing`（回归，506 样本 / 13 特征，扩展交互项后 105 特征）、`iris`、`digits`、`make_blobs` / `make_moons`。

### 2.3 监督学习算法（上）

![监督学习算法选型速查](/ml/ml-algorithms.svg)

#### 2.3.1 k 近邻（k-NN）

```python
from sklearn.neighbors import KNeighborsClassifier, KNeighborsRegressor
clf = KNeighborsClassifier(n_neighbors=3).fit(X_train, y_train)
reg = KNeighborsRegressor(n_neighbors=3).fit(X_train, y_train)
```

- **原理**：找训练集中距离最近的 k 个邻居，分类按多数投票，回归取平均。
- **关键参数**：`n_neighbors`（越小模型越复杂、边界越曲折；越大越平滑）。
- **优点**：模型简单、容易解释、适合**小型数据集**，是很好的**基准模型**。
- **缺点**：样本多或特征多时预测慢；对**高维稀疏数据**几乎无效；**必须缩放特征**（基于距离）。

#### 2.3.2 线性模型

预测公式：**ŷ = w[0]·x[0] + w[1]·x[1] + … + w[p]·x[p] + b**，其中 `w` 存于 `coef_`、`b` 存于 `intercept_`。

| 模型 | 类别 | 正则化 | 关键参数与特点 |
| --- | --- | --- | --- |
| `LinearRegression` | 回归 | 无 | 无参数；高维时容易过拟合 |
| **Ridge**（岭回归） | 回归 | **L2**：系数整体趋近 0 | `alpha`，默认 1.0；增大 alpha → 系数更小、训练集性能降、泛化可能升 |
| **Lasso** | 回归 | **L1**：部分系数**恰为 0**，可自动选特征 | `alpha`；减小 alpha 可缓解欠拟合，常需同时增大 `max_iter` |
| `LogisticRegression` | 分类 | 默认 L2 | `C`（**正则化强度的倒数**，C 越大约束越弱、模型越复杂）；`penalty='l1'` 可得更易解释的稀疏模型 |
| `LinearSVC` | 分类 | 默认 L2 | `C`，与 LogisticRegression 决策边界相似 |

**要点**：

- 训练集与测试集分数都低且接近 → **欠拟合**（如默认 alpha=1.0 的 Lasso 在波士顿数据上只用了 105 个特征中的 4 个）；
- 训练与测试分数接近但偏低 → 模型可能欠拟合；训练远高于测试 → 过拟合；
- 线性模型**训练与预测都极快**，能扩展到十万/百万级样本，对**稀疏数据效果好**；大数据可用 `solver='sag'` 或 `SGDClassifier` / `SGDRegressor`；
- 多分类常用「一对多（one-vs-rest）」，`decision_function` 每类一个分数，`classes_` 给出类别顺序，取 argmax 即预测。

#### 2.3.3 朴素贝叶斯分类器

| 类 | 适用数据 |
| --- | --- |
| `GaussianNB` | 连续特征（任意维度） |
| `BernoulliNB` | 二元 / 0-1 特征，计算每个类别中每个特征**不为 0 的元素个数** |
| `MultinomialNB` | 计数数据（典型是文本词频） |

`coef_` 不适用，核心参数是 `alpha`（平滑）。**只用于分类**；比线性模型还快，适合**超大数据集与高维数据**，训练速度极快、可解释性尚可，但**精度通常低于线性模型**（特征独立性假设过强）。

#### 2.3.4 决策树

```python
from sklearn.tree import DecisionTreeClassifier, DecisionTreeRegressor
tree = DecisionTreeClassifier(max_depth=4, random_state=0).fit(X_train, y_train)
print(tree.feature_importances_)   # 特征重要性，总和为 1
```

- **原理**：对特征做一系列「if/else」判断，叶结点给出预测；回归叶结点输出该区域内训练目标的均值。
- **控制复杂度**：不预剪枝会长到所有叶结点**纯**为止 → 训练集 100% 精度、严重过拟合。常用预剪枝参数 `max_depth`、`max_leaf_nodes`、`min_samples_leaf`。
- **优点**：速度快、**不需要缩放**、可可视化（`export_graphviz`）、容易解释；`feature_importances_` 可查看每个特征的重要性。
- **缺点**：即使预剪枝也**经常过拟合、泛化差**；决策边界是轴平行的；**不能外推**到训练数据范围之外（Citi Bike 案例中随机森林与树在未来时间上给出常数预测，R² 为负）。实践中多用下面的集成方法替代单棵树。

> 决策树回归与线性回归在「分箱后」的差异：分箱让**线性模型**更灵活（每个箱子一个取值），却让**决策树**灵活性下降——因为树本来就能自己学出最优分箱位置。

#### 2.3.5 决策树集成

**集成（ensemble）** 是合并多个机器学习模型来构建更强大模型的方法，书中重点是两种树集成。

| 项目 | **随机森林** `RandomForestClassifier/Regressor` | **梯度提升决策树** `GradientBoostingClassifier/Regressor` |
| --- | --- | --- |
| 思想 | 多棵**相互独立、略有差异**的树，结果取平均 | 串行**纠正前一棵树的错误**，每棵树都浅（弱学习器） |
| 随机性来源 | 自助采样（bootstrap）+ `max_features` 随机选特征 | 主要靠连续拟合残差，随机性较少 |
| 常用参数 | `n_estimators`、`max_features`、`max_depth`、`n_jobs=-1` | `n_estimators`、`learning_rate`、`max_depth`（默认 3）、`subsample` |
| 默认 | 树完全生长；分类 `max_features=sqrt(n_features)`，回归 `max_features=n_features` | 默认 100 棵树、深度 3、学习率 0.1 |
| 调参 | `max_features` 大 → 树相似；小 → 树差异大、需更深 | `learning_rate` 与 `n_estimators` 需权衡；常需更多调参 |
| 表现 | 几乎总优于单棵树，鲁棒、不需缩放 | 精度**通常略高于**随机森林；训练更慢、预测更快、内存更省 |

**随机森林要点**：

- 不需要数据缩放，**不适用于高维稀疏数据**（如文本），这类数据用线性模型更合适；
- 大数据集表现通常很好，可 `n_jobs` 并行；但**内存占用大、训练与预测比线性模型慢**；
- `max_features` 是最关键的随机性旋钮；`feature_importances_` 比单棵树更稳定可靠。

**梯度提升要点**：对参数更敏感，`learning_rate` 越小通常需要越多的树；大规模问题可参考 `xgboost`（书中提到其速度常优于 scikit-learn 实现）。

#### 2.3.6 核支持向量机（SVM）

```python
from sklearn.svm import SVC
svm = SVC(kernel='rbf', C=1.0, gamma='scale').fit(X_train, y_train)
```

- **线性 SVM 与核技巧**：在高维空间里学习线性决策边界，等价于原空间的非线性边界；常用 **RBF（高斯）核**。
- **支持向量**：位于类别边界附近、决定边界位置的关键训练点；预测只依赖这些点。
- **两个关键参数**：

| 参数 | 作用 | 太小 / 太大 |
| --- | --- | --- |
| `C` | 正则化参数（与线性模型同向：C 大 = 约束弱） | 太小 → 边界近乎线性、误分类点影响小；太大 → 边界剧烈弯曲去迁就个别点 |
| `gamma` | RBF 核宽度（决定单个点影响范围） | 太小 → 影响范围大、模型简单；太大 → 每个点各自成岛、过拟合 |

- **优点**：对**特征含义相似的中等规模**数据集非常强大，决策边界平滑。
- **缺点**：**必须缩放数据**（否则尺度大的特征主导距离）；**对参数敏感**；样本量很大时训练慢；概率输出需要额外校准。

#### 2.3.7 神经网络（深度学习）

```python
from sklearn.neural_network import MLPClassifier
mlp = MLPClassifier(hidden_layer_sizes=(100,), activation='relu',
                    solver='adam', alpha=0.0001, max_iter=200,
                    random_state=0).fit(X_train_scaled, y_train)
```

- **多层感知机（MLP）** 即普通前馈网络：输入层 → 一个或多个隐层（非线性 `relu` / `tanh`）→ 输出层。
- **复杂度控制**：隐层数、每层隐单元数、L2 惩罚 `alpha`。权重总数 = 各层结点数乘积之和（100 特征 + 100 隐单元 ≈ 10 100 个权重；加第二隐层翻到约 20 100 个）。
- **调参套路**：先建一个**大到能过拟合**的网络确认任务可学，再缩小网络或增大 `alpha` 提升泛化。
- `solver`：`'adam'`（默认，多数情况好用但**对缩放敏感**）、`'lbfgs'`（鲁棒但大数据慢）、`'sgd'`（参数最多）。入门推荐 adam 与 lbfgs。
- **必须缩放**：所有输入特征应**均值 0、方差 1**；书中乳腺癌数据缩放后精度明显提升，否则会出现「达到最大迭代次数」警告。
- **随机初始化**：权重随机设置，相同参数不同 `random_state` 可能得到不同模型（小网络尤其明显）。
- **优缺点**：给定足够数据与算力、仔细调参，能构建极复杂模型并常击败其他算法；但训练时间长、需要仔细预处理、调参本身是门艺术、可解释性差。scikit-learn 不支持 GPU，更灵活的模型应用 keras / TensorFlow 等框架。

### 2.4 分类器的不确定度估计

| 方法 | 输出 | 说明 |
| --- | --- | --- |
| `decision_function` | 二分类形状 `(n_samples,)`，多分类 `(n_samples, n_classes)` | 正值偏向正类、负值偏向反类；**看符号即可复现 predict** |
| `predict_proba` | 二分类恒为 `(n_samples, 2)`，多分类每类一列 | 每行和为 1；取 argmax 复现预测；通常比决策函数更易解释 |

**注意**：

- 不是所有分类器都有这两个方法，多数至少有一个；
- 多分类对比 `predict` 与 `decision_function` 时**务必用 `classes_` 属性**对齐列顺序，类别是字符串或非 0 起始整数时尤其容易错；
- 不确定度反映的是「模型 + 参数」的置信度：**过拟合模型可能给出置信度很高但错误的预测**；若预测 70% 确定时确实 70% 正确，称模型已被**校正（calibrated）**。

### 2.5 何时使用哪种模型（★ 全书速查表）

| 模型 | 书中结论 |
| --- | --- |
| **最近邻** | 适用于小型数据集，很好的基准模型，容易解释 |
| **线性模型** | 非常可靠的**首选**算法，适用于非常大的数据集与高维数据 |
| **朴素贝叶斯** | 只用于分类；比线性模型更快，适合超大数据与高维数据；精度通常低于线性模型 |
| **决策树** | 速度快、不需缩放、可可视化、易解释；但常过拟合 |
| **随机森林** | 几乎总优于单棵决策树，鲁棒、强大、不需缩放；**不适用于高维稀疏数据** |
| **梯度提升决策树** | 精度通常略高于随机森林；训练更慢、预测更快、内存更省；需要更多参数调节 |
| **支持向量机** | 对特征含义相似的中等规模数据集很强大；**需要缩放、对参数敏感** |
| **神经网络** | 能构建极复杂模型，尤其适合大数据；**对缩放与参数都敏感**，大型网络训练很久 |

**实践顺序**：面对新数据集，先从**简单模型**（线性模型、朴素贝叶斯、最近邻）起步作为基线，理解数据后再尝试随机森林、梯度提升、SVM、神经网络。

### 2.6 易错点

- **C 是正则化强度的倒数**：`C` 越大模型越复杂；而 Ridge / Lasso 的 `alpha` 越大模型越简单，方向相反。
- 线性模型 / SVM / 神经网络 / k-NN **需要缩放**；决策树、随机森林、朴素贝叶斯**不需要缩放**。
- 训练集与测试集分数**都低且接近**是欠拟合，不是过拟合。
- 决策树与随机森林**无法外推**到训练特征范围之外；时间序列/未来预测不要直接用原始时间戳喂给树模型。
- `predict_proba` 的列顺序来自 `classes_`，不是「0/1」的直觉顺序。

## 第3章 无监督学习与预处理

![预处理缩放与训练/测试一致性](/ml/ml-preprocess.svg)

### 3.1 无监督学习的类型与挑战

| 类型 | 含义 | 典型方法 |
| --- | --- | --- |
| **无监督变换** | 创建数据的**新表示**，使其更易被人或算法理解 | 降维（PCA、NMF、t-SNE）、缩放、特征提取 |
| **聚类** | 把数据点划分成若干组，组内相似 | k 均值、凝聚聚类、DBSCAN |

**核心挑战**：没有标签，也就没有「标准答案」，**很难量化算法的有用性**，评估往往是定性的、探索性的。但无监督方法在监督学习中同样重要——很多算法（SVM、神经网络、k-NN）对**数据缩放**极其敏感。

### 3.2 预处理与缩放（★）

```python
from sklearn.preprocessing import MinMaxScaler, StandardScaler
scaler = MinMaxScaler().fit(X_train)      # 只在训练集上 fit！
X_train_scaled = scaler.transform(X_train)
X_test_scaled  = scaler.transform(X_test)  # 用同一变换，绝不重新 fit
```

| 变换器 | 效果 | 适用 |
| --- | --- | --- |
| `StandardScaler` | 每特征均值 0、方差 1（不限制范围） | 线性模型、SVM、神经网络的**默认首选** |
| `MinMaxScaler` | 每特征缩放到 [0, 1] | 需要固定边界、图像像素等 |
| `RobustScaler` | 用中位数与四分位数，忽略离群点 | 数据含明显异常值 |
| `Normalizer` | 按**样本**（行）缩放到单位范数 | 文本 / 方向型数据 |

**铁律（书中用一整节强调）**：`fit` 只在训练集上做，训练与测试应用**完全相同的变换**。`transform` 总是减去**训练集**的最小值、除以**训练集**的范围，因此测试集缩放后**可能超出 [0, 1]**——这是正常现象，不是 bug。

若分别对训练集与测试集各自 `fit`，两图看起来都「规整」，但**相对位置被改变**，模型学到的是错的数据分布，评估结果不可信。这正是第 6 章「数据泄露」的轻量版本。

**缩放带来的收益**：书中 cancer 数据集上 SVM 缩放前精度明显偏低、缩放后达 **0.97**；神经网络缩放后也大幅提升。

### 3.3 降维、特征提取与流形学习

| 方法 | 原理 | 特点与用途 |
| --- | --- | --- |
| **PCA（主成分分析）** | 先减去均值、再旋转到方差最大的正交方向，保留前 k 个主成分 | 无监督、线性；`components_` 每行一个主成分按重要性排序；`explained_variance_ratio_` 看解释方差；常用于可视化与去噪；成分/系数**可正可负**，解释性弱 |
| **NMF（非负矩阵分解）** | 把数据分解为**非负**分量与非负系数的加权和 | 适合由多个独立源**叠加**而成的数据（音轨、多乐器音乐、人脸）；分量全为正，**比 PCA 更易解释**（无正负抵消） |
| **t-SNE（流形学习）** | 保持高维空间中点的「邻近关系」，映射到 2D / 3D | **只用于可视化**，不能用于训练或变换新数据；无监督却能清楚分开类别；对 `perplexity` 等参数敏感 |

**PCA 用法**：

```python
from sklearn.decomposition import PCA
pca = PCA(n_components=2).fit(X_scaled)   # 默认仅旋转保留全部成分
X_pca = pca.transform(X_scaled)
```

- 应用 PCA **前先缩放**，否则尺度大的特征会主导方差；
- 人脸识别中先取前 100 个主成分，再用 `pca.inverse_transform` 回到原空间可视化；
- PCA 是「旋转 + 丢弃方向」的线性方法，对非线性结构（如 two_moons）无能为力，这时用 t-SNE 或核方法。

### 3.4 聚类算法（★）

![三种聚类算法的对比](/ml/ml-clustering.svg)

#### k 均值（KMeans）

```python
from sklearn.cluster import KMeans
km = KMeans(n_clusters=3, random_state=0).fit(X)
labels = km.labels_          # 或 km.predict(X_new)
centers = km.cluster_centers_
```

1. 随机选 k 个点作**簇中心**；2. 每个点分配给最近中心；3. 中心更新为所分配点的**均值**；4. 重复直到分配不再变化。

- **必须指定簇数**；可用 `cluster_centers_` 表示簇，也可视为一种「分解」（每个点由其中心表示）。
- **假设**：各簇大小相近、各方向同等重要、簇呈凸形（球形）。对沿对角线拉长的簇、复杂形状簇**失效**。
- 簇中心是平均值，因此人脸聚类得到的中心是「平滑的平均脸」。

#### 凝聚聚类（AgglomerativeClustering）

- **自底向上**：每个点初始为一组，反复合并最相似的两组，形成**层次结构**。
- `linkage`：`'ward'`（默认，方差增加最小 → 大小相近的簇）、`'average'`、`'complete'`。
- 需指定 `n_clusters`；scikit-learn 不画树状图，可用 `scipy.cluster.hierarchy.dendrogram` 辅助判断合适的切割点。
- 优点：给出**完整的层次划分**，可通过树状图查看；缺点：同样倾向大小相近的簇，不能识别噪声点。

#### DBSCAN

- **基于密度**：从**核心样本**（`min_samples` 邻域内点数足够）出发扩展簇；`eps` 定义「邻近」的距离。
- **不需要预先指定簇数**，能自动判断簇数，能识别**噪声点**（标签 -1），能处理**复杂形状**的簇。
- 参数：`eps` 太小 → 全是噪声；太大 → 全部并成一个簇。`min_samples` 越小，越小的点组被视为簇。
- 缺点：可能产生大小差异很大的簇；比 k 均值与凝聚稍慢，但可扩到较大数据集。

| 维度 | k 均值 | 凝聚聚类 | DBSCAN |
| --- | --- | --- | --- |
| 需指定簇数 | 是 | 是 | **否** |
| 噪声点 | 无（全部归属） | 无 | **有（标签 -1）** |
| 簇形状 | 凸 / 球形 | 凸形为主 | **任意复杂形状** |
| 层次结构 | 无 | **有（树状图）** | 无 |
| 输出中心 | **有** `cluster_centers_` | 无 | 无 |

#### 聚类的评估

- **不能用精度（accuracy）**：簇标签本身**没有语义**，重要的是「哪些点被分到同一簇」。
- 有真实标签时：**ARI（调整兰德指数）**、**NMI（归一化互信息）**，取值 0（随机）到 1（完全一致），比精度合理。
- 无真实标签时：**轮廓系数（silhouette_score）**，但书中指出它会偏爱 k 均值那种凸形簇（k 均值分数最高，人眼却更喜欢 DBSCAN 的结果）。
- 更稳健的思路是**基于鲁棒性**：加噪声或换参数反复聚类，结果一致才可信（写书时 scikit-learn 尚未内置）。
- **聚类的应用与评估本质上是定性的、探索性的**——人工检查每个簇的典型样本往往比单一指标更有价值。

### 3.5 估计器接口小结（★）

| 接口 | 用途 | 典型方法 |
| --- | --- | --- |
| `fit(X[, y])` | 从数据学习模型/参数 | 所有估计器 |
| `predict(X)` | 生成**新输出**（标签、回归值、簇标签） | 分类器、回归器、聚类 |
| `transform(X)` | 生成输入 X 的**新表示** | 预处理、降维、特征提取 |
| `fit_transform(X)` | 二者合并 | `StandardScaler`、`PCA` 等 |

**约定**：`X` 恒为二维连续值 NumPy 数组 / SciPy 稀疏矩阵（行 = 样本）；`y` 为一维目标数组；`X_train`/`y_train`、`X_test`/`y_test` 是全书统一命名。

### 3.6 易错点

- `scaler.fit(X_test)` 是**严重错误**；测试集只能用 `transform`，且变换参数来自训练集。
- 测试集缩放后超出 [0, 1] 是**正确结果**，说明用的是训练集的统计量。
- t-SNE 只能可视化，**不能 `.transform` 新样本**，也不能当作监督模型输入。
- PCA 成分的正负号是任意的；NMF 分量非负才更易解释。
- 聚类不能用 accuracy 评估；DBSCAN 的 `-1` 是噪声而非类别编号。

## 第4章 数据表示与特征工程

> **用正确的方式表示数据，对监督模型性能的影响比精确调参更大**。数据表示取决于两件事：**数据的语义** 与 **所用的模型种类**（线性模型 vs 基于树的模型差异最大）。

### 4.1 分类变量与 One-Hot 编码（★）

**One-Hot 编码（N 取一编码 / 虚拟变量）**：把有 k 个取值的分类特征展开成 k 个二元特征，每个样本只有一个为 1。

```python
data_dummies = pd.get_dummies(data)          # 对字符串列自动展开
X = data_dummies.drop(['income_<=50K', 'income_>50K'], axis=1).values
y = data_dummies['income_>50K'].values
```

| 要点 | 说明 |
| --- | --- |
| 与统计学虚拟编码的区别 | 统计学常用 **k−1** 个特征（全 0 表示第 k 类），可避免数据矩阵秩亏；one-hot 用 k 个 |
| 必须分离目标 | 把输出变量或其派生列留在特征里，是监督建模**非常常见的错误** |
| 检查取值 | 先用 `Series.value_counts()` 看唯一值，人工输入常有拼写/大小写差异（male / man） |
| 类别是数字时 | 数字不代表连续！若语义无顺序关系（如 workclass 的 0~8）**必须**当作离散变量做 one-hot；五星评分则视任务而定 |
| 指定分类列 | `OneHotEncoder(categorical_features=...)` 或 `ColumnTransformer` 可明确标记哪些列是分类变量 |

**get_dummies 的经典陷阱**：若训练集与测试集**分开**调用 `get_dummies`，某取值只在训练集出现时，两边生成的列数与列名不同 → 模型无法应用到测试集；更糟的是列的位置对应了不同的语义。解决：在合并后的数据框上统一编码，或显式对齐列名。

### 4.2 分箱、离散化、线性模型与树

```python
from sklearn.preprocessing import OneHotEncoder, PolynomialFeatures
bins = np.linspace(-3, 3, 11)
which_bin = np.digitize(X, bins=bins)
X_binned = OneHotEncoder(sparse=False).fit_transform(which_bin)
```

把连续特征划入若干**箱子（bin）**并 one-hot 化后：

- **线性模型变得更灵活**：每个箱子可以有自己的系数（原本只有一条直线）；
- **决策树灵活性反而下降**：每个箱子内特征恒定，任何模型只能给出同一个值；树本来就能自己学到最优划分点；
- 书上用 wave 数据集演示：分箱后线性回归与决策树**预测完全重合**；
- 结论：**分箱对线性模型收益大，对基于树的模型通常无益**。

### 4.3 交互特征与多项式特征

```python
from sklearn.preprocessing import PolynomialFeatures
poly = PolynomialFeatures(degree=2, include_bias=False)
X_poly = poly.fit_transform(X)
print(poly.get_feature_names())   # 查看每个新特征的来源
```

- **交互特征** = 特征之间的乘积；**多项式特征** = 特征的平方、立方等。
- 与分箱结合：把「箱子指示符 × 原始特征」加入，等价于让线性模型在每个箱子内学一条独立的直线。
- 在 Ridge 上能显著提升性能；但对随机森林这类复杂模型帮助有限——**核 SVM 可以学到类似的复杂度而无需显式特征变换**。
- 代价：特征数随 degree 组合爆炸，需配合正则化。

### 4.4 单变量非线性变换

| 变换 | 适用情形 |
| --- | --- |
| `log(x + 1)` | **计数数据**（登录次数、订单数），取值非负且常有长尾；+1 是为了处理 x = 0 |
| `log(y + 1)` | 预测计数型目标时同样有效 |
| `exp` | 与 log 反向，调节相对比例 |
| `sin` / `cos` | **周期性模式**（一天中的时刻、星期几、季节） |

**原因**：多数模型在特征（回归中还包括目标）近似**高斯分布**时表现最好；线性模型与神经网络依赖每个特征的**尺度与分布**，而树模型只关心特征的顺序。若特征与目标是非线性关系（如内存价格随年份指数下降），直接建模很困难，`log` 变换能把关系拉直——书中对价格取对数后，树模型与线性模型都能外推，未取对数时决策树只能给出常数。

### 4.5 自动化特征选择

| 方法 | 类 | 原理 | 优缺点 |
| --- | --- | --- | --- |
| **单变量统计** | `SelectKBest` / `SelectPercentile`（`f_classif`、`f_regression`） | 逐个计算特征与目标的统计显著性（分类即方差分析 ANOVA），选置信度最高的 | **极快、无需建模**；但只单独看每个特征，**会丢掉「组合起来才有信息」的特征**，且完全独立于后续模型 |
| **基于模型** | `SelectFromModel` | 用监督模型（如随机森林、L1 线性模型）给出 `feature_importances_` / `coef_`，保留超过阈值（如 `median`）的特征 | 考虑特征间关系、与模型一致；计算更重 |
| **迭代特征选择（RFE）** | `RFE` | 先在全特征上建模型并删掉最不重要的，反复迭代直到剩指定个数 | 效果常最好，但**计算量最大** |

书中用「原始特征 + 随机噪声」的合成数据验证：只要选对特征，**线性模型的表现可以与随机森林一样好**。特征选择本身依赖数据，因此必须放在**交叉验证循环内部**（见第 6 章）。

### 4.6 利用专家知识（Citi Bike 案例，★）

- 任务：用「日期 + 时刻」预测某站点未来 3 小时的租车数量。
- **失败做法**：直接把时间戳（整数）喂给随机森林 → 训练集很好，测试集 R² = **−0.04**（什么都没学到）。原因：树模型**无法外推**到训练时间范围之外，只能输出训练集中最近点的目标值。
- **改进一**：把时间拆成「一周的星期几 + 一天中的时刻」两个特征 → 捕捉周期性，随机森林 R² ≈ **0.84**。
- **改进二**：改用 LinearRegression 直接吃整数编码 → 效果很差，因为它把星期几/时刻当成**连续线性变量**（时间越晚租得越多）。
- **改进三**：用 `OneHotEncoder` 把星期几与时刻当作**分类变量** → 性能与随机森林相当，且**系数可解释**（每个「星期几 × 时刻」组合一个系数）。

> 教训：领域知识（这里是「租车行为具有周期性」）能把不可学的问题变成可学的问题，**比换更复杂的模型更有效**。

### 4.7 易错点

- 数字编码的分类变量若语义**无顺序**，必须 one-hot，绝不能当连续值。
- `get_dummies` 必须保证训练/测试**列名与列序一致**，否则语义错位。
- 分箱提升线性模型、未必提升树模型；多项式/交互特征对 Ridge 有效、对随机森林帮助有限。
- 计数数据用 `log(x+1)`，不能直接 `log(x)`（0 无定义）。
- 特征选择、缩放等**依赖数据的处理**必须放进交叉验证内部，否则数据泄露。

## 第5章 模型评估与改进

![交叉验证、数据划分与网格搜索](/ml/ml-cv-grid.svg)

> 我们关心的**不是模型在训练集上拟合得多好**，而是它对训练过程中没见过的数据的预测能力。

### 5.1 交叉验证（★）

```python
from sklearn.model_selection import cross_val_score, StratifiedKFold, KFold
from sklearn.model_selection import LeaveOneOut, ShuffleSplit, GroupKFold
scores = cross_val_score(logreg, X, y, cv=5)          # 默认 3 折/5 折，分类用分层 k 折
print(scores.mean(), scores.std())
```

| 策略 | 做法 | 适用 |
| --- | --- | --- |
| **k 折交叉验证** | 数据分成 k 份，轮流用 k−1 份训练、1 份验证，取 k 个分数的平均 | 通用默认；k 越大每折训练数据越多（10 折用 90%），但计算更贵 |
| **分层 k 折（StratifiedKFold）** | 每折中各类别比例与整体一致 | **分类默认**，避免按标签排序时某折只有一个类别 |
| `KFold(shuffle=True)` | 打乱后再切分 | 数据按标签/时间排序且不想用分层时 |
| **留一法（LeaveOneOut）** | 每折只留 1 个样本做验证 | 小数据集；计算极贵、方差大 |
| `ShuffleSplit` | 多次随机划分，可指定 `train_size` / `test_size` | 需要重复随机切分 |
| **`GroupKFold`** | 按 `groups` 数组分组，**同一组不会同时出现在训练和验证折** | 同一人的多张照片、同一患者的多次记录；**groups 不是标签** |

**交叉验证的优点**：比单次 `train_test_split` 更稳健（避免碰巧分到「幸运」的测试集）、每折都能给出分数从而看出方差、训练数据利用率更高。书里 iris 上 5 折精度从 90% 到 100% 波动，说明模型对划分敏感或数据太小。

### 5.2 网格搜索（★）

**数据必须三分为训练 / 验证 / 测试**：训练集建模型，验证集选模型与参数，测试集只在**最后**评估一次。若用测试集或交叉验证去选参数，测试数据就被「用完了」，再用同一数据评估会得到**过于乐观**的估计——书中对比：验证集最高 96%，而最终测试集只有 **92%**，不能声称 97%。

```python
from sklearn.model_selection import GridSearchCV
param_grid = {'C': [0.001, 0.01, 0.1, 1, 10, 100],
              'gamma': [0.001, 0.01, 0.1, 1, 10, 100]}
grid = GridSearchCV(SVC(), param_grid=param_grid, cv=5)
grid.fit(X_train, y_train)
print(grid.best_params_, grid.best_score_, grid.best_estimator_)
print(grid.score(X_test, y_test))     # 这才是泛化性能
```

| 属性 / 概念 | 说明 |
| --- | --- |
| `best_params_` | 平均验证分数最高的参数组合 |
| `best_score_` | **交叉验证的平均验证精度**，不是测试集分数 |
| `best_estimator_` | 用最佳参数在**整个训练集**上重新拟合的模型 |
| `cv_results_` | 每种参数组合在各折的分数、均值与标准差；二维网格适合画热图 |
| **嵌套交叉验证** | 外层评估、内层调参；结论只能表述为「SVC 在 iris 上交叉验证平均精度 98%」，不多不少 |
| 非网格空间 | `param_grid` 可传**字典列表**，为不同 kernel / 不同模型指定各自的参数集合 |

> 热图若呈「垂直条形」，说明只有 gamma 影响精度、C 不重要；网格每加一个参数，需训练的模型数**指数增长**。

### 5.3 评估指标与评分（★）

#### 混淆矩阵与二分类指标

| 术语 | 含义 |
| --- | --- |
| **TP** 真正例 | 正类被正确判为正类 |
| **FP** 假正例（第一类错误） | 反类被误判为正类 |
| **TN** 真反例 | 反类被正确判为反类 |
| **FN** 假反例（第二类错误） | 正类被误判为反类 |

**译名提醒（易混）**：本书把 `accuracy` 译「精度」、`precision` 译「准确率」、`recall` 译「召回率」；多数中文资料称 precision 为「精确率 / 查准率」。下面用通用写法并附英文。

| 指标 | 公式 | 关心什么 |
| --- | --- | --- |
| 精度 **accuracy** | (TP+TN) / 全部 | 整体正确比例 |
| 精确率 **precision**（书中「准确率」） | TP / (TP+FP) | **限制假正例**：如药物临床试验很贵，只在很确定有效时才推进 |
| 召回率 **recall** / TPR | TP / (TP+FN) | **限制假反例**：如癌症筛查不能漏诊 |
| **F1** | 2·precision·recall / (precision+recall) | 两者的调和平均 |
| **FPR** 假正例率 | FP / (FP+TN) | ROC 的横轴 |

```python
from sklearn.metrics import confusion_matrix, classification_report
from sklearn.metrics import precision_recall_curve, average_precision_score
from sklearn.metrics import roc_curve, roc_auc_score
print(classification_report(y_test, y_pred))
```

**为什么 accuracy 会骗人**：在 9:1 不平衡数据上，永远预测多数类就有 90% 精度，却「什么都没学到」。书中用 `DummyClassifier` 与真实分类器对比说明：同一精度下模型可能有天壤之别。

**阈值与曲线**：

- 改变 `decision_function` 的阈值即是在 precision 与 recall 之间做折中，目标应由**业务目标**驱动（如「召回率至少 90%」）；
- **PR 曲线**每个点对应一个阈值，曲线下面积即 **average precision**（`average_precision_score`）；把所有样本判为正类可得 100% 召回率，但精确率极低，模型无用；
- **ROC 曲线**以 FPR 为横轴、TPR 为纵轴，**AUC** 是曲线下面积，衡量「正类样本排名高于反类」的程度；AUC = 1.0 表示存在某个阈值可以完美分类。书中 `gamma=0.01` 的 SVC 精度一般但 **AUC = 1.0**——只看精度会漏掉这个好模型；
- **多分类**：常用宏平均 / 微平均 / 加权平均的 F1；`classification_report` 逐类给出，类别不平衡时大类会主导；
- **回归**：默认 **R²** 最直观；业务上有时按 MSE / MAE 调参，但书中建议优先 R²。

#### 在模型选择中使用指标

`GridSearchCV(..., scoring='roc_auc')` 可指定评分；分类默认 accuracy、回归默认 R²。选哪个指标必须回到**最终目标**：商业指标（增加利润、减少损失）最理想，难以直接度量时再退而求其次用代理指标。

### 5.4 本章两个必须记住的要点（原书强调）

1. 用测试集或交叉验证**选模型 / 选参数**，就「用完了」测试数据；必须保留一份从未参与任何决策的测试集，或改用嵌套交叉验证。
2. 网格搜索与交叉验证只能作用于**单个监督模型**；现实流程包含预处理等多个步骤，必须引入第 6 章的 `Pipeline`，否则预处理会在交叉验证之外泄露信息。

### 5.5 易错点

- `best_score_` 是**验证集**平均分数，不能当测试集泛化性能报告。
- 分层 k 折用于分类；`GroupKFold` 的 `groups` 是分组标识，**不是类别标签**。
- 类别不平衡时不要只看 accuracy；优先看 PR 曲线 / AUC / classification_report。
- 二分类里「正类」是人为指定的，换正类后 precision、recall 会变。
- 提高召回率最粗暴的办法是全判正类（召回率 100%），但精确率趋近于类别占比，模型毫无价值。

## 第6章 算法链与管道

![Pipeline 与交叉验证中防止数据泄露](/ml/ml-pipeline.svg)

> 现实中的机器学习应用**很少只用单个算法**，而是把缩放、特征选择、降维、模型等多个处理步骤串成一条链。`Pipeline` 把这些步骤封装成**一个 scikit-learn 估计器**。

### 6.1 为什么必须要用管道：数据泄露（★★）

**错误做法**：先在整个训练集上 `MinMaxScaler().fit_transform(X_train)`，再拿缩放后的数据跑 `GridSearchCV`。

问题在于：交叉验证的每一折都会把训练集再切成训练部分与验证部分，而缩放时已经**用了验证部分的信息**（最小值/最大值），导致验证折不再「前所未见」，交叉验证结果**过于乐观**，可能选到次优参数。

> **原则：任何从数据中提取信息的处理，都必须只作用于当前折的训练部分；交叉验证应位于整个处理过程的「最外层循环」。**

书中给了一个震撼的例子：100 个样本、10000 个**完全随机**的特征、随机生成的目标（二者本无任何关系）。先在交叉验证**之外**用 `SelectPercentile` 选特征，再评估 Ridge → 交叉验证平均 **R² = 0.91**（看似极好）；改用 Pipeline 把特征选择放进循环内 → **R² = −0.25**（模型根本无效）。结论从「表现很好」直接翻转为「没有效果」。

- 缩放类泄露通常影响有限；**特征选择与特征提取**的泄露会造成显著差异。

### 6.2 构建管道

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import MinMaxScaler
from sklearn.svm import SVC

pipe = Pipeline([('scaler', MinMaxScaler()), ('svm', SVC())])
pipe.fit(X_train, y_train)
print(pipe.score(X_test, y_test))
```

- 每个步骤是 `(名称, 估计器实例)` 元组；
- `pipe.fit` 依次对中间步骤调用 `fit` + `transform`，把输出喂给下一步，最后一步仅调用 `fit`；
- 预测时中间步骤只调用 `transform`，最后一步 `predict`；
- **除最后一步外，所有步骤都必须有 `transform` 方法**；最后一步只需有 `fit`（因此可以做「只有 scaler + PCA」的纯变换管道，调用 `pipe.transform`）。

### 6.3 在网格搜索中使用管道（★）

参数名要用 **`步骤名__参数名`（双下划线）** 指定属于哪一步：

```python
param_grid = {'svm__C': [0.001, 0.01, 0.1, 1, 10, 100],
              'svm__gamma': [0.001, 0.01, 0.1, 1, 10, 100]}
grid = GridSearchCV(pipe, param_grid=param_grid, cv=5)
grid.fit(X_train, y_train)
```

这样每一折内部都会**重新 fit 缩放器**，彻底消除泄露。

### 6.4 通用管道接口

| 用法 | 说明 |
| --- | --- |
| `make_pipeline(MinMaxScaler(), SVC())` | 自动按类名小写命名步骤（`minmaxscaler`、`svc`），省去手写元组 |
| `pipe.steps` | 由 `(名称, 估计器)` 元组组成的列表，`pipe.steps[0][1]` 是第一个估计器 |
| `pipe.named_steps['svm']` | 按名称取某个步骤，用于查看系数、主成分等属性 |
| `grid.best_estimator_.named_steps['...']` | 取出网格搜索最佳管道中某一步的属性 |
| 参数名对照 | `make_pipeline` 下 LogisticRegression 的参数写成 `logisticregression__C` |

### 6.5 同时搜索预处理参数与模型参数

```python
pipe = make_pipeline(StandardScaler(), PolynomialFeatures(), Ridge())
param_grid = {'polynomialfeatures__degree': [1, 2, 3],
              'ridge__alpha': [0.001, 0.01, 0.1, 1, 10, 100]}
```

- 书中 boston 数据的热图显示：**二次多项式有用，三次比一次、二次都差很多**；
- 策略很强，但 `GridSearchCV` 会穷举所有组合，**每加一个参数模型数量指数增长**。

### 6.6 用网格搜索选择「用哪个模型」

把模型本身作为管道的一个步骤，并在参数网格里给它赋不同的估计器；不需要某步骤时设为 `None` 跳过：

```python
pipe = Pipeline([('preprocessing', StandardScaler()), ('classifier', SVC())])
param_grid = [
    {'classifier': [SVC()], 'preprocessing': [StandardScaler(), None],
     'classifier__gamma': [0.001, 0.01, 0.1], 'classifier__C': [0.1, 1, 10]},
    {'classifier': [RandomForestClassifier(n_estimators=100)],
     'preprocessing': [None], 'classifier__max_features': [1, 2, 3]}
]
```

随机森林不需缩放，所以把 `preprocessing` 设为 `None`；不同模型需要不同参数，故用**参数网格列表**。

### 6.7 管道的额外好处

- 代码更简洁，避免「忘记对测试集应用同样变换」或「变换顺序搞错」；
- 让「尝试不同处理步骤组合」变得简单，但书中提醒：**别把流程复杂化，要评估每个组件是否真的必要**。

### 6.8 易错点

- 参数名是 `步骤名__参数`（**两个下划线**），写成单下划线或直接用 `C` 会报错或被忽略。
- `make_pipeline` 自动命名是类名小写，与手写 `Pipeline` 的名称不同，参数网格要相应改。
- 特征选择、缩放、PCA 等**任何依赖数据的步骤**都必须在管道内；只在管道外做一次 `fit_transform` 就是泄露。
- 管道最后一步没有 `predict` 也可以（纯变换管道），但中间步骤没有 `transform` 一定不行。

## 第7章 处理文本数据

![文本数据的词袋与 tf-idf 处理流程](/ml/ml-text.svg)

### 7.1 字符串特征不只是「文本」

| 类型 | 例子 | 处理方式 |
| --- | --- | --- |
| **分类变量** | 性别、颜色（`grey` / `gray` 拼写差异） | 先检查 `value_counts()`，清洗后 one-hot |
| 可转换为分类的自由字符串 | 问卷里手填的职业 | 人工归并后再编码 |
| **结构化字符串** | 日期、地址、编号 | 拆解成有意义的数值/分类字段（如年、月、时刻） |
| **自由文本** | 影评、推文、客服消息 | 本章的词袋 / tf-idf 流程 |

**先看数据再决定处理方式**；不要见到字符串列就丢进 `CountVectorizer`。中文没有天然词边界，书中基于英文空格分词的方法需先做分词才能套用。

典型任务：电影评论**情感分析**（IMDb 影评，25 000 条训练 / 25 000 条测试）、判断客户消息是投诉还是咨询、从演讲推断政治立场。

### 7.2 词袋表示（Bag of Words）

```python
from sklearn.feature_extraction.text import CountVectorizer
vect = CountVectorizer().fit(text_train)
X_train = vect.transform(text_train)        # 稀疏矩阵
feature_names = vect.get_feature_names_out()
```

- **词袋**：丢弃词序与语法，只统计每个词例（token）在文档中出现的次数；语料中出现过的每个词对应一个特征。
- 默认用**两个及以上字符**的正则表达式分词，并**统一转小写**（`soon` / `Soon` / `sOon` 归为同一词例）。
- 输出是 **SciPy 稀疏矩阵**——词表动辄数万维，但每篇文档只含几十个非零值。
- 用 `min_df`（如 `min_df=5`，词至少出现在 5 个文档中）**丢弃稀有词例**，可显著减少特征数、加速训练，往往不损失精度。

> 书中提示：`CountVectorizer` 默认设置不学习任何统计量，所以单独在训练集 fit 后再交叉验证尚可接受；但实际项目**从一开始就应放进 Pipeline**。

### 7.3 停用词

```python
vect = CountVectorizer(min_df=5, stop_words='english')
```

- 固定的停用词表（如 `the`、`and`）主要对**小型数据集**有用——数据不足以让模型自己判断哪些词无信息量。
- 书中 IMDb 实验里，删除 305 个停用词后验证精度**略有下降**，收益不明显；另一种做法是设 `max_df` 自动舍弃出现在过多文档中的高频词。

### 7.4 tf-idf（★）

**词频—逆文档频率**：对「在某文档中频繁出现、但在语料库多数文档里不常出现」的词给高权重，抑制到处都出现的高频词。

**tf-idf(t, d) = tf(t, d) × idf(t)**，其中 **idf(t) = log\[ (1 + N) / (1 + N_w) \] + 1**，N 为文档总数，N_w 为包含词 t 的文档数；之后通常再做 L2 归一化。

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression

pipe = make_pipeline(TfidfVectorizer(min_df=5), LogisticRegression())
param_grid = {'tfidfvectorizer__ngram_range': [(1, 1), (1, 2), (1, 3)],
              'logisticregression__C': [0.001, 0.01, 0.1, 1, 10]}
grid = GridSearchCV(pipe, param_grid, cv=5)
```

- tf-idf **利用了训练数据的统计属性**，因此必须用 Pipeline 保证网格搜索有效（否则泄露）。
- 也可用 `CountVectorizer` + `TfidfTransformer` 两步实现同样效果。
- 训练完成后查看 **Logistic 回归绝对值最大的系数**，即可知道哪些词最能代表正面/负面评价——线性模型在文本上的可解释性优势。

### 7.5 n 元分词（n-gram）

| 参数 | 含义 |
| --- | --- |
| `ngram_range=(1, 1)` | 只用一元分词（单词） |
| `ngram_range=(1, 2)` | 一元 + 二元分词 |
| `ngram_range=(1, 3)` | 再加三元分词 |

- 二元分词能捕捉**上下文**：书中 `worth` 单独出现无判别力，但 `not worth` 是负面、`definitely worth` / `well worth` 是正面。
- 书中实验：**加二元分词提升明显，三元分词贡献很小**；更长的 n-gram 会让特征数暴涨并带来过拟合，原则上二元数量是一元的平方级。
- 大多数应用 `min` 应设为 1（单词本身信息量丰富）。

### 7.6 高级分词、词干提取与词形还原

| 方法 | 做法 | 效果 |
| --- | --- | --- |
| **词干提取（stemming）** | 用规则截断词尾得到词干 | `was` → `wa`，`worse` → `wors`；简单粗暴 |
| **词形还原（lemmatization）** | 借助词性与词典还原标准词形 | `was` → `be`，`worse` → `bad`；名词 `meeting` 不变、动词 `meeting` → `meet` |

- 词形还原更复杂，但**通常给出更好的结果**；二者都可通过 `CountVectorizer(tokenizer=自定义可调用对象)` 接入（书中用 spacy 做词形还原）。
- 与许多特征工程技巧一样，**效果因数据集而异**，只有在追求最后一点性能时才值得尝试。

### 7.7 主题建模与文档聚类（LDA）

```python
from sklearn.decomposition import LatentDirichletAllocation
lda = LatentDirichletAllocation(n_components=10, learning_method='batch',
                                max_iter=25, random_state=0)
doc_topics = lda.fit_transform(X_tfidf)
```

- 每个**主题**是词上的分布，每篇文档是主题上的混合；主题**没有内在顺序**，改变主题数会改变所有主题。
- `learning_method='batch'` 比默认 `online` 慢但结果更好；增大 `max_iter` 也常有收益。
- 查看每个主题权重最高的词来命名主题；可对 `document_topics` 求和看各主题整体权重。
- **LDA 是随机算法**，改 `random_state` 可能得到完全不同的主题；对无监督结论要**通过查看主题内的具体文档**验证直觉。
- 注意与**线性判别分析（Linear Discriminant Analysis）** 同名缩写 LDA，两者完全不同。
- LDA 生成的主题也可作为监督学习的**紧凑特征**，训练样本很少时尤其有用。

### 7.8 易错点

- 词袋**丢弃词序**，所以「not good」与「good not」在 `(1,1)` 下相同；需靠 n-gram 补救。
- `idf` 由**训练语料**统计得到，测试文本只能用 `transform`；tf-idf 不放进 Pipeline 就是泄露。
- `stop_words` 不是万能的：大数据集上收益有限，甚至略降精度。
- LDA 主题数没有「正确答案」，且结果依赖随机种子。

## 第8章 全书总结

### 8.1 先想清楚问题，再动手建模

机器学习算法通常只是**更大的数据分析与决策过程的一小部分**。开始之前应退一步问：

1. 想回答什么问题？是探索性分析，还是已有明确目标（检测欺诈、推荐电影、寻找行星）？
2. 如何**定义并衡量成功**？能否直接用商业指标（增加利润、减少损失）度量？
3. 「如果我构建出**完美的模型**，会怎么样？」——若完美检测所有欺诈每月只省 100 美元，就不值得投入。
4. 是否拥有合适的数据来评估模型？是否要让人参与决策？

**人在回路（human in the loop）**：无人驾驶需要即时决策；而医疗等高精度场景可以让算法处理「简单情况」（哪怕只占 10%~90%），把不确定的复杂情况交给人——照样能缩短响应时间、降低成本。

### 8.2 从原型到生产

模型构建只是反馈环路的一环：

**收集新数据 → 清洗数据 → 构建模型 → 分析模型 →（回到收集）**

分析模型犯的错误，往往能指出数据里缺了什么、还该收集什么、或该如何重新定义任务。**收集更多/不同的数据、或微调任务定义，常常比连续跑网格搜索调参回报更高**。

生产系统还需单独测试：上线后的数据分布、延迟、失败回退与监控，与离线评估是两回事。

### 8.3 构建自定义估计器

当预处理依赖数据、又想用 `Pipeline` / `GridSearchCV` 时，可以自己写一个兼容 scikit-learn 接口的估计器：

```python
from sklearn.base import BaseEstimator, TransformerMixin

class MyTransformer(BaseEstimator, TransformerMixin):
    def __init__(self, power=1):
        self.power = power
    def fit(self, X, y=None):        # 即使无监督也要接受 y 参数
        return self
    def transform(self, X):
        return X ** self.power
```

- 继承 `BaseEstimator` 获得 `get_params` / `set_params`（网格搜索必需），继承 `TransformerMixin` 获得 `fit_transform`；
- `fit` 必须**只接受 `X` 和 `y`** 两个参数，且即使是无监督模型也要保留 `y=None`；
- 这样自定义步骤就能无缝放进管道，参与交叉验证，避免数据泄露。

### 8.4 下一步方向

| 方向 | 说明 |
| --- | --- |
| **理论** | 统计学习基础（《The Elements of Statistical Learning》等）补足偏差—方差、正则化、优化的理解 |
| **其他框架** | keras / TensorFlow / theano / lasagna 做深度学习（支持 GPU，可比 CPU 快 10~100 倍）；`xgboost` 做大规模梯度提升；`vw`（vowpal wabbit）适合流数据与超大数据集 |
| **其他任务类型** | 排序、推荐系统、时间序列预测等，范式远多于本书的分类/回归/聚类 |
| **概率建模** | 用概率语言描述问题结构（如融合 GPS、指南针、加速度计做定位），再结合机器学习与概率推断；不要把所有物理先验丢进黑盒 |
| **更大数据集** | 本书假设数据能放进内存（NumPy 数组或稀疏矩阵）。扩展路径：**核外学习**（分块从磁盘/网络读取、逐块更新模型，仅部分模型支持）或**集群分布式**（Hadoop / Spark MLLib，需复杂基础设施） |
| **磨练技术** | Kaggle、OpenML（2 万+ 数据集、5 万+ 任务）；但比赛给定了指标与预处理好的数据，别忘了**定义问题与收集数据**才是现实工作中同等重要的能力 |

> 全书结语：继续挖掘数据，同时**不要忽视大局**。

### 8.5 易错点

- 自定义估计器的 `fit` 忘记接收 `y` 参数，会导致管道调用失败。
- 「完美模型能带来多大收益」没算清就投入建模，是项目层面最常见的浪费。
- 核外学习仍由单机处理，运行时间可能很长，且并非所有算法都支持。

## 期末速记

| 主题 | 一句话记忆 |
| --- | --- |
| 三接口 | `fit` 学参数、`predict` 出标签、`transform` 换表示；`fit` 会**重置**模型 |
| 数据划分 | 训练 / 验证 / 测试三分；选模型和调参只能碰验证集，测试集最后用一次 |
| 缩放铁律 | 只在训练集 `fit`，训练与测试用**同一个** `transform`；测试集可超出 [0,1] |
| 何时缩放 | k-NN、线性模型、SVM、神经网络、PCA **需要**；树与随机森林**不需要** |
| 复杂度方向 | `C` 越大越复杂、`alpha` 越大越简单、`max_depth` 越大越复杂 |
| 欠拟合信号 | 训练与测试分数**都低且接近**；过拟合是训练高、测试低 |
| 算法起步 | 先用线性模型 / 朴素贝叶斯 / k-NN 做基线，再上随机森林、梯度提升、SVM、神经网络 |
| 不平衡数据 | 别只看 accuracy；用 precision / recall / F1、PR 曲线、AUC 与 `classification_report` |
| 防泄露 | 任何依赖数据的步骤（缩放、特征选择、tf-idf）都放进 `Pipeline`，参数名用 `步骤名__参数` |
| 树不能外推 | 时间序列/未来预测要把时间拆成周期特征或 one-hot，别直接喂时间戳整数 |
| 文本主线 | 词袋 → `min_df` 去稀有词 → tf-idf → n-gram → 线性模型看系数；主题用 LDA |
| 聚类评估 | 不用 accuracy；有标签用 ARI/NMI，无标签用轮廓系数 + 人工检查 |
