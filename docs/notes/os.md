## 第 1 章 操作系统引论

### 1.1 目标、作用与发展动力（★★）

| 维度 | 内容 |
| --- | --- |
| 四大目标 | **方便性**（提供接口）、**有效性**（提高资源利用率与吞吐）、**可扩充性**（模块化、易加新功能）、**开放性**（遵循标准、可互操作） |
| 作为用户与硬件间的接口 | 命令接口（联机/脱机）、程序接口（系统调用）、图形用户接口 |
| 作为资源管理者 | 处理机／存储器／设备／文件四大资源管理，外加接口管理 |
| 作为扩充机器 | 在裸机上叠加软件层，把硬件抽象成虚拟机（"虚机器"） |
| 发展动力 | 提高资源利用率、方便用户、器件更新换代、体系结构发展、应用需求（实时/嵌入式/分布式/云） |

::: tip 现代操作系统新增目标
除了经典的新功能（系统安全、网络功能与服务、支持多媒体），工程上还应关注：**可观测性**（ tracing / eBPF / perf ）、**资源隔离与配额**（ cgroup / QoS ）、**热升级与在线修复**（ live patch ）、**能耗与异构调度**（ big.LITTLE、DVFS ）、**供应链与启动信任链**（ Secure Boot / 度量启动）。这些本质仍是「有效性 + 开放性 + 安全性」在云与端侧的延伸。
:::

### 1.2 操作系统发展过程（★★★）

| 阶段 | 关键机制 | 主要优点 | 主要缺点 |
| --- | --- | --- | --- |
| 无 OS（人工操作） | 用户独占全机、手工装带 | 无 | CPU 等待人工、资源利用率极低、串行 |
| 单道批处理 | 监督程序 + 作业自动接续 | 减少人工装卸时间 | 内存中仅一道作业，I/O 时 CPU 空闲 |
| **多道批处理** | 多道程序并发、作业调度 | CPU 与 I/O 并行，利用率/吞吐高 | 周转时间长、无交互、作业调度与内存管理复杂 |
| **分时系统** | 时间片轮转、多路卡 + 终端 | 人机交互、多路性、独立性、及时性 | 对每个用户响应变慢；须解决「及时接收、及时处理」 |
| **实时系统** | 截止时间驱动、抢占式优先级 | 高可靠、可预测、响应确定 | 资源利用率常偏低；硬实时须可调度性证明 |
| 微机 OS | 单用户多任务 → 多用户多任务 | 界面友好、个人可用 | 早期 DOS 无双模式/保护，一个程序可搞垮系统 |
| 嵌入式 OS | 裁剪内核、实时、低功耗 | 体积小、可裁剪、确定性强 | 资源受限、无通用文件系统/虚存 |
| 网络 OS | 网络协议栈、远程访问、共享 | 资源共享、互操作 | 各节点自治，非单一系统映像 |
| 分布式 OS | 单一系统映像、透明性 | 透明、容错、可扩展 | 一致性与通信开销、实现复杂 |

::: danger 易错 · 并发与并行、多道与分时
- **并发**＝同一**时间段**内多个事件都发生（宏观同时、微观可能交替）；**并行**＝同一**时刻**同时发生（须多核/多处理机）。单 CPU 上只能并发不能并行。
- **多道批处理**追求「资源利用率与吞吐量」，**分时系统**追求「响应时间与交互性」，**实时系统**追求「截止时间与可靠性」——三者目标不同，别混答。
- 分时系统的「及时性」按**人能接受的等待时间**（秒级）衡量；实时系统按**控制对象要求的截止时间**（毫秒甚至微秒级）衡量。
:::

::: tip 工作示例 · 多道程序如何提升利用率
单道：作业先算 50 ms 再 I/O 50 ms， cycle = 100 ms， CPU 利用率 50%。
两道并发（A 计算时 B 可 I/O，I/O 与 CPU 由通道/控制器并行）：理想情况下 CPU 几乎不空转，利用率接近 100%，吞吐从 10 作业/秒提升到约 20 作业/秒。这正是引入多道程序设计的根本动因；但每个作业的**周转时间**会变长（要排队、要被切换）。
:::

### 1.3 四大基本特性（★★★）

| 特性 | 含义 | 典型体现 |
| --- | --- | --- |
| 并发 | 一段时间内多程序同时处于运行状态 | 进程/线程；**并发是共享、虚拟、异步的前提** |
| 共享 | 系统资源供多个并发进程共同使用 | 互斥共享（打印机、临界资源）／同时访问（磁盘、可重入代码） |
| 虚拟 | 把物理实体映射为若干逻辑对应物 | 时分复用（虚拟处理机、虚拟设备 SPOOLing）／空分复用（虚拟存储器、虚拟磁盘） |
| 异步 | 进程以不可预知的速度推进，但结果须可再现 | 须用同步机制保证「异步环境下的确定性」 |

::: danger 易错 · 虚拟的实现前提
「虚拟」必须落在**复用**上：CPU 用时分复用把一个 CPU 变成多个虚拟 CPU；虚存用空分复用 + 请求调入把小内存变成大地址空间；SPOOLing 用排队+磁盘把一台独占打印机变成多台逻辑打印机。**没有并发与共享就不需要虚拟**。另外异步不等于结果不确定——只要同步正确，进程多次运行的**结果必须可再现**（这是操作系统必须保证的）。
:::

### 1.4 运行环境：双模式、中断与内核（★★★）

| 机制 | 要点 |
| --- | --- |
| 双重工作模式 | 内核态（管态、特权态）／用户态（目态）；PSW 中的模式位标识；**特权指令**只能在内核态执行 |
| 特权指令举例 | 关/开中断、I/O 指令、修改 PSW/页表基址、停机、清内存 |
| 态切换 | 用户→内核：**系统调用 / 中断 / 异常**（陷入，硬件自动置模式位）；内核→用户：修改 PSW 后返回 |
| 中断（外中断） | 来自 CPU 外部、与当前指令无关（I/O 完成、时钟、键盘）；可屏蔽中断与不可屏蔽中断 |
| 异常（内中断） | 来自 CPU 内部、由当前指令引发（除零、越界、缺页、非法指令、系统调用陷入） |
| 内核支撑功能 | 中断处理、时钟管理、原语操作；资源管理功能：进程／存储器／设备管理 |
| 原语 | 由若干条指令组成、用于完成特定功能、**执行不可被中断**（靠关中断或硬件原子指令实现） |
| 生成与引导 | BIOS/UEFI 自检 → 加载引导程序（Boot Loader）→ 加载内核 → 初始化 → 创建 init/systemd（1 号进程）→ 用户登录 |

![操作系统层次与系统调用](/os/os-arch.svg)

::: tip 补充 · 中断与异常的完整区分（考研高频）
| | 中断 (Interrupt) | 异常 (Exception) | 系统调用 (Trap) |
| --- | --- | --- | --- |
| 来源 | CPU 外部设备 | 当前指令执行出错/特殊 | 程序主动请求内核服务 |
| 与当前指令关系 | 无关（异步） | 直接相关（同步） | 直接相关（同步） |
| 返回后 | 继续下一条指令 | 可能**重新执行**当前指令（如缺页）或终止 | 继续下一条指令 |
| 典型 | 时钟、磁盘完成、网卡收包 | 除零、越界、缺页、非法指令 | `read`、`fork`、`write` |

「系统调用」「中断」「异常」分属接口与运行环境两个话题，容易让人误以为三者互不相关——实际上它们都走**同一套陷入/中断向量机制**，只是来源和处理流程不同。
:::

::: danger 易错 · 态切换与模式位
- 用户程序**不能**直接修改 PSW 的模式位（那是特权操作），只能通过陷入让硬件切换。
- 「系统调用」是**陷入（trap / 软中断）**，不是外部中断；但它执行时通常要**关中断/开中断**来保护临界区——两者别混。
- 早期 DOS 所用的 8088 没有保护模式与特权级，所以一个用户程序可以破坏系统——这正是双模式必要性的例证；80286 起 x86 才引入保护模式（4 个特权级，Linux 只用 ring 0 / ring 3）。各体系结构的特权级对应关系：x86 的 **ring 0 / ring 3**、ARM 的 **EL0（用户）~ EL3（安全监视器）**、RISC-V 的 **M（机器）/ S（监督）/ U（用户）** 三模式；用户态→内核态只有**系统调用（trap）、中断、异常**三条陷入路径，机制统一。
:::

### 1.5 主要功能与系统调用（★★★）

| 管理功能 | 具体内容 |
| --- | --- |
| 处理机管理 | 进程控制、进程同步、进程通信、调度（作业/进程）、死锁处理 |
| 存储器管理 | 内存分配与回收、地址变换、内存保护（上下限/界地址寄存器）、内存扩充（虚拟存储） |
| 设备管理 | 缓冲、设备分配与回收、设备驱动、设备独立性、虚拟设备（SPOOLing） |
| 文件管理 | 目录管理、文件读写与保护、存储空间管理、逻辑地址到物理盘块的映射 |
| 接口管理 | 命令接口、程序接口（系统调用）、GUI；现代再加网络接口与可观测接口 |

系统调用按功能分：进程控制（`fork`/`exec`/`exit`/`wait`）、文件操纵（`open`/`read`/`write`/`close`）、设备管理（`ioctl`）、信息维护（`time`/`getpid`）、进程通信（`pipe`/`shmget`/`socket`）、内存管理（`mmap`/`brk`）。

::: tip 工作示例 · 一次 `read` 的完整路径
`printf` → 库函数 → `write(fd, buf, n)` → 把系统调用号与参数放入规定寄存器 → 执行陷入指令（`syscall` / `int 0x80`）→ 硬件切内核态、查**系统调用表** → 内核 `sys_write` 校验 fd 与缓冲区 → VFS → 具体文件系统/设备驱动 → 数据写入页缓存或设备 → 返回用户态并把返回值放入寄存器。
关键点：**库函数 ≠ 系统调用**。`fread` 是库函数（带用户态缓冲），底层才可能触发 `read`；`strlen`、`memcpy`、`abs` 完全不进内核；而 `malloc` 通常只在堆不够时才用 `brk`/`mmap`。
:::

### 1.6 操作系统结构（★★★）

| 结构 | 思想 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 简单（无结构） | 过程间随意调用 | 早期实现快、开销小 | 庞大混乱、难维护、难验证 |
| 模块化 | 按功能划分模块、明确接口 | 可裁剪、易扩展、可并行开发 | 模块间依赖与接口设计难；模块划分易与实际调用关系不一致 |
| 分层式 | 每层只使用**更低层**的服务 | 易调试验证、易替换底层 | 层次定义困难、每层都增加开销（效率偏低） |
| **微内核** | 内核只留最基本功能（进程/内存/通信/中断），文件系统、驱动等放到**用户态服务器** | 高可靠、可扩展、易移植、适合分布式 | 频繁的进程间通信与态切换导致**性能下降** |
| 外核 (Exokernel) | 内核只做物理资源的**隔离与复用**，把抽象交给库 OS | 应用可定制抽象、极致性能 | 库 OS 复杂、生态弱 |
| 混合（宏内核+模块） | 单内核地址空间 + 可动态加载模块 | 性能接近宏内核、又具模块化 | 驱动 bug 仍可崩内核（无隔离） |

::: danger 易错 · 宏内核 vs 微内核
- 微内核的「微」指**功能少**，不是代码行数或性能弱；恰恰因 IPC 多，性能通常**更差**。
- 现代 Linux 是**宏内核 + 可加载模块**（混合），不是微内核；Windows NT 最初宣称微内核，实际为混合内核；**seL4（形式化验证）、QNX、Fuchsia/Zircon、MINIX 3** 才是微内核代表。微内核结构的经典举例（Mach、Windows NT 早期设计）之外，也应了解这些现代实例。
- 「外核」与「虚拟机」思路相反：外核**减少**抽象暴露硬件，VMM**增加**一层硬件抽象（第 11 章）。
:::

## 第 2 章 进程的描述与控制

### 2.1 前趋图与程序执行（★★）

前趋图（DAG）中 `Pi → Pj` 表示 Pj 只能在 Pi 完成后开始；无前趋的结点称初始结点，无后继的称终止结点，结点可带权（程序段执行时间）。

| | 顺序执行 | 并发执行 |
| --- | --- | --- |
| 特征 | **顺序性、封闭性（独占资源、结果不受外界影响）、可再现性** | **间断性（"执行—暂停—执行"）、失去封闭性、不可再现性** |
| 结果 | 由初始条件唯一决定 | 与执行速度/调度次序有关，可能出错 |

::: tip 工作示例 · 不可再现性
两个并发进程共享变量 `n`（初值 5）：`P1: n++`，`P2: printf(n); n=0;`。若 P1 先执行完则输出 5；若 P2 先执行 `printf` 再被抢占、P1 加 1，随后 P2 执行 `n=0`，最终 n=0 而输出 5；若 P2 完整执行再 P1 执行，输出 5 且 n=1。**同样的输入得到不同结果**即为失去可再现性，必须引入进程同步（第 4 章）。
:::
「前趋图」常与「Bernstein 条件」一起考：两程序段可并发的条件是 `R(P1)∩W(P2) ∪ R(P2)∩W(P1) ∪ W(P1)∩W(P2) = ∅`（读集与写集互不相交）。

### 2.2 进程定义、特征与 PCB（★★★）

**进程＝程序段 + 数据段 + PCB**，是程序的一次执行过程，是系统**资源分配与调度（传统 OS 中）的基本单位**。

| 特征 | 说明 |
| --- | --- |
| 动态性 | 有创建、执行、暂停、消亡的生命周期（"进程是动态的，程序是静态的"） |
| 并发性 | 多个进程可并发执行（引入进程的目的） |
| 独立性 | 独立运行、独立获得资源、独立接受调度（传统意义上） |
| 异步性 | 按各自不可预知的速度推进 |
| 结构性 | 由程序段、数据段、PCB 三部分组成 |

PCB 主要内容：**进程标识符**（PID/UID）、**处理机状态**（通用寄存器、PC、PSW、栈指针，切换时保存/恢复）、**进程调度信息**（状态、优先级、等待时间、已执行时间、队列指针）、**进程控制信息**（程序/数据地址、资源清单、打开文件表、同步与通信信息、链接指针）。

::: danger 易错 · 进程与程序、PCB 的作用
- 一个程序可对应**多个进程**（多次运行），一个进程也可执行多个程序（`exec` 系列替换映像）。
- PCB 是进程**存在的唯一标志**：创建进程＝创建 PCB，撤销进程＝回收 PCB；PCB 常驻**内核空间**，用户不可直接访问。
- **上下文切换**保存的是「处理机状态」而非整个进程映像；切换有开销（保存/恢复寄存器、TLB 失效、缓存冷启动），所以时间片不能太小。
:::

### 2.3 进程状态与转换（★★★）

| 基本状态 | 含义 |
| --- | --- |
| 创建（New） | 申请空白 PCB、填写信息、分配资源，尚未进入就绪队列 |
| 就绪（Ready） | 已获得除 CPU 外的全部资源，排队等调度 |
| 运行（Running） | 占用处理机执行（单 CPU 下最多一个） |
| 阻塞／等待（Blocked） | 等待某事件（I/O 完成、信号量、申请资源）而暂停，**即使有 CPU 也不能运行** |
| 终止（Terminated） | 正常/异常结束，回收资源与 PCB（**僵尸态**：PCB 保留等待父进程 `wait` 回收） |

五态转换条件：创建→就绪（**接纳/提交**）、就绪→运行（**调度/分派**）、运行→就绪（**时间片用完／被高优先级抢占**）、运行→阻塞（**等待某事件，主动**）、阻塞→就绪（**所等事件完成，被动，由其它进程/中断唤醒**）、运行→终止（正常结束或异常）。

七态再加入**挂起（Suspend）**：因内存不足、用户/父进程请求、系统负荷调节，把进程**换出到外存**；新增「就绪挂起」「阻塞挂起」两态。

| 转换 | 触发 |
| --- | --- |
| 活动就绪 → 静止就绪（挂起） | `suspend` 原语 |
| 活动阻塞 → 静止阻塞 | `suspend` 原语 |
| 静止阻塞 → 静止就绪 | 所等待的事件发生（仍在外存） |
| 静止就绪 → 活动就绪 | `active`（激活）原语且内存可用 |
| 运行 → 静止就绪 | 时间片到 + 被挂起 |

::: danger 易错 · 状态转换方向
- **阻塞→运行不可能**：必须先到就绪队列重新排队；**就绪→阻塞也不可能**（没运行就不会发起等待）。
- **阻塞是主动行为**（进程自己执行 `wait`/`P`/`read` 陷入），**唤醒是被动的**（由中断或另一进程执行 `signal`/`V`）。
- 挂起 ≠ 阻塞：阻塞仍在**内存**，挂起已被换到**外存**；挂起的进程不能被直接调度执行。
:::

### 2.4 进程控制原语（★★）

| 原语 | 主要动作 |
| --- | --- |
| 创建 `fork` / `Create` | 申请空白 PCB → 分配 PID 与资源 → 初始化 PCB → 插入就绪队列；失败则回退 |
| 终止 `exit` / `Terminate` | 查 PCB → 若在运行则置终止并调度 → 终止子孙进程 → 归还资源 → 移出队列、回收 PCB |
| 阻塞 `block` / 唤醒 `wakeup` | 阻塞：保存现场、改状态为阻塞、插入等待队列、转调度；唤醒：移出等待队列、改就绪、插入就绪队列 |
| 挂起 `suspend` / 激活 `active` | 换出到外存／换回内存，必要时触发中级调度 |

::: tip 工作示例 · `fork` 与进程计数（含 stdio 缓冲陷阱）
```c
int main(void) {
    fork();          /* ① */
    fork();          /* ② */
    printf("hello\n");
    return 0;
}
```
①后 2 个进程、②后各再分叉 → **共 4 个进程**，标准输出（行缓冲、有 `\n`）打印 **4 行**。
若写成 `printf("hello")`（无换行）且输出**重定向到文件**（全缓冲），缓冲区内容会随 `fork` 被复制到每个子进程，最终可能打印 **8 次**——这是 `fork` 与用户态缓冲交互的经典陷阱。工程做法：`fork` 前 `fflush(NULL)`，或 `fork` 后立即 `exec`（子进程用 `_exit` 而非 `exit` 避免重复刷新缓冲）。
:::

::: tip 补充 · 现代 `fork` 的三个重要机制
- **写时复制 COW**：`fork` 只复制页表并把父子页表项标为只读共享，任一方的写操作触发缺页异常才真正复制物理页；因此 `fork` 很快，但「父进程内存越大，`fork` 仍越慢」（页表本身要复制）。
- **僵尸与孤儿**：子进程终止而父进程未 `wait` → 僵尸（占 PCB/退出码）；父进程先终止 → 孤儿被 1 号进程（init/systemd）收养并回收。
- **替代方案**：`vfork`（不复制页表、子进程须立即 `exec`，父进程阻塞）、`posix_spawn`、`clone`（可精细共享地址空间/文件表/信号，Linux 线程即用 `clone` 实现）。这些工程结论与经典 `fork` 语义同样重要。
:::

### 2.5 进程通信（★★★）

| 方式 | 机制 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 共享存储器系统 | 划出共享区（基于共享数据结构／共享存储区），进程读写该区 | **最快**的 IPC：数据不经内核中转拷贝 | 需进程自己解决同步与互斥 |
| 管道 `pipe` | 内核中的循环缓冲区，字节流、半双工、FIFO | 简单、随 `fork` 传递 fd | 只能亲缘进程（匿名管道）；容量有限；无消息边界 |
| 消息传递 | `send`/`receive` 原语；直接（显式指名）或间接（**信箱**） | 隐藏实现、易用于分布式 | 每次通信都要进出内核、有拷贝开销 |
| 命名管道 FIFO / 消息队列 / 信号量 / 共享内存 | System V / POSIX IPC 对象 | 无亲缘关系也能通信、有类型/优先级 | 需显式删除、权限与生命周期管理 |
| 信号 `signal` | 异步通知（软件中断） | 轻量 | 只能传信号编号，不能传数据 |
| 套接字 `socket` | 可跨主机 | 通用、跨网络 | 开销最大 |

::: danger 易错 · 共享内存"最快"的准确含义
「共享内存是同一台机器上最快的 IPC，因为数据无须在不同进程间复制」这一表述的准确含义是：**映射建立后**，读写直接命中同一物理页，不再经过「用户态→内核缓冲区→用户态」的两次拷贝；但**首次建立映射、缺页、以及缓存一致性/伪共享**仍有开销，且必须由用户进程自行用信号量/锁保证互斥。别把「最快」理解成「零开销」或「自带同步」。
:::

### 2.6 线程（★★★）

引入线程的目的：**减少程序并发执行时的时空开销**（创建、撤销、切换）。线程是**CPU 调度的基本单位**，进程仍是**资源分配的基本单位**；同一进程内的线程共享地址空间、全局变量、打开文件、信号处理器等，各自独享 **TCB、线程 ID、栈、寄存器上下文、程序计数器、errno、线程私有存储**。

| 比较项 | 进程 | 线程 |
| --- | --- | --- |
| 资源所有权 | 拥有资源（地址空间、文件、设备） | 基本不拥有，共享所属进程资源 |
| 调度 | 传统 OS 中既是资源单位也是调度单位 | **调度/分派的基本单位** |
| 并发性 | 进程间可并发 | 进程间 + 进程内线程间均可并发 |
| 切换开销 | 大（要换页表/TLB、上下文） | 小（同地址空间，无需换页表） |
| 独立性/隔离 | 强，一个崩不影响其它 | 弱，一个线程崩可能终止整个进程 |
| 通信 | 需 IPC | 直接读写共享变量（但须同步） |

![三种线程实现模型](/os/os-thread.svg)

| 实现方式 | 管理方 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 用户级线程 ULT（多对一） | 用户态线程库 | 切换不需陷入内核、可自定义调度、可在不支持线程的 OS 上实现 | **一个线程阻塞则整个进程阻塞**；多线程无法在多核上并行；系统调用阻塞问题需「包裹器/jacket」 |
| 内核级线程 KLT（一对一） | 内核 | 一个线程阻塞不影响其它；可多核并行 | 每次线程切换要陷入内核，开销较大 |
| 混合（多对多 / 两级） | 库 + 内核 | 兼顾灵活与并行 | 实现复杂（Linux 早期 LWP、Solaris；现代 Linux 用 1:1 的 NPTL） |

::: danger 易错 · 线程模型的两个"经典错答"
- 「用户级线程比内核级线程快」**只在切换时成立**，但 ULT 无法利用多核，且一处阻塞全进程停摆——所以现代通用 OS（Linux NPTL、Windows、pthread）都用 **1:1 内核级线程**。
- 「同一进程内线程切换不需要切换页表/TLB」成立，但**不同进程的线程切换**仍然要换地址空间（并带来 TLB 失效）。
- 「线程实现方式」与「线程具体实现」分开看时，容易漏掉：**协程/纤程**（用户态可调度的更轻单位，Go goroutine、Java 虚拟线程）其实是 ULT 思想的现代回归，靠运行时的**非阻塞 I/O + 挂起/恢复**规避阻塞问题。
:::

## 第 3 章 处理机调度

### 3.1 调度的层次与目标（★★★）

| 层次 | 名称 | 对象 | 频率 | 作用 |
| --- | --- | --- | --- | --- |
| 高级 | **作业调度**（长程、接纳调度） | 作业（从后备队列选入内存） | 最低（分钟级） | 决定**多道程序度**，为作业创建进程 |
| 中级 | **内存调度**（交换调度） | 挂起进程 | 中 | 换出/换入，平衡内存负荷（第 2 章七态） |
| 低级 | **进程调度**（短程、CPU 调度） | 就绪进程 | 最高（毫秒级） | 分派处理机，是 OS 核心 |

**调度时机**：当前进程终止／时间片到／因等待而阻塞／I/O 完成唤醒／出现更高优先级进程（抢占式）。
**不能调度**的情形：处理中断过程中、进程在**操作系统内核临界区**中、执行原语（原子操作）过程中。

| 指标 | 定义 |
| --- | --- |
| CPU 利用率 | 忙时间 / 总时间 |
| 吞吐量 | 单位时间完成的作业数 |
| 周转时间 `T` | 完成时刻 − 到达（提交）时刻 |
| 带权周转 `W` | `T / 服务时间 Ts ≥ 1`（越小越好，反映"相对等待"） |
| 等待时间 | 在就绪队列中等待的总时间 |
| 响应时间 | 首次提交请求到**首次产生响应**的时间（分时系统关键） |

::: danger 易错 · 周转时间与带权周转
- 周转时间**含**运行时间、就绪等待、阻塞等待（若题目给的是纯 CPU 作业则只含运行 + 就绪等待）；**等待时间不含运行时间**。
- `W = T/Ts` 恒 **≥ 1**，最小 1 表示"一来就一直跑到完"。SJF 可使平均 `T`、平均 `W` 最小，但长作业会饥饿。
- 「响应比」`R = (等待时间 + 服务时间)/服务时间 = 1 + 等待/服务`，与带权周转形式相似但用途不同：**响应比用于调度决策（选谁上 CPU），带权周转用于事后评价**。
:::

### 3.2 六种调度算法（★★★）

| 算法 | 抢占性 | 决策依据 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| FCFS（First Come First **Served**，先来先服务） | 非抢占 | 到达先后 | 公平、简单、实现容易 | **对短作业不利**（护航效应），平均周转长；对 CPU 繁忙型有利、I/O 繁忙型不利 |
| SJF / SPF | 可抢占（SRTF） | 服务时间最短 | **平均周转与平均带权周转最小**（可证明最优） | 需预知运行时间；长作业饥饿；不保证响应时间 |
| 优先级 PSA | 静态/动态、抢占/非抢占 | 优先级 | 可体现紧迫程度 | 低优先级饥饿（用**老化 aging** 提升等待久者的优先级） |
| HRRN | 非抢占 | 响应比 `R` 最高 | 兼顾等待时间与服务时间，长作业不会无限饥饿 | 每次调度要计算响应比，开销略大 |
| RR | 抢占（时间片） | 就绪队列轮转 | 响应快、公平，天然适合分时 | 时间片过大退化为 FCFS；过小则切换开销占比高 |
| 多级队列 MQ | 每队列可不同算法 | 按进程性质分队列（前台/后台） | 分类服务 | 队列间若固定优先级会饥饿 |
| **多级反馈队列 MFQ** | 抢占 | 多级队列 + 时间片递增 + 降级/升级 | **综合性能最好**（短作业快速完成、I/O 型优先、长作业最终也能得到大时间片） | 参数（队列数、时间片、提升周期）难调 |

::: tip MFQ 的工作规则（考研常考简答）
① 设 N 个就绪队列，优先级逐层降低、时间片逐层增大（如 1、2、4、8…）；② 新进程进第 1 级队尾，按 FCFS 等待；③ 若在时间片内未完成，则**降级**到下一级队尾；④ 仅当高优先级队列为空才调度低一级队列；⑤ 高优先级进程到达可**抢占**当前进程（被抢占者放回原队列队尾，不降级）；⑥ 为防止长作业饥饿，可周期性把等待过久的进程**提升**到高一级队列（aging）。
:::

### 3.3 工作例题 · 四种算法的完整手算（★★★）

设 5 个进程（到达时刻，服务时间）：`A(0,3) B(2,6) C(4,4) D(6,5) E(8,2)`，单位 ms。

**① FCFS**
```text
甘特: |  A(0-3)  |   B(3-9)    |  C(9-13)  |  D(13-18)  | E(18-20) |
```
| 进程 | 到达 | 服务 | 完成 | 周转 T | 带权 W |
| --- | --- | --- | --- | --- | --- |
| A | 0 | 3 | 3 | 3 | 1.00 |
| B | 2 | 6 | 9 | 7 | 1.17 |
| C | 4 | 4 | 13 | 9 | 2.25 |
| D | 6 | 5 | 18 | 12 | 2.40 |
| E | 8 | 2 | 20 | 12 | **6.00** |
| **平均** | | | | **8.60** | **2.56** |

**② SJF（非抢占）**：`t=0` 只有 A → A(0-3)；`t=3` 只有 B → B(3-9)；`t=9` 时 C/D/E 均已到达，按服务时间选 E(2) → E(9-11)，再 C(11-15)，再 D(15-20)。

| 进程 | 完成 | 周转 T | 带权 W |
| --- | --- | --- | --- |
| A | 3 | 3 | 1.00 |
| B | 9 | 7 | 1.17 |
| E | 11 | 3 | 1.50 |
| C | 15 | 11 | 2.75 |
| D | 20 | 14 | 2.80 |
| **平均** | | **7.60** | **1.84** |

**③ HRRN**：`t=9` 时算响应比 `R=1+等待/服务`：
`R_C = (5+4)/4 = 2.25`，`R_D = (3+5)/5 = 1.60`，`R_E = (1+2)/2 = 1.50` → **选 C**（9-13）。
`t=13`：`R_D = (7+5)/5 = 2.40`，`R_E = (5+2)/2 = 3.50` → **选 E**（13-15）→ D（15-20）。
平均周转 `= (3 + 7 + 9 + 7 + 14)/5 = 8.00`，平均带权 `2.14`。

**④ RR**：另取 `P1(0,4) P2(1,3) P3(2,2)`，时间片 `q=2`（新到达者先入队，用完时间片者再排到队尾）：

```text
q=2:  P1[0-2] P2[2-4] P3[4-6] P1[6-8] P2[8-9]
完成: P3=6  P1=8  P2=9
周转: P1=8  P2=8  P3=4     平均 6.67     平均带权 (2+2.67+2)/3 = 2.22
q=1:  P1 P2 P1 P3 P2 P1 P3 P2 P1  → 完成 P3=7 P2=8 P1=9，平均周转 7.00
q=4:  P1[0-4] P2[4-7] P3[7-9]   → 完成 P1=4 P2=7 P3=9，平均周转 5.67（已退化为 FCFS）
```

::: tip 工作示例 · 抢占式 SJF（SRTF）手算
仍用 `A(0,3) B(2,6) C(4,4) D(6,5) E(8,2)`，规则：**新进程到达时比较"剩余服务时间"，更短者抢占**。
```text
t=0  A(3) 运行
t=2  B 到达(6)，A 剩 1 < 6 → A 继续
t=3  A 完成；只剩 B → B 运行
t=4  C 到达(4) < B 剩 5 → C 抢占
t=6  D 到达(5)，C 剩 2 最短 → C 继续
t=8  E 到达(2) < C? C 已完成于 t=8；比较 E(2)、B(5)、D(5) → E 运行
t=10 E 完成；B(5)=D(5) 平局，先到者优先 → B(10-15) → D(15-20)
```
| 进程 | 完成 | 周转 T | 带权 W |
| --- | --- | --- | --- |
| A | 3 | 3 | 1.00 |
| C | 8 | 4 | 1.00 |
| E | 10 | 2 | 1.00 |
| B | 15 | 13 | 2.17 |
| D | 20 | 14 | 2.80 |
| **平均** | | **7.20** | **1.59** |

对比非抢占 SJF 的 7.60/1.84：**抢占式（SRTF）平均周转更短**；与非抢占 SJF 一样仍需预知运行时间，且切换次数增多。
:::

::: danger 易错 · RR 时间片与"上下文切换开销"
- 若一次切换耗时 `s`，时间片 `q`，则切换开销占比约 `s/(q+s)`；`q` 太小会"把 CPU 全花在切换上"，还造成 TLB/缓存失效。
- **q 增大不保证平均周转单调下降**：本例 q=1 → 7.00，q=2 → 6.67，q=4 → 5.67 恰好递减，但换成别的进程集可能非单调，考试须按甘特图实算，不能凭直觉。
- 抢占式 SJF（SRTF）与新进程到达时要**重新比较剩余服务时间**，不是比较总服务时间。
:::

### 3.4 多处理机调度与实时调度（★★）

| 主题 | 要点 |
| --- | --- |
| 多处理机调度算法 | 自调度（各 CPU 共享全局就绪队列）、成组调度（ gang scheduling，一组相关线程同时上多核）、专用处理机分配 |
| 负载均衡 | 推迁移／拉迁移，周期性把任务从忙 CPU 迁到闲 CPU |
| 处理机亲和性 | 软亲和（尽量留原 CPU 以复用缓存）／硬亲和（绑定，牺牲均衡换缓存局部性） |
| 实时调度条件 | 就绪时间、开始/完成截止时间、处理时间、资源需求、优先级；系统须**可调度**且支持抢占 |
| EDF（最早截止时间优先） | 动态优先级，截止越早越优先；**单处理器上是最优的动态调度算法** |
| LLF（最低松弛度优先） | 松弛度 `= 必须完成时间 − 尚需运行时间 − 当前时刻`，越小越紧急 |
| RMS（速率单调） | 静态优先级，周期越短优先级越高；可调度充分条件 `U ≤ n(2^(1/n) − 1)`，n→∞ 时上界 `ln2 ≈ 0.693` |
| 优先级倒置 | 高优先级进程被低优先级进程持有的资源阻塞，中间优先级进程又抢占，导致高优先级被**无限延迟** |

::: tip 补充 · 优先级倒置的现代解法与 Linux 调度演进
- 解法：**优先级继承**（持锁者临时继承等待者的优先级，用完即恢复）或**优先级天花板协议**；经典事故是 1997 年火星探路者号因优先级倒置反复复位。
- **完全公平调度器 CFS**：用 `vruntime`（虚拟运行时间，按权重换算）把进程挂在红黑树最左侧，实现"按权重比例分配 CPU"，不再是固定时间片轮转。
- **更新的演进**：Linux 6.6 起以 **EEVDF（Earliest Eligible Virtual Deadline First）** 替代 CFS，引入"合格时间 + 虚拟截止时间"以更好地支持延迟敏感任务与 `latency_nice`；此外还有 **SCHED_DEADLINE**（基于 CBS + GRUB 的 EDF 实现）、**schedutil** 与 DVFS 联动、**cgroup CPU 配额**、**NUMA 感知的负载均衡**。多级反馈队列与 RR 仍是理解这些机制的**概念基础**，但现代内核不再直接照搬。
:::

## 第 4 章 进程同步与死锁

### 4.1 同步、互斥与临界区准则（★★★）

- **临界资源**：一次只允许一个进程使用的资源（打印机、共享变量、缓冲区）。
- **临界区**：进程中访问临界资源的那段代码。
- **同步**（直接制约）：为完成共同任务而协调执行次序（如生产者必须在消费者取走后才能放）。
- **互斥**（间接制约）：因争用临界资源而互相排斥。

临界区四准则：**空闲让进、忙则等待、有限等待、让权等待**（前三条必须满足；「让权等待」指不能进入临界区的进程应释放 CPU，软件/硬件的忙等方案不满足它）。

### 4.2 同步机制谱系（★★★）

| 机制 | 代表 | 是否忙等 | 关键性质 |
| --- | --- | --- | --- |
| 软件方法 | 单标志法、双标志先修改、双标志后修改、**Peterson** | 忙等 | Peterson 用 `flag[2] + turn` 满足三准则，但只适用两进程且忙等 |
| 硬件方法 | **关中断**、TSL(TestAndSet)、Swap(XCHG)、CAS | 忙等 | 原子指令保证"检查+上锁"不可分；关中断只适用单 CPU 且不能交用户 |
| 锁 | 互斥锁、自旋锁、读写锁、递归锁 | 自旋锁忙等 | 互斥锁阻塞时让出 CPU；自旋锁适用持有时间极短、多核场景 |
| **信号量** | 整型／记录型／AND 型／信号量集 | 记录型不忙等 | `P`/`V`（`wait`/`signal`）为原子操作，可表达互斥与同步 |
| **管程** | 管程 + 条件变量 | 不忙等 | 把共享变量与对其的操作**封装**起来，编译器保证互斥 |

```c
/* Peterson 算法（两进程互斥，重点） */
int flag[2] = {0, 0};   /* 想进临界区的意愿 */
int turn;                /* 谁优先（后设置者让先设置者） */

void enter(int i) {
    int j = 1 - i;
    flag[i] = 1;        /* 先声明意愿 */
    turn = j;           /* 后写 turn：谦让 */
    while (flag[j] && turn == j) ;   /* 忙等 */
}
void leave(int i) { flag[i] = 0; }
```

```c
/* 记录型信号量：S.value > 0 表示可用资源数；< 0 时绝对值表示等待进程数 */
typedef struct { int value; struct process *L; } semaphore;

void wait(semaphore *S) {           /* P */
    S->value--;
    if (S->value < 0) block(S->L);  /* 自我阻塞，插入等待队列 */
}
void signal(semaphore *S) {         /* V */
    S->value++;
    if (S->value <= 0) wakeup(S->L);/* 唤醒一个等待进程 */
}
```

::: danger 易错 · 信号量的核心陷阱
- **整型信号量**「只要 `S ≤ 0` 就不断测试」会**忙等**，违反让权等待；记录型才引入阻塞队列。
- `S.value < 0` 时 `|S.value|` **等于阻塞在该信号量上的进程数**；`V` 后 `S.value ≤ 0` 才需唤醒。
- **P/V 必须成对且顺序严格**：互斥 P 放在同步 P 之后（否则可能死锁）；对同一信号量的 P、V 不能遗漏。
- `V` 操作**不会被阻塞**（可以唤醒别人，自己永远能继续）；`P` 才可能阻塞。
- 多个进程对多个临界资源「各 P 一个」若顺序不同会死锁 → 用 **AND 型信号量**（一次原子地申请全部）或按统一编号顺序申请。
:::

### 4.3 三大经典 PV 问题（★★★）

**① 生产者-消费者（n 个缓冲区）**
```c
semaphore mutex = 1;     /* 缓冲池互斥 */
semaphore empty = n;     /* 空缓冲区数 */
semaphore full  = 0;     /* 满缓冲区数 */

void producer(void) {
    while (1) {
        produce(&item);
        P(empty);        /* 先同步 */
        P(mutex);        /* 后互斥 —— 顺序不可颠倒 */
        append(item);
        V(mutex);
        V(full);
    }
}
void consumer(void) {
    while (1) {
        P(full);
        P(mutex);
        item = take();
        V(mutex);
        V(empty);
        consume(item);
    }
}
```

**② 读者-写者（读者优先）**
```c
semaphore wmutex = 1;    /* 写者与写者/首个读者互斥 */
semaphore rmutex = 1;    /* 保护 readcount */
int readcount = 0;

void reader(void) {
    P(rmutex);
    if (readcount == 0) P(wmutex);   /* 第一个读者上锁 */
    readcount++;
    V(rmutex);
    read();
    P(rmutex);
    readcount--;
    if (readcount == 0) V(wmutex);   /* 最后一个读者解锁 */
    V(rmutex);
}
void writer(void) { P(wmutex); write(); V(wmutex); }
```
读者优先会导致**写者饥饿**；写者优先解法需再加 `semaphore w = 1`，在「有写者等待时阻止新读者进入」。

**③ 哲学家进餐（防死锁三法）**
```c
/* 法1：至多允许 4 人同时拿叉 */
semaphore room = 4, chop[5] = {1,1,1,1,1};
void philosopher(int i) {
    while (1) {
        think();
        P(room);
        P(chop[i]); P(chop[(i+1)%5]);
        eat();
        V(chop[i]); V(chop[(i+1)%5]);
        V(room);
    }
}
/* 法2：奇数号先左后右、偶数号先右后左（破坏环路等待）
   法3：用 AND 型信号量 SP(chop[i], chop[(i+1)%5]) 原子取两把叉 */
```

::: tip 现代同步原语
- **futex（fast userspace mutex）**：Linux 线程同步的基石。无竞争时完全在**用户态**用一个原子整型完成（不陷入内核）；有竞争时才通过 `futex_wait/futex_wake` 进入内核阻塞队列。上层的 `pthread_mutex`、条件变量、信号量都基于它——解决了「锁的大部分时间无人争用，却每次都要系统调用」的浪费。
- **条件变量**：管程思想在 pthread 中的落地，必须**与互斥锁配合**并用 `while` 而非 `if` 检查条件（防虚假唤醒 spurious wakeup）。
- **无锁编程**：CAS + 内存屏障实现原子队列/引用计数；要处理 ABA 问题（版本号/双字 CAS）。
- **RCU**：读侧几乎零开销，见第 10 章。
:::

### 4.4 死锁（★★★）

**四个必要条件**（缺一不可）：互斥使用、请求和保持（已占资源不放又申请新资源）、不可剥夺（不可抢占）、**环路等待**。

| 处理策略 | 做法 | 代价 |
| --- | --- | --- |
| 预防 | 破坏四个条件之一：资源一次性分配（破请求保持）、申请失败则释放已有（破不可剥夺）、**资源线性编号按序申请**（破环路等待） | 资源利用率低、限制并发 |
| 避免 | 动态检查分配后系统是否仍**安全**（银行家算法） | 需预知最大需求；进程数/资源数固定；开销大 |
| 检测 | 允许死锁发生，周期性跑**死锁检测算法**（资源分配图化简 / 类似银行家的 Work 扫描） | 检测本身有开销 |
| 解除 | 剥夺资源、撤销（终止）进程、进程回退（回滚到检查点） | 可能丢失工作；要选"代价最小"的牺牲者 |

::: danger 易错 · 安全状态 ≠ 无死锁？
- **安全状态**一定**无死锁**；**不安全状态不一定已死锁**，只是"存在走向死锁的可能"。银行家算法拒绝不安全请求，本质是把系统状态**始终约束在安全子集**内。
- 死锁预防「资源按序申请」破坏的是**环路等待**，不是"互斥"（很多资源本质上必须互斥，无法破坏）。
- 死锁检测中「可完全化简的资源分配图」⇔ 无死锁；若化简后仍有边连着进程，则这些进程处于死锁。
:::

### 4.5 工作例题 · 银行家算法完整演算（★★★）

系统有 3 类资源 `A/B/C`，总量 `(10, 5, 7)`；`T0` 时刻状态如下：

| 进程 | Allocation 已分配 | Max 最大需求 | Need = Max − Allocation |
| --- | --- | --- | --- |
| P0 | (0,1,0) | (7,5,3) | (7,4,3) |
| P1 | (2,0,0) | (3,2,2) | (1,2,2) |
| P2 | (3,0,2) | (9,0,2) | (6,0,0) |
| P3 | (2,1,1) | (2,2,2) | (0,1,1) |
| P4 | (0,0,2) | (4,3,3) | (4,3,1) |

已分配合计 `(7,2,5)` → `Available = (10,5,7) − (7,2,5) = (3,3,2)`。

**安全性检查**（`Work = Available`，反复找 `Need_i ≤ Work` 的进程，令其"假想完成"并归还其 **Allocation**）：

| 步 | Work（开始时） | 选中 | 判据 | Work（归还后）= Work + Allocation |
| --- | --- | --- | --- | --- |
| 1 | (3,3,2) | **P1** | Need (1,2,2) ≤ Work | (3,3,2)+(2,0,0) = (5,3,2) |
| 2 | (5,3,2) | **P3** | (0,1,1) ≤ Work | (5,3,2)+(2,1,1) = (7,4,3) |
| 3 | (7,4,3) | **P0** | (7,4,3) ≤ Work | (7,4,3)+(0,1,0) = (7,5,3) |
| 4 | (7,5,3) | **P2** | (6,0,0) ≤ Work | (7,5,3)+(3,0,2) = (10,5,5) |
| 5 | (10,5,5) | **P4** | (4,3,1) ≤ Work | (10,5,5)+(0,0,2) = (10,5,7) |

所有进程均能完成 → **存在安全序列 ⟨P1, P3, P0, P2, P4⟩，T0 状态安全**（安全序列**不唯一**）。

**处理请求 `Request1 = (1,0,2)`**：
① `Request1 ≤ Need1 (1,2,2)` ✓；② `Request1 ≤ Available (3,3,2)` ✓；
③ 试探分配：`Available = (2,3,0)`、`Allocation1 = (3,0,2)`、`Need1 = (0,2,0)`；
④ 安全性检查得安全序列 ⟨P1, P3, P0, P2, P4⟩ → **可以立即分配**。

**反例：一个必须被拒绝的请求**（2 类资源，总量 `(10,5)`）：

| 进程 | Allocation | Need | 初始 Available = (4,2) |
| --- | --- | --- | --- |
| P1 | (3,2) | (4,2) | 初始安全序列 ⟨P1, P2⟩ |
| P2 | (3,1) | (4,3) | |

若 P2 请求 `(2,1)`：满足 `Request ≤ Need` 与 `≤ Available`，试探后 `Available = (2,1)`、`Allocation2 = (5,2)`、`Need2 = (2,2)`。此时 `Work = (2,1)`：P1 的 Need `(4,2)` 不满足（A 不足），P2 的 Need `(2,2)` 也不满足（B 不足）→ **无任何进程可完成，状态不安全，必须拒绝该请求**（令 P2 等待）。

![资源分配图与银行家算法](/os/os-deadlock.svg)

::: tip 银行家算法的现实定位
银行家算法是「死锁避免」的标准解法，但**通用操作系统几乎不实现它**：进程的最大资源需求难以预先声明、资源数量动态变化、检查开销高。工程上的做法是「预防 + 检测/超时 + 设计规约」：按统一顺序加锁（可用 lockdep 静态/动态检测锁序反转）、`try_lock` 超时回退、数据库用**等待图 + 死锁检测 + 事务回滚**、内核用锁类编号与看门狗。考研仍须掌握手算，但要理解它是**理论模型**。
:::

## 第 5 章 存储器管理

### 5.1 存储层次、装入与链接（★★）

| 层次 | 典型容量/速度 | 管理方 |
| --- | --- | --- |
| 寄存器 | 几十字节 / 1 个时钟周期 | 编译器/硬件 |
| 高速缓存 Cache | KB~MB / ns | **硬件**（对 OS 基本透明） |
| 主存 | GB / 几十 ns | **OS**（本管理主体） |
| 磁盘缓存 | 主存中的一部分 | OS（页缓存/缓冲区） |
| 固定磁盘 / 可移动存储 | TB / ms | OS + 设备驱动 |

| 概念 | 分类 | 要点 |
| --- | --- | --- |
| 地址绑定 | 编译时（绝对装入）／装入时（**静态重定位**）／运行时（**动态重定位**） | 现代 OS 用动态运行时装入，靠 **重定位寄存器（基址）+ 界地址（限长）寄存器** 在每次访存时做变换与越界检查 |
| 装入方式 | 绝对装入、可重定位装入、动态运行时装入 | 绝对装入只适单道程序；可重定位装入后地址**不再改变** |
| 链接方式 | 静态链接、装入时动态链接、**运行时动态链接** | 运行时链接便于共享库（`.so`/`.dll`）、节省内存、方便更新 |
| 逻辑/物理地址 | 逻辑（相对/虚拟）地址空间 vs 物理（绝对）地址空间 | 地址变换由 **MMU** 硬件完成 |

::: danger 易错 · 保护与重定位
- 「内存保护」由**硬件**在每次访存时检查（基址 + 限长，或页表项的有效/读写位），OS 只负责**设置**这些寄存器/页表。
- 静态重定位**不能**在程序运行中移动它，也不能实现虚拟存储（因为装入后地址就固定了）；紧凑（拼接）技术必须依赖**动态重定位**。
- 「编译 → 链接 → 装入」的顺序不能颠倒；`malloc` 拿到的是**虚拟地址**，物理页可能要到真正写入时才分配（延迟分配/请求调页）。
:::

### 5.2 交换与覆盖（★★）

- **覆盖**（早期）：程序员把不会同时执行的程序段划为一组、共用同一覆盖区；**对用户不透明**，已淘汰。
- **交换**：把暂时不运行的进程（或页/段）整体换出到外存**交换区/交换文件**，需要时再换入；由中级调度驱动。
- 交换区与文件区区别：交换区**不存放文件的长期数据**、空间连续或块映射简单、追求换入换出速度；文件区要管理目录、索引、空闲空间与持久性。
- 交换的代价：磁盘 I/O 极慢；换出优先级应避开正在 I/O 的进程（否则 I/O 缓冲区被换出会出错，常用**锁住页面 pin**）。

### 5.3 连续分配方式（★★★）

| 方式 | 思想 | 碎片 | 评价 |
| --- | --- | --- | --- |
| 单一连续分配 | 内存分系统区 + 用户区，一次只装一道程序 | 无内部碎片但有大量浪费 | 只适单用户单任务 |
| 固定分区分配 | 预先划分若干固定大小（可相等/不等）分区 | **内部碎片** | 简单但限制并发度、大作业装不下 |
| 动态分区分配 | 按作业实际需要**现场**划分区 | **外部碎片** | 需分配算法 + 回收合并；可用**紧凑**整理 |
| 动态重定位分区 | 动态分区 + 紧凑 + 重定位寄存器 | 外部碎片可被整理 | 紧凑要移动全部已装入程序，开销大 |

动态分区四种分配算法（空闲分区链按**地址递增**排列时）：

| 算法 | 做法 | 效果 |
| --- | --- | --- |
| 首次适应 FF | 从链首找第一个够大的分区 | 高址部分保留大分区；低址留下大量小碎片、查找变慢 |
| 循环首次适应 NF | 从**上次找到的位置之后**开始 | 碎片分布较均匀，但可能破坏大分区 |
| 最佳适应 BF | 找**最小且够大**的分区（按容量递增排序） | 保留大分区；但会留下大量**难以利用的极小碎片** |
| 最坏适应 WF | 挑**最大**分区（按容量递减排序） | 剩余分区仍较大可用；但大分区很快被切小，不利于大作业 |

::: tip 工作示例 · 一次分配请求的四种结果
空闲分区链（按地址序）：`(20K, 50K, 30K, 100K)`，作业请求 **14K**：

- **FF** → 取 20K，剩 6K 挂在原处 → 链 `(6K, 50K, 30K, 100K)`
- **NF**（上次分配到 20K，从其后开始）→ 取 50K，剩 36K → 链 `(20K, 36K, 30K, 100K)`
- **BF** → 最小的够大者仍是 20K，剩 6K → 同 FF
- **WF** → 取 100K，剩 86K → 链 `(20K, 50K, 30K, 86K)`

可见「最佳适应」并不总是全局最优：它每次都制造最小剩余块，长期看碎片最多。工程上现代内核的**伙伴系统（buddy） + slab/slub** 用 2 的幂次块 + 分级空闲链表，兼顾分配速度与碎片控制。
:::

**分区回收的四种情况**：① 回收区与前空闲区相邻 → 合并（改大小）；② 与后相邻 → 合并（改始址 + 大小）；③ 与前后都相邻 → 三合一（减少一个表项）；④ 都不相邻 → 新建一个空闲表项。

### 5.4 分页存储管理（★★★）

**基本思想**：把用户程序的**逻辑地址空间**分成等长的**页（page）**，把**内存物理空间**分成同样大小的**块/页框（frame）**；分配以块为单位，离散存放，靠**页表**建立「页号 → 物理块号」映射。

| 概念 | 说明 |
| --- | --- |
| 页大小 | 必须是 2 的幂（便于硬件拆分地址）；太小 → 页表过长、换入换出频繁；太大 → 页内碎片增大。常见 4 KB |
| 页表项 PTE | 物理块号 + 有效位/读写位/访问位/修改位/缓存控制等 |
| 地址结构 | `逻辑地址 = 页号 p | 页内偏移 d`；`p = A / L`，`d = A mod L`（L 为页大小） |
| 地址变换 | `物理地址 = 页表[p] 的块号 × L + d`（页内偏移**不变**） |
| 碎片 | 只有**最后一页可能有页内碎片**（平均 L/2），**无外部碎片** |

::: tip 工作示例 · 分页地址变换手算
设页大小 `L = 1 KB = 1024 B`，页表：`0→2, 1→3, 2→8`，求逻辑地址 `A = 2500` 的物理地址。

```text
p = 2500 / 1024 = 2        （整除）
d = 2500 mod 1024 = 452
查页表：第 2 页 → 第 8 块
物理地址 = 8 × 1024 + 452 = 8192 + 452 = 8644
```
**二进制快算法**（页大小 2^10，故低 10 位就是页内地址）：
`2500 = 10 0111000100₂` → 高 2 位 `10₂ = 2` 为页号，低 10 位 `0111000100₂ = 452` 为偏移；块号 `8 = 1000₂`，拼接得 `1000 0111000100₂ = 8644`。**只要把页号替换成块号，低位原样保留**——这是分页与分段最大的区别（分段要「段基址 + 段内偏移」做加法）。
:::

::: tip 工作示例 · 页表容量与多级页表
32 位逻辑地址、页大小 4 KB（`2^12`）、页表项 4 B：
- 页内偏移占 12 位 → 页号占 20 位 → 共 `2^20 = 1 048 576` 个页表项
- 单级页表大小 `= 2^20 × 4 B = 4 MB`，且**每个进程**都要一份、还要求连续内存
- 两级页表：页号拆为 `10 + 10`，外层页表 `2^10 × 4 B = 4 KB`；只有被用到的二级页表才创建 → 典型只需 `4 KB + 少数 × 4 KB`，但**每次访存多一次**（3 次访存）
- 64 位系统（x86-64 实际用 48 位虚拟地址、4 级页表 `9+9+9+9+12`）级数更多，故必须靠 **TLB + 大页（2 MB / 1 GB）** 压低开销
:::

**快表 TLB 与有效访问时间 EAT**（设查 TLB `t = 20 ns`，一次访存 `ma = 100 ns`，命中率 `λ = 90%`）：

```text
命中 : t + ma = 20 + 100 = 120 ns      （查 TLB 得块号 → 直接访存取数据）
未命中: t + ma(查页表) + ma(取数据) = 20 + 200 = 220 ns
EAT  = 0.9 × 120 + 0.1 × 220 = 108 + 22 = 130 ns
对照: 无 TLB 的分页 = 2ma = 200 ns；两级页表无 TLB = 3ma = 300 ns
```
若 `λ = 98%`，`EAT = 0.98×120 + 0.02×220 = 122 ns`——**命中率几个百分点就决定性能**，这是 TLB 与 ASID（地址空间标识，切换进程时避免整体刷新 TLB）如此重要的原因。

::: tip 页面共享与保护（高频考点）
- **可共享页面必须是纯代码（可重入代码）**：多个进程的页表项指向**同一物理块**，且各进程对共享页的**逻辑页号必须相同**（否则一方置换/重定位会破坏另一方的映射）。典型例子：多进程共享同一个编辑器/库代码段。
- 若共享页是数据（可读写），一个进程的修改对其它进程立即可见，且置换时会互相牵连，一般不允许。
- 共享带来的收益：`n` 个进程共享 `k` 页代码，物理内存只占一份；各进程页表中该项的**读写位**可不同（如代码段对所有人只读+可执行）。
- 分段中共享更自然：以**段**为单位共享一个子程序（整段只读可执行），比按页共享不会把无关内容挤进同一段。
:::

::: danger 易错 · 分页相关高频错
- 分页**一维**地址（只需一个逻辑地址）；分段**二维**（段号 + 段内偏移），因为段长不等。
- 「页内碎片」只出现在进程最后一页；分页**没有外部碎片**，但仍浪费页表内存。
- 页表基址在**页表基址寄存器（PTBR / CR3）**中，进程切换时换掉它并（可能）刷新 TLB；这才是上下文切换的主要隐性开销。
- **反置页表**按物理块组织（每项记「进程号 + 页号」），全系统**只一张**，节省内存但查找需哈希/联想寄存器，且难以实现共享内存。
:::

### 5.5 分段与段页式（★★★）

| 比较项 | 分页 | 分段 |
| --- | --- | --- |
| 划分依据 | **物理**单位，固定大小，用户不可见 | **逻辑**单位（主程序/子程序/数据/栈），长度不定，用户可见 |
| 地址形式 | 一维（页号由硬件从地址拆出） | 二维（段号 + 段内偏移） |
| 目的 | 提高内存利用率、消除外部碎片（系统需要） | 方便编程、共享、保护、动态链接（用户需要） |
| 碎片 | 页内碎片（平均半页） | **段间外部碎片** |
| 共享/保护 | 按页不直观（可能把不同逻辑内容挤进一页） | **按段天然共享与保护**（一个子程序 = 一段，只读/可执行） |
| 地址变换 | 块号 × L + d | **段基址 + 段内偏移**，并校验 `偏移 < 段长` |

**段页式**：先把用户程序分段，每段再分页；地址 = `段号 | 段内页号 | 页内偏移`。每个进程一张段表，每段一张页表；访问一次数据需 **3 次访存**（段表 → 页表 → 数据），配 TLB 可降到 1 次。兼具分段的逻辑清晰与分页的无外部碎片，但管理最复杂（现代 x86-64 实际已弱化分段，段基址置 0）。

## 第 6 章 虚拟存储器

### 6.1 局部性原理与虚拟存储器（★★★）

**局部性原理**（Denning）：程序执行时呈现出
- **时间局部性**：刚被访问的指令/数据不久后可能再被访问（循环、局部变量、计数器）；
- **空间局部性**：刚被访问的存储单元附近的单元不久后可能被访问（顺序执行、数组遍历、结构体）。

虚拟存储器＝**具有请求调入功能和置换功能、能从逻辑上扩充内存容量**的存储器管理系统。其容量由**计算机地址结构（CPU 寻址位数）**与外存可用空间共同决定，而非物理内存大小。

| 特征 | 含义 |
| --- | --- |
| 多次性 | 作业无需一次全部装入，可分多次调入（最关键） |
| 对换性 | 暂不用的页/段可换出，需要时再换入 |
| 虚拟性 | 从逻辑上扩充内存，用户看到的是远大于物理内存的虚拟地址空间 |

::: danger 易错 · 虚存容量
- 虚存**最大容量 = min(地址空间上限 2^位数, 内存 + 外存可用空间)**。例如 32 位地址 → 上限 4 GB，即使磁盘有 1 TB，单个进程虚存也不超过 4 GB。
- 虚存建立在**离散分配**（分页/分段）基础上，连续分配方式无法实现；且必须有**硬件支持**（页表机制、缺页中断机构、地址变换机构）。
- 「虚拟存储器」不等于「交换区」：交换区只是存放换出页的外存区域。
:::

### 6.2 请求分页的硬件支持（★★★）

| 页表项新增字段 | 作用 |
| --- | --- |
| 状态位（有效位 P） | 该页是否已在内存；为 0 时访问触发**缺页中断** |
| 访问位 A | 记录是否被访问过，供 Clock/LRU 类算法与页回收使用 |
| 修改位 D（脏位） | 页被写过；换出时**未修改页可直接丢弃**，不必写回磁盘 |
| 外存地址 | 该页在磁盘/交换区的位置 |
| 保护/缓存位 | 读写执行权限、是否可缓存等 |

**缺页中断**与一般中断的区别：① 在**指令执行期间**（取指或访存时）产生并处理，而非指令执行完后；② 一条指令执行期间可能**产生多次**缺页（如跨页的指令、源操作数与目的操作数分处不同页）；③ 处理完后**重新执行该条指令**（而非执行下一条）；④ 属于**异常（内中断）**，但处理过程中可能再发生缺页（需保存现场）。

**缺页处理流程**：查页表发现 P=0 → 保存现场、陷入内核 → 找空闲物理块（无则按置换算法选牺牲页，脏页先写回）→ 从外存读入所需页 → 更新页表项（置 P=1、清 D）→ 恢复现场 → **重新执行被中断的指令**。

| 分配策略 | 说明 |
| --- | --- |
| 固定分配局部置换 | 每进程固定物理块数，只在自己的块内换出 |
| 可变分配全局置换 | 系统维护空闲块队列，缺页时可**从其它进程**夺块（最常用，但可能引发抖动） |
| 可变分配局部置换 | 根据缺页率动态增减该进程的块数（结合工作集） |
| 最小物理块数 | 要保证一条指令能完整执行所需的块数，与指令格式和寻址方式有关 |

### 6.3 页面置换算法（★★★）

| 算法 | 依据 | 是否可实现 | 特点 |
| --- | --- | --- | --- |
| OPT（最佳） | 淘汰**未来最长时间不再访问**的页 | 否（需预知未来） | 缺页率理论下界，作为评价基准 |
| FIFO | 淘汰**最早进入**内存的页 | 是 | 简单但可能淘汰常用页；存在 **Belady 异常** |
| LRU | 淘汰**最近最久未使用**的页 | 是（需寄存器/栈硬件支持，开销大） | 性能接近 OPT；无 Belady 异常（属栈式算法） |
| LFU | 淘汰**访问次数最少**的页 | 是 | 无法反映"近期"热度，早期常访问的页不易淘汰 |
| Clock（NRU / 二次机会） | 用访问位 A 组成循环队列扫描，A=1 清 0 给一次机会，A=0 换出 | 是 | LRU 的低成本近似，工业界常用 |
| **改进型 Clock** | 同时考虑 (A, D) 四类 | 是 | 优先换出 (0,0) 且**无需写回**，顺序 `(0,0)→(0,1)→(1,0)→(1,1)` |
| 页面缓冲算法 PBA | 换出页暂放空闲/修改链表，不立即写盘 | 是 | 减少磁盘 I/O，可快速"回收"误淘汰页 |

::: tip 工作示例 · 三种算法的完整手算（经典页面走向）
页面走向：`7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1`（共 20 次访问），分配 **3 个物理块**（初始为空）。

| 算法 | 缺页次数 | 缺页率 |
| --- | --- | --- |
| **FIFO** | **15** | 75.0% |
| **LRU** | **12** | 60.0% |
| **OPT** | **9** | 45.0% |

以 FIFO 为例的前几步：访问 7（缺，装入 7）→ 0（缺，装入 0）→ 1（缺，装入 1，满）→ 2（缺，**淘汰最早进入的 7**）→ 0（命中）→ 3（缺，淘汰 0）→ 0（缺，淘汰 1）→ 4（缺，淘汰 2）…… 逐次记录可得 15 次。
若给 **4 个物理块**：FIFO = 10 次、LRU = 8 次、OPT = 8 次（增加块数通常降低缺页率，但 FIFO 不保证）。
:::

::: tip 工作示例 · Clock 算法的扫描过程
3 个物理块，当前循环队列（指针指向块 1）：`[1(A=1), 2(A=1), 3(A=0)]`，请求访问页 **4**：
1. 扫到块 1：`A=1` → 清 0，指针后移（给"第二次机会"）；
2. 扫到块 2：`A=1` → 清 0，指针后移；
3. 扫到块 3：`A=0` → **淘汰页 3**，装入页 4，指针移到块 3 的下一位置；
4. 结果：`[1(A=0), 2(A=0), 4(A=1)]`。

**改进型 Clock** 按 `(A,D)` 四元组分两轮扫描：第一轮找 `(0,0)`（不写回、直接换出）；找不到则第二轮找 `(0,1)`（需写回），同时把扫过的 `(1,x)` 的 A 清 0；再找不到则第三轮必能遇到被自己清成 `(0,x)` 的页。优先淘汰 `(0,0)` 是为了**省一次磁盘写**。
:::

::: tip Belady 异常（考研高频）
**Belady 异常**：某些置换算法（如 FIFO）在**增加物理块数**后，缺页次数反而上升。
取页面走向 `1 2 3 4 1 2 5 1 2 3 4 5`：

| 算法 | 3 个物理块 | 4 个物理块 | 结论 |
| --- | --- | --- | --- |
| **FIFO** | **9 次** | **10 次** | **出现 Belady 异常** |
| LRU | 10 次 | 8 次 | 正常（减少） |

原因：FIFO 只按"进入先后"淘汰，不遵守**栈式性质**（"在 n 个块中驻留的页集合必须是 n+1 个块中驻留集合的子集"）。LRU、OPT 都是栈式算法，故**不可能出现 Belady 异常**；Clock 是近似算法，一般不出现。这一反直觉结论是高频考点，复习时务必掌握。
:::

**缺页率与有效访问时间 EAT**（设 `ma = 100 ns`，缺页处理含磁盘 I/O 约 `10 ms = 10⁷ ns`）：

```text
EAT = (1 − p) × ma + p × 缺页处理时间
p = 0      → 100 ns
p = 0.001  → 0.999×100 + 0.001×10⁷ ≈ 10 100 ns   （约 100 倍）
p = 0.01   → 0.99×100 + 0.01×10⁷  ≈ 100 099 ns  （约 1000 倍）
```
结论：**缺页率哪怕只有 1%，性能也会塌方式下降**——所以虚存可行的前提是程序具有良好的局部性。

### 6.4 抖动、工作集与内存映射文件（★★）

| 概念 | 说明 |
| --- | --- |
| **抖动（thrashing）** | 同时运行的进程太多、每个分到的物理块数小于工作集，导致刚换出的页马上又要换入，CPU 利用率骤降、磁盘忙得不可开交 |
| 根本原因 | 多道程序度过高 + 全局置换 + 局部性差 |
| **工作集 W(t, Δ)** | 进程在最近 `Δ` 个时间单位（工作集窗口）内访问过的页集合；`|W|` 为工作集大小 |
| 预防 | 采用局部置换、给每进程分配不小于工作集的块数、利用**缺页率反馈**调节多道程序度（缺页率过高就挂起若干进程）、预调页 + 负载控制 |
| **内存映射文件 mmap** | 把文件直接映射到进程虚拟地址空间，用**缺页异常按需读入文件页**，免去 `read` 的显式拷贝；`MAP_SHARED` 的修改由内核延迟写回（**不保证即时落盘**，须 `msync`/`fsync`） |

::: tip 现代内核的虚存机制
- **页缓存（page cache）+ 回写**：文件读写先命中内存中的页缓存，`pdflush`/`writeback` 线程按脏页比例与超时批量写盘；`O_DIRECT` 可绕过页缓存。
- **按需分配与 COW**：`malloc` 只扩虚拟区间（VMA），首次写入才分配物理页；`fork` 的写时复制也靠缺页异常实现。
- **内存回收与 OOM**：kswapd 按 LRU 链表（active/inactive）扫描回收，回收不足时 **OOM killer** 按 `oom_score` 选进程终止；可用 `zswap`/`zram` 先压缩换出页。
- **大页（THP / hugetlb）**：2 MB/1 GB 页减少 TLB miss 与页表层级；**cgroup memory** 做容器内存限额；**ASID/PCID** 让进程切换时不必全刷 TLB。
- 注意：以 Windows XP 与早期 Linux 为例的"虚拟存储器实现"，其 32 位 4 GB 划分、三级页表等结论已不适用于 64 位现代系统；考试按原理作答，工程上应以上述机制为准。
:::

::: danger 易错 · 请求分页高频错
- 缺页中断是**异常**，处理完要**重新执行**当前指令，不是执行下一条。
- 修改位 D=0 的牺牲页**无需写回**（直接覆盖），D=1 才需一次磁盘写；改进型 Clock 优先选 (A=0, D=0) 正是为省这次 I/O。
- 缺页率随物理块增加**并非严格单调下降**（FIFO 有 Belady 异常）；但 LRU/OPT 单调不增。
- 「预调页」用于进程首次装入（依据局部性一次调入一批），「请求调页」是运行期按需调入；预测不准的预调页反而浪费 I/O。
:::

## 第 7 章 输入/输出系统

### 7.1 I/O 系统的层次与接口（★★★）

| 层次（自顶向下） | 主要职责 |
| --- | --- |
| 用户层 I/O 软件 | 库函数（`printf`/`fread`）、SPOOLing 系统、格式化与假脱机 |
| **与设备无关的 I/O 软件** | 设备命名与映射、设备保护、统一缓冲、错误报告、分配与回收、提供统一接口 |
| **设备驱动程序** | 把抽象请求翻译成具体控制器命令、检查状态、处理中断、启动 I/O |
| **中断处理程序** | 响应中断、保存/恢复现场、唤醒被阻塞的驱动进程 |
| 硬件 | 设备控制器（寄存器 + 数据缓冲）、设备本身 |

四层接口：用户与 OS 之间的接口（系统调用/库函数）、OS 与驱动之间的接口、驱动与控制器之间的接口、软件/硬件接口。

| 设备分类 | 依据 | 例子 |
| --- | --- | --- |
| 存储/输入输出设备 | 用途 | 磁盘、键盘、显示器、打印机 |
| **块设备 / 字符设备** | 信息交换单位 | 磁盘（可寻址、按块）/ 键盘、打印机（不可寻址、字符流） |
| 独占 / 共享 / 虚拟设备 | 分配方式 | 打印机 / 磁盘 / SPOOLing 后的"虚拟打印机" |
| 低速/中速/高速 | 传输速率 | 键盘 / 打印机 / 磁盘、网卡 |

设备控制器功能：接收并识别命令、数据交换、标识与报告设备状态、地址识别、数据缓冲、差错控制。**内存映像 I/O** 把控制器寄存器映射到内存地址空间，可用普通访存指令访问；另一类是专用 **I/O 端口 + 专用 I/O 指令**（x86 的 `in`/`out`）。

### 7.2 四种 I/O 控制方式（★★★）

| 方式 | 数据搬运者 | CPU 干预粒度 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| 程序轮询（忙等） | CPU | 每个字/字节 | 简单 | CPU 全程被占，效率极低 |
| **中断驱动** | CPU | 每个字/字节一次中断 | CPU 可与设备并行工作 | 每字节一次中断，高速设备会"中断淹没" |
| **DMA** | **DMA 控制器** | 每**一批**（块）一次中断 | CPU 只做初始化与收尾；适合高速块设备 | 需 DMA 控制器与总线仲裁；占用总线（周期窃取） |
| **I/O 通道（通道处理机）** | 专用处理器 | 每**一组**块（一次执行通道程序） | 进一步解放 CPU，可管理多台设备 | 硬件成本高，现代已被智能控制器/NVMe 队列吸收 |

DMA 控制器寄存器：`MAR`（内存地址）、`DC`（传送计数）、`CR`（命令/方向）、`DR`（数据缓冲）。流程：CPU 写 MAR/DC/CR 启动 → DMA 控制器逐字搬运（**周期窃取**总线周期）→ DC 减到 0 → 发中断通知 CPU。

::: tip 工作示例 · 中断方式 vs DMA 的 CPU 开销
设备需传输 1000 B；每次中断处理（保存现场、分派、恢复）耗时 100 μs。

- **中断驱动**：每字节中断一次 → `1000 × 100 μs = 100 000 μs = 100 ms` 全耗在 CPU 上。
- **DMA**：CPU 初始化 100 μs + 整块传完一次中断 100 μs → 合计 **200 μs**，其余时间 CPU 可运行其它进程。

相差 500 倍——这就是"高速块设备必须用 DMA"的定量理由。对 1 Gb/s 以上网卡，连每包一次中断都太多，还需 **NAPI/中断合并（interrupt coalescing）** 或轮询。
:::

![I/O 层次与四种控制方式](/os/os-io.svg)

::: danger 易错 · 中断与 DMA
- DMA 传送**数据本身不经过 CPU 寄存器**，但 CPU 仍要负责**启动**和**收尾**（中断）。
- DMA 与 CPU 争用总线时用「周期窃取」，CPU 会被短暂暂停，但**不是**被中断（无现场切换）。
- 「通道」是能执行**通道程序**的专用处理机，比 DMA 高一级；一台通道可管多台同类设备。现代系统里多由设备内嵌控制器 + 多队列实现（NVMe 最多 64K 队列、每队列 64K 命令）。
:::

### 7.3 中断处理与设备驱动（★★）

中断处理流程：设备发中断请求 → CPU 在**指令执行完**时检测 → 关中断、保存断点与现场 → 查**中断向量表**转入处理程序 → 处理（读状态、取数据、唤醒等待进程）→ 恢复现场、开中断 → 返回。

Linux 把中断处理分为**上半部（top half，硬中断，关中断、极短，只做登记）**与**下半部（bottom half：softirq / tasklet / 工作队列 / 线程化中断）**，避免长时间关中断丢失其它中断。

设备分配的四级数据结构：**SDT 系统设备表 → DCT 设备控制表 → COCT 控制器控制表 → CHCT 通道控制表**；分配顺序「先设备、再控制器、后通道」，任一失败都要**回溯释放**。设备独立性靠「逻辑设备名 → 物理设备名」映射表（LUT）实现，好处是设备增减/替换时用户程序不改、并便于重定向与共享。

### 7.4 SPOOLing 与缓冲区管理（★★★）

**SPOOLing（假脱机）**：用**磁盘上的输入井/输出井 + 内存中的输入/输出缓冲区 + 输入/输出进程 + 井管理程序**，把一台**独占设备**改造成可共享的**虚拟设备**。

::: tip 工作示例 · 共享打印机
三个用户进程同时"打印"：各自的输出数据并不是直接送打印机，而是由输出进程写到**输出井**中的独立文件，并登记到打印请求队列；输出进程再按队列**依次**把井中文件送到打印机。用户看到的是"立刻打印完成、各自有一台打印机"，实际物理打印机仍串行工作。这体现了**用磁盘做缓冲 + 排队**把独占设备虚拟化的思想（也是"虚拟性"的典型例子）。
:::

| 缓冲技术 | 每块处理时间（T：设备→缓冲区，M：缓冲区→用户区，C：CPU 处理） |
| --- | --- |
| 无缓冲 | `T + C`（设备与 CPU 完全串行） |
| 单缓冲 | `max(C, T) + M` |
| 双缓冲 | `max(C + M, T)`（设备与 CPU 可**并行**） |
| 环形缓冲区 / 缓冲池 | 多缓冲组成循环队列，用 `Getbuf/Putbuf` 与 `EM/IN/OUT` 队列管理，削峰填谷 |

代入 `T = 100 μs, M = 50 μs, C = 50 μs`：单缓冲 `= max(50,100)+50 = 150 μs/块`；双缓冲 `= max(100,100) = 100 μs/块` → **提速 1.5 倍**。

::: danger 易错 · 缓冲 vs 缓存
- **缓冲区（buffer）**主要解决「生产/消费速度不匹配」与「粒度不匹配」，数据一般**只经过一次**；**缓存（cache）**解决「慢设备重复访问」，靠局部性保留副本可反复命中。
- 单缓冲下「CPU 处理」与「设备输入」能并行，但「缓冲区→用户区 M」必须串行；双缓冲才能让两者完全重叠。
- **SPOOLing 必须以磁盘为井**，它是设备虚拟化，不是简单的缓冲；且 SPOOLing 提高了设备利用率，却**不缩短单个作业的响应时间**。
:::

### 7.5 磁盘性能与调度算法（★★★）

一次磁盘读写的总时间：

```text
Ta = Ts(寻道) + Tτ(平均旋转延迟) + Tt(传输) + 控制器/排队开销
Tτ = 1/(2 × 转速)         Tt = 传输字节数 / 传输速率
```

::: tip 工作示例 · 单次磁盘访问时间
7200 rpm 磁盘：`Tτ = 60 s / 7200 / 2 ≈ 4.17 ms`；平均寻道 `Ts = 8 ms`；传输速率 200 MB/s，读 4 KB 需 `4 KB / 200 MB/s ≈ 0.02 ms`。
`Ta ≈ 8 + 4.17 + 0.02 = 12.19 ms`，其中**机械定位占 99.8%**。这解释了三点：① 顺序 I/O 远快于随机 I/O；② 预读与合并请求价值巨大；③ SSD 无机械定位后随机读性能提升 2~3 个数量级。
:::

| 调度算法 | 规则 | 优点 | 缺点 |
| --- | --- | --- | --- |
| FCFS | 按请求到达顺序 | 公平、简单 | 磁头来回大幅移动，性能最差 |
| **SSTF 最短寻道优先** | 选距当前磁头最近的请求 | 明显减少寻道 | 可能"粘着"在局部磁道，远端请求**饥饿** |
| **SCAN 电梯算法** | 沿一个方向扫到底（通常到端点），途中服务，再反向 | 无饥饿、性能较稳 | 刚扫过的区要等一整趟；到端点的空走常属浪费 |
| **CSCAN 循环扫描** | 只在一个方向服务，到端点后**快速返回起点**再同向服务 | 等待时间更均匀 | 回程虽不计寻道但仍耗时 |
| LOOK / C-LOOK | SCAN/CSCAN 但只走到**最远的请求**即折返（不到物理端点） | 消除空走，实际系统常用 | — |
| N-step-SCAN / FSCAN | 把请求队列分段，防"磁臂粘着" | 兼顾公平 | 实现稍复杂 |

::: tip 工作示例 · 五种算法完整寻道计算
磁盘 0–199 磁道，磁头当前在 **100**，请求队列（按到达序）：`55, 58, 39, 18, 90, 160, 150, 38, 184`，均向磁道号**增大**方向初始移动。

| 算法 | 服务序列 | 总移动磁道数 | 平均寻道 |
| --- | --- | --- | --- |
| **FCFS** | 100→55→58→39→18→90→160→150→38→184 | **498** | 55.33 |
| **SSTF** | 100→90→58→55→39→38→18→150→160→184 | **248** | 27.56 |
| **SCAN**（到 199 后折返） | 100→150→160→184→199→90→58→55→39→38→18 | **280** | 31.11 |
| **C-SCAN**（到 199 后回 0，回程不计） | 100→150→160→184→199→(0)→18→38→39→55→58→90 | **189** | 21.00 |

FCFS 逐段：`45+3+19+21+72+70+10+112+146 = 498`。
SSTF 逐段：`10+32+3+16+1+20+132+10+24 = 248`（在 18 处跳到最近的 150）。
**注意**：SCAN/CSCAN 的"到端点"是否计入总距离，各教材约定不同；若题目要求 LOOK（只到最远请求 184），则 SCAN 变为 `100→150→160→184→90→58→55→39→38→18`，总 `50+10+24+94+32+3+16+1+20 = 250`。答题时**先写清假设**再算。
:::

![磁盘结构与调度算法](/os/os-disk.svg)

::: tip 现代 I/O 栈
- **NVMe / PCIe SSD**：无机械寻道，传统 SSTF/SCAN 意义大幅下降，改由设备内部 **FTL + 多队列 + NCQ/TCQ** 做并行与重排；调度重点转为**公平性、延迟隔离与读写混合**（如 Linux `mq-deadline`、`BFQ`、`kyber`、`none`）。
- **io_uring**：通过用户态与内核共享的**提交/完成环形队列**实现异步 I/O，可批量提交、零拷贝（`O_DIRECT` + 固定缓冲）、可选轮询模式，大幅降低系统调用与中断开销；是 `aio`/`epoll + 线程池` 的现代替代。
- **MSI-X**：把中断向量直接投递到指定 CPU 核，配合 **RSS/RPS** 做网络多队列与 NUMA 亲和；**DMA-BUF / VFIO / SR-IOV** 支持零拷贝与设备直通（第 11 章）。
- 注意：I/O 通道与 SPOOLing 属于大型机/早期共享设备时代的核心内容，仍须作为原理掌握；但现代通用 OS 中「通道」已被智能控制器取代，磁盘调度也以 SSD 为主，需明确其**历史定位**。
:::

## 第 8 章 文件管理

### 8.1 文件、逻辑结构与目录（★★★）

文件＝**具有文件名的一组相关元素的集合**，是用户进行 I/O 的基本单位；数据项 → 记录 → 文件（三级）。文件属性：名称、标识符、类型、位置、大小、保护、时间与使用计数。

| 逻辑结构 | 特点 | 访问方式 |
| --- | --- | --- |
| 顺序文件（连续/串/顺序结构） | 记录按序排列；定长记录可**随机访问**（第 i 条地址 = 首址 + i×L） | 顺序/随机 |
| 索引文件 | 为变长记录建索引表（记录号 → 指针） | 随机，速度快但多占索引空间 |
| 索引顺序文件 | 先分组、组间索引、组内顺序 | 折中：先查索引定位组，再顺序查（两级） |
| 直接文件 / 哈希文件 | 键值经哈希函数直接得盘块地址 | 随机最快，需处理冲突、不适合范围查询 |

::: tip 工作示例 · 定长记录寻址
某顺序文件有定长记录 `L = 128 B`，记录在盘块 `1 KB` 内不跨块存放，首记录在 100 号盘块：
每块可放 `1024/128 = 8` 条记录；第 35 条记录（从 1 起）所在盘块 `= 100 + (35−1)/8 = 100 + 4 = 104`，块内序号 `= (35−1) mod 8 = 2`（第 3 条）。若允许记录跨块，则要用「字节偏移 = (35−1)×128 = 4352 B」，第 `4352/1024 = 4` 块（余 256 B）——**「可否跨块」会改变寻址公式**，读题务必看清。
:::

### 8.2 文件目录、FCB 与 inode（★★★）

| 目录结构 | 特点 |
| --- | --- |
| 单级 | 只允许一层，不允许重名，查找慢；不适多用户 |
| 两级 | 主文件目录 MFD + 用户文件目录 UFD，解决重名与共享隔离 |
| **树形（多级）** | 当前目录、相对/绝对路径、`..`；最常用，但不便共享 |
| 无环图目录 | 允许一个文件出现在多个目录中（共享），须用**链接计数**防止悬空 |

**FCB（文件控制块）** 含：文件名、文件号、物理位置、长度、属性、时间戳、共享/使用计数等。目录文件＝FCB 的有序集合。
**索引节点 inode**：把「文件名」与「文件描述信息」分离——目录项只保留 `文件名 + inode 编号`，其余元数据放进 inode。好处是**目录项变小、检索时读的盘块大幅减少**，且便于硬链接共享（多个目录项可指向同一 inode）。

::: tip 工作示例 · inode 分离为何能加速目录检索
目录中有 128 个文件，盘块 1 KB：

| 方案 | 目录项大小 | 每块可放 | 目录占块数 | 顺序查找平均读盘块 |
| --- | --- | --- | --- | --- |
| 完整 FCB 放目录 | 64 B | `1024/64 = 16` 项 | 8 块 | `(8+1)/2 = 4.5` 块 |
| 分离 inode（文件名 16 B + inode 号 2 B） | 18 B | `1024/18 = 56` 项 | 3 块 | `(3+1)/2 = 2` 块（约 1.5~2） |

减少的是**查目录时的磁盘 I/O 次数**；定位到 inode 后仍需一次读 inode 才能拿到盘块地址。这也解释了为什么「按名查找」在有目录缓存（dentry cache）后几乎不再读盘。
:::

| 文件共享方式 | 硬链接 | 符号链接（软链接） |
| --- | --- | --- |
| 本质 | 新增一个**目录项指向同一 inode**，链接计数 +1 | 新建一个独立文件，内容是目标文件的**路径字符串** |
| 删除原文件 | 只要链接计数 > 0，文件仍在 | 链接变成**悬空指针（dangling）** |
| 跨文件系统 / 链接目录 | 不可以（inode 号只在本文件系统内有效）／一般不允许 | 可以／可以 |
| 权限与大小 | 与原文件完全一致（同一对象） | 链接文件自身有独立 inode 与权限 |
| 查找开销 | 直接定位 inode | 需再解析一次路径，可能多级 |

### 8.3 文件保护与文件系统实现（★★）

- **保护域**：`<对象, 权限>` 集合；**访问矩阵**中行＝域、列＝对象、元素＝允许的操作集合。
- 矩阵稀疏 → 两种实现：**访问控制表 ACL**（按列存，每个对象挂一张"谁能对我做什么"，Unix 9 位权限 `rwxr-xr--` 与 POSIX ACL 属此类）、**能力表 capability**（按行存，每个进程持有一张"我能对谁做什么"，更便于传递但难以撤销）。
- 文件系统实现层次：磁盘分区 → 每区建文件系统（超级块、空闲块管理、inode 区、数据区）→ **挂载（mount）** 把该文件系统挂到目录树的某个挂载点；挂载信息表记录每个安装卷。
- **VFS 虚拟文件系统**四大对象：超级块对象（superblock）、索引节点对象（inode）、目录项对象（dentry）、文件对象（file）；它把"上层统一系统调用"与"下层具体文件系统"解耦，使 ext4、XFS、NFS、procfs 可共存。

![目录、inode 与索引分配](/os/os-file.svg)

::: tip 现代文件系统
- **ext4**：在 ext2/ext3 基础上加**日志（journal）**、区段（extent）、多块分配、延迟分配、更快 fsck；**XFS/btrfs/ZFS** 提供 COW、快照、校验和与在线扩容；**NTFS/APFS** 分别是 Windows/macOS 主流。
- **日志与崩溃一致性**：先写日志再落盘，崩溃后按日志重做/撤销；`fsync` 才保证数据真正落盘（`write` 返回成功通常只表示进了页缓存）。COW 文件系统用「写新块 + 原子改指针」避免日志双写。
- **文件系统一致性检查**：`fsck` 检查块计数、inode 链接计数、目录项与 inode 对应；日志文件系统可大幅缩短恢复时间。
- **稀疏文件、硬链接与 reflink**：稀疏文件只为实数**据**分配块（空洞读回 0）；reflink/COW 克隆可做到「秒级复制大文件」。
- **FUSE / 用户态文件系统**、**网络文件系统 NFS/SMB**、**分布式文件系统**进一步把 VFS 的下层实现扩展到网络与用户态。
:::

## 第 9 章 磁盘存储器管理

### 9.1 外存组织方式（★★★）

| 组织方式 | 优点 | 缺点 |
| --- | --- | --- |
| **连续组织** | 顺序访问最快、支持直接访问、目录项只需首块号+长度 | 产生**外部碎片**、须预知文件大小、不便插入删除/增长 |
| **链接组织**（隐式/显式 FAT） | 无碎片、便于动态增长 | 只能顺序访问、指针占空间、一个指针损坏会断链；FAT 需整表常驻内存 |
| **索引组织** | 支持**直接访问**、无外部碎片、便于增长 | 索引块本身占空间；小文件也要一个索引块 |

**混合索引（UNIX inode 式）**：直接地址 10 项 + 一级间接 + 二级间接 + 三级间接，兼顾小文件（直接命中、零额外 I/O）与大文件。

::: tip 工作示例 · 索引分配最大文件长度
盘块 `1 KB`，盘块号占 `4 B` → 一个索引块可存 `1024/4 = 256` 个盘块号。

```text
直接地址（10 项）          : 10 × 1 KB = 10 KB
一级间接                  : 256 × 1 KB = 256 KB
二级间接                  : 256² × 1 KB = 65 536 KB = 64 MB
三级间接                  : 256³ × 1 KB = 16 777 216 KB = 16 GB
混合索引总计               : (10 + 256 + 65 536 + 16 777 216) × 1 KB ≈ 16 GB
```
同理：访问「二级间接中的某块」需 `1(读二级索引) + 1(读一级索引) + 1(读数据) = 3` 次磁盘 I/O；直接地址只需 1 次。**小文件走直接地址**正是性能关键。注意文件最大长度还受**盘块号位数**限制（如 32 位块号 × 1 KB = 4 TB 上限）。
:::

::: tip 工作示例 · FAT 表大小与访问开销
磁盘 `1 GB`、盘块 `4 KB`、盘块号 `4 B`：
```text
盘块总数 = 1 GB / 4 KB = 2^18 = 262 144
FAT 表大小 = 2^18 × 4 B = 1 MB
```
FAT **每个盘块对应一个表项**（记录该块所在链的下一块号，末块为结束标志）。FAT 常驻内存时，查链不需读盘，但**文件数据块仍是隐式链接的物理离散块**，随机访问要沿链逐块推算；若 FAT 不驻内存，则每查一次链就多一次读盘。这与索引分配的「一次读索引块即得全部块号」形成对比，是三种组织方式取舍的关键。
:::

### 9.2 文件存储空间管理（★★★）

| 方法 | 思想 | 适用 |
| --- | --- | --- |
| 空闲区表法 / 空闲链表法 | 记录每个连续空闲区的始址与长度；或把空闲块/空闲区链成链 | 连续分配；小文件系统 |
| **位示图法** | 用 1 个二进制位表示 1 个盘块（0 空闲 / 1 已分配，或反之） | 任意分配方式；空间开销小、易找连续块 |
| **成组链接法** | 把空闲块按固定数量分组，每组第一块存下一组的块号与数量；栈式管理 | 大型文件系统（Unix 经典），兼有链表与表法的优点 |

::: tip 工作示例 · 位示图容量与行列换算
磁盘 1 GB、盘块 1 KB → 盘块总数 `= 2^20 = 1 048 576` 块，位示图需 `2^20 位 = 131 072 B = 128 KB`（正好 128 个盘块）。

设位示图每行 `n = 16` 位、字号 `i` 与位号 `j` 均**从 0 起**：

```text
盘块号 b = n × i + j        反算  i = b / n (整除),  j = b mod n
例：b = 1025  →  i = 64, j = 1；   b = 3000 → i = 187, j = 8
```
若题目约定**从 1 起编号**（字号、位号、盘块号均从 1 开始），公式改为 `b = n(i−1) + j`，反算 `i = (b−1)/n + 1`、`j = (b−1) mod n + 1`。**答题前先确认编号约定**，这是最常见的计算失分点。
:::

![外存组织、位示图与 RAID](/os/os-storage.svg)

### 9.3 提高磁盘 I/O 速度与可靠性（★★）

| 途径 | 机制 |
| --- | --- |
| 磁盘高速缓存 | 在内存保留最近访问的盘块，命中则不读盘；与页缓存常合一 |
| 预读 / 延迟写 / 合并 | 顺序访问时提前读后续块；写先入缓存批量回写；把相邻请求合并成一次 I/O |
| 优化物理布局 | 把文件的数据块与其 inode 放在邻近柱面，减少寻道 |
| RAID | 并行 + 冗余，见下表 |
| 容错 | SFT-I（双份目录/双份文件分配表 + 热修复重定向）、SFT-II（磁盘镜像/双工）、SFT-III（集群/双机热备）、后备系统（全量/增量/差异备份） |

| RAID 级别 | 冗余方式 | 最少盘数 | 有效容量利用率 | 可容忍坏盘 |
| --- | --- | --- | --- | --- |
| RAID 0 | 条带化，**无冗余** | 2 | 100% | 0 |
| RAID 1 | 镜像 | 2 | 50% | 1（每对镜像最多 1） |
| RAID 2 / 3 / 4 | 海明校验 / 位级奇偶 / 块级专用校验盘 | 3 | (N−1)/N | 1（RAID2 可纠错） |
| **RAID 5** | 块级条带 + **校验分布式**轮流存放 | 3 | (N−1)/N | 1 |
| **RAID 6** | 双份校验（P+Q） | 4 | (N−2)/N | 2 |
| **RAID 10** | 先镜像再条带 | 4 | 50% | 每对 1 |

例：8 块 1 TB 盘 → RAID 0 = 8 TB；RAID 5 = **7 TB**；RAID 6 = 6 TB；RAID 10 = **4 TB**。RAID **不能替代备份**（误删、勒索、控制器故障仍会丢数据）。

### 9.4 数据一致性与存储新技术（★★）

- **事务**：访问并修改多个数据项的一个不可分割单位，具 **ACID**（原子性、一致性、隔离性、持久性）；事务记录写入**稳定存储器**。
- **检查点**：周期性把已提交事务的结果固化并记录检查点，恢复时只需重放检查点之后的事务，避免扫描整个日志。
- **并发控制**：锁 / 时间戳 / 两阶段锁协议（2PL），保证事务可串行化。
- **重复数据一致性**：同一数据存多份时，须保证所有副本同步更新（可用「回写所有副本 + 版本号/配额」或主副本复制）。
- **SSD**：以闪存页（读/写单位）与块（擦除单位）组织，**FTL 闪存转换层**做逻辑→物理地址映射；需要**磨损均衡**、垃圾回收、坏块管理；**写前擦除**导致写入放大，`TRIM` 让主机通知哪些块已无效以减轻 GC。这些是固态硬盘的工程重点。
- **新型存储**：NVM/持久内存（PMEM，可按字节寻址、`DAX` 绕过页缓存）、分布式/对象存储、纠删码（比多副本更省空间）、云盘与分层存储。

::: danger 易错 · 磁盘管理高频错
- 链接组织（隐式链接）**不能随机访问**；显式链接（FAT）虽可随机，但 FAT 须常驻内存，否则多次读盘。
- 索引分配的「最大文件长度」计算里，间接级数增加的是**乘法**（256 倍/级），不是加法。
- 位示图从 0/从 1 编号的公式不同；且分配后要把对应位改 1、回收改 0。
- RAID 5 的校验**分布**在各盘（避免 RAID 4 的校验盘瓶颈）；RAID 0 没有任何容错，一块坏全盘数据丢失。
- 事务的持久性靠**稳定存储 + 日志**，不是靠"写在内存里"；`fsync` 与检查点是两个不同层次的概念。
:::

## 第 10 章 多处理机操作系统

### 10.1 多处理机系统结构（★★）

| 分类维度 | 类型 | 特点 |
| --- | --- | --- |
| 耦合度 | **紧密耦合**（共享主存，总线/交叉开关互连）／松散耦合（各自主存，经通信线路/通道互连，实为分布式） | 前者由单一 OS 统一管理 |
| 处理器地位 | **对称多处理 SMP**（各处理器平等、共享同一 OS 副本）／非对称 ASMP（主从式，主处理器跑 OS） | SMP 是现代多核主流 |
| 存储访问 | **UMA 统一内存访问**（各核访存时间相同，集中式共享内存）／**NUMA 非一致内存访问**（内存物理上分布、逻辑上连续，访问本地节点快、远端慢） | 多核服务器必做 NUMA 亲和 |

::: tip 缓存一致性
SMP 中每个核有私有 Cache，同一内存块可能有多份副本，必须用 **MESI / MOESI 等缓存一致性协议** 通过总线侦听（snooping）或目录协议维护一致。由此产生**伪共享（false sharing）**：两个核频繁写同一 Cache 行中的不同变量，导致该行在核间反复失效，性能骤降——工程上用「缓存行填充 / 对齐」规避。这是多核编程最常见的性能陷阱。
:::

### 10.2 多处理机同步机制（★★★）

| 机制 | 要点 |
| --- | --- |
| 集中式 / 分布式同步 | 前者由一个中心管理者（单点瓶颈），后者各节点协作 |
| **自旋锁 spinlock** | 加锁失败时**忙等**（反复测试锁变量），适用于持锁时间**短于**两次上下文切换开销的场景；单 CPU 上自旋毫无意义（持锁者无法运行） |
| 二进制指数补偿算法 | 抢锁失败后按 `2^k` 递增退避，减少总线争用 |
| 待锁 CPU 等待队列 | 记录等待者，释放锁时直接唤醒，避免"一窝蜂"抢锁 |
| 定序机构 / 逻辑时钟 | 为分布式事件定全序（Lamport 时间戳、向量时钟） |
| **面包房算法** | 用「取号 + 号码比较」实现 N 个进程互斥，无需硬件原子指令，满足 FIFO 公平 |
| **令牌环算法** | 令牌在逻辑环中轮转，持令牌者才能进临界区，天然互斥与公平 |
| **RCU 读-复制-更新** | 读者**不加锁、几乎零开销**；写者先复制一份副本 → 修改副本 → 原子替换指针 → 等待所有"宽限期"内的旧读者退出后释放旧副本 |

::: tip RCU 为什么快
适用场景：**读多写少**（路由表、内核对象查找）。读者只需在"读侧临界区"内禁止抢占（甚至可完全无原子操作），写者承担复制与延迟回收的代价。它把同步成本从"每个读者一次原子加解锁"转移到"每个写者一次复制 + 一次等待"，因此读者扩展性接近线性。理解 RCU 的关键在于**宽限期（grace period）**与回调回收流程：写者替换指针后注册回调，内核检测到所有 CPU 都经历了一次静止状态（quiescent state）后才执行回调释放旧副本。
:::

### 10.3 多处理机调度与死锁（★★）

| 主题 | 内容 |
| --- | --- |
| 性能评价因素 | 加速比、CPU 利用率、负载均衡、迁移开销、缓存/内存亲和性、任务间通信量 |
| 进程分配方式 | 静态分配（每个 CPU 固定一组进程，简单但易失衡）／动态分配（自调度，可迁移） |
| **自调度** | 全局就绪队列，空闲 CPU 自行取任务；易实现、自动均衡，但**破坏亲和性**且共享队列本身是竞争热点 |
| **成组调度 gang scheduling** | 把一个并行作业的多个线程**同时**分派到多个 CPU，避免"线程互相等待对方被调度" |
| 专用处理机分配 | 并行作业运行期独占一组 CPU，减少切换，但利用率低 |
| 死锁分类 | 资源死锁 / 通信死锁（互相等待消息）；分布式死锁检测用等待图或超时 |

**Amdahl 定律**（衡量并行加速上限）：`S = 1 / ((1 − f) + f/N)`，其中 `f` 为可并行部分比例、`N` 为处理器数。即使 `N → ∞`，`S ≤ 1/(1−f)`：若串行部分占 10%，最大加速比仅 10 倍。

## 第 11 章 虚拟化和云计算

### 11.1 虚拟化基础与 VMM（★★★）

**虚拟化必要条件**（Popek-Goldberg 定理）：① 程序在虚拟机上的运行结果与在裸机上**一致**（除时序/资源差异）；② 敏感指令与特权指令必须能被 VMM **陷入并模拟**（"陷入-模拟"）；③ 绝大多数指令可**直接在硬件上执行**（否则性能不可接受）。

| VMM 架构 | 位置 | 代表 | 特点 |
| --- | --- | --- | --- |
| **裸金属型（Type 1）** | 直接跑在硬件上 | VMware ESXi、Xen、KVM（内核模块形态）、Hyper-V | 性能好、用于数据中心 |
| **宿主机型（Type 2）** | 跑在宿主 OS 之上 | VMware Workstation、VirtualBox | 便于桌面开发，性能与隔离稍弱 |

| 虚拟化维度 | 经典做法 | 现代硬件辅助 |
| --- | --- | --- |
| CPU | 全虚拟化（二进制翻译处理不可陷入的敏感指令）／半虚拟化（客户机主动 `hypercall`） | **Intel VT-x / AMD-V**：引入根/非根模式与 VMCS，敏感指令自动陷入；VM-entry/exit |
| 内存 | **影子页表**（VMM 维护 GVA→HPA 映射，每次客户机改页表都要陷出，开销大） | **EPT / NPT（二级地址翻译）**：硬件自动完成 GVA→GPA→HPA 两级转换；配合大页降低 TLB 开销 |
| I/O | 全模拟（QEMU 设备模型，每次 I/O 多次陷入）／半虚拟 **virtio**（前后端共享环形队列） | **SR-IOV / 设备直通 / IOMMU**：把物理设备虚拟成多个 VF 直接分配给客户机，接近原生性能 |
| 多核虚拟化 | vCPU 调度、超分（overcommit）、CPU 亲和与 NUMA 绑定 | 中断投递优化、posted interrupt |

内存虚拟化还需 **ballooning**（客户机内驱动"充气"回收页交还宿主机）、**KSM 同页合并**（把内容相同的页共享为一份 COW 页）。

### 11.2 云计算与虚拟机迁移（★★）

云计算定义特征（NIST）：按需自助服务、广泛网络接入、资源池化、快速弹性、可计量服务。服务模型 **IaaS / PaaS / SaaS**（再加 FaaS/Serverless）；部署模型公有云 / 私有云 / 混合云 / 社区云。

**虚拟机迁移**（尤其**预拷贝 live migration**）：① 先整体拷贝内存页到目标主机；② 记录期间被修改的脏页，**迭代**增量拷贝（每轮脏页越来越少）；③ 当剩余脏页足够少时**短暂暂停**源 VM，拷贝最后一轮并切换；④ 目标机接管，通过 ARP 广播/网络重定向把流量引过去，源机释放。停机时间通常几十~几百毫秒，对上层服务近似无感。

### 11.3 轻量级虚拟化与容器（★★★）

**关键对比**：容器**不模拟硬件、不跑独立内核**，而是共享宿主内核，靠**内核机制做隔离**，因此启动快（毫秒级）、内存与 I/O 开销小、密度高；代价是**隔离性弱于 VM**、内核版本必须与宿主兼容、所有容器共享同一内核（内核漏洞可越界）。

| 机制 | 作用 |
| --- | --- |
| **namespace** | 隔离视图：`pid / net / mnt / uts / ipc / user / cgroup / time` 等 |
| **cgroup** | 限额与统计：`cpu / memory / blkio / pids / devices` 等（v2 为统一层级） |
| **UnionFS / 分层镜像** | 镜像分层只读 + 容器可写层（overlay2），实现秒级分发与复用 |
| **capabilities / seccomp / AppArmor-SELinux** | 收窄 root 权力、限制系统调用、强制访问控制，弥补共享内核的隔离弱点 |

![虚拟化架构与容器对比](/os/os-virtual.svg)

::: tip 容器时代的新形态
- **编排**：Kubernetes 负责调度、服务发现、滚动升级、自愈与 horizontal autoscaling；Pod 是最小调度单位。
- **Serverless / FaaS**：平台按需拉起函数实例（常基于轻量虚拟机 microVM 或 gVisor 用户态内核），把资源管理进一步从用户侧移走。
- **机密计算 / TEE**：AMD SEV-SNP、Intel TDX、ARM CCA 让**连 hypervisor 也无法读取**客户机内存，弥补云上多租户信任问题。
- **unikernel / WASM**：把应用与极简内核编译成单一镜像，或把 WASM 沙箱作为跨平台的轻量"进程"，进一步压缩启动与隔离开销。
:::

## 第 12 章 保护和安全

### 12.1 安全环境与加密基础（★★）

| 概念 | 内容 |
| --- | --- |
| 安全目标 | 数据**机密性**、**完整性**、**可用性**（CIA），加上可审计性/不可抵赖 |
| 系统安全特征 | 多面性（多层防护）、动态性（威胁演变）、层次性、适度性（安全与可用/成本权衡） |
| 对称加密 | 加解密同密钥，速度快，适合大数据；代表 AES、SM4（早期 DES 已不安全） |
| 非对称加密 | 公钥加密/私钥解密 或 私钥签名/公钥验签；速度慢，用于密钥交换与签名；代表 RSA、ECC、SM2 |
| **数字签名** | 对消息摘要用**私钥**加密，接收方用公钥验证 → 认证身份 + 完整性 + 不可抵赖 |
| **数字证书 / PKI** | CA 用私钥对「用户身份 + 公钥」签名，把公钥与身份绑定；验证时走**证书链**直至受信任根 CA |

::: danger 易错 · 术语与方向
- 「数字证明书」即现代通用术语的**数字证书**（X.509），二者指同一事物。
- **加密**用接收方**公钥**（只有接收方能解）；**签名**用发送方**私钥**（任何人可验证）。方向别反。
- 「散列函数」（MD5/SHA-1 已不抗碰撞，应用 SHA-256/SM3）提供完整性，**不是加密**；HMAC = 散列 + 密钥，才提供认证。
:::

### 12.2 用户验证、攻击与可信系统（★★）

| 验证方式 | 要点 |
| --- | --- |
| 口令 | 最常用；必须**加盐（salt）+ 慢哈希**（bcrypt/Argon2）存储，禁止明文或裸 MD5；配合口令策略与限次锁定 |
| 物理标志 | IC 卡、U 盾、硬件令牌（"你所拥有的"） |
| 生物识别 | 指纹/人脸/虹膜（"你本身的特征"），不可撤销、须防重放与活体伪造 |
| 多因素 MFA | 组合以上两类以上，显著提升安全性 |

| 攻击类型 | 说明 |
| --- | --- |
| 逻辑炸弹 / 陷阱门（后门） | 满足特定条件才触发的恶意代码／绕过正常认证的隐藏入口 |
| 特洛伊木马 / 登录欺骗 | 伪装成正常程序／伪造登录界面骗取口令 |
| **缓冲区溢出** | 越界写覆盖栈上的返回地址或函数指针，劫持控制流；经典防御见下 |
| 病毒 / 蠕虫 / 移动代码 | 病毒依附宿主程序、需人触发；蠕虫可独立自我传播；移动代码来自网络（脚本、Applet、宏） |
| 拒绝服务 / 侧信道 / 供应链 | 耗尽资源／通过时序、功耗、缓存推断密钥／在构建或分发环节植入恶意代码 |

**可信系统**：访问矩阵模型（控制"谁能访问什么"）与信息流控制模型（控制"信息能流向哪里"，如 Bell-LaPadula 防泄密、Biba 防篡改）；**可信计算基 TCB** ＝ 系统中**所有**为保障安全所依赖的硬件、固件、软件集合，必须尽量小、可验证。安全设计原则：最小特权、机制与策略分离、 Economy of mechanism（机制简洁）、完全中介（每次访问都检查）、Fail-safe defaults（默认拒绝）、开放设计、最小共享、易用性。

![系统攻击与现代防御对照](/os/os-security.svg)

::: tip 现代系统安全机制（工程与面试高频）
- **缓冲区溢出缓解**：栈保护者 Canary、**DEP/NX**（数据页不可执行）、**ASLR**（地址空间随机化）、**CFI/影子栈**、RELRO、FORTIFY；共同目标是让"注入 shellcode + 跳转到它"失效。
- **内核隔离**：用户/内核页表分离 **KPTI**（缓解 Meltdown）、**Spectre 类推测执行侧信道**需 retpoline/IBRS/屏障与硬件修复；这两个 2018 年的漏洞直接改变了 OS 的地址空间设计。
- **最小权限落地**：`capabilities` 拆分 root 权力、`seccomp-bpf` 白名单系统调用、沙箱（浏览器渲染进程、容器）、强制访问控制 SELinux/AppArmor、**Landlock**。
- **可信启动链**：Secure Boot → 度量启动（TPM PCR）→ 远程证明；配合全盘加密（LUKS/FileVault）与密钥托管。
- 注意：「缓冲区溢出」有时被归入"来自系统内部的攻击"，有时又被视为外部攻击——准确说法是**它属于程序漏洞（可被本地或远程利用）**，与"内部/外部"的划分维度不同，不宜混在同一分类下；现代分类按「漏洞类型 / 攻击面 / 攻击者能力」三个维度展开。

## 综合例题精讲（跨章）

> 这一组题目把多章知识点串在一起，按「读题 → 列条件 → 完整演算 → 结论」展开，适合考研综合应用题与面试手撕。所有数值均已逐步核算。

### 综 1 · 三级流水线 PV 综合（第 2、4 章）

**题**：系统有输入进程 `I`（把卡片数据读入缓冲区 B1）、计算进程 `C`（从 B1 取数据处理后放入 B2）、输出进程 `P`（从 B2 取结果打印）。B1、B2 各可放 `n` 个数据，三个进程并发。用记录型信号量写出同步互斥结构，并说明 P 操作顺序能否交换。

**解**：需要 4 类信号量——两个缓冲区的「空/满」计数 + 每个缓冲区一把互斥锁。

```c
semaphore empty1 = n, full1 = 0, mutex1 = 1;
semaphore empty2 = n, full2 = 0, mutex2 = 1;

void input(void) {
    while (1) {
        read_card(&x);
        P(empty1);  P(mutex1);  put_B1(x);  V(mutex1);  V(full1);
    }
}
void compute(void) {
    while (1) {
        P(full1);   P(mutex1);  x = get_B1();  V(mutex1);  V(empty1);
        y = process(x);
        P(empty2);  P(mutex2);  put_B2(y);     V(mutex2);  V(full2);
    }
}
void output(void) {
    while (1) {
        P(full2);   P(mutex2);  y = get_B2();   V(mutex2);  V(empty2);
        print(y);
    }
}
```

**P 顺序不能交换**：以 `input` 为例，若写成 `P(mutex1); P(empty1);`，当 B1 已满时进程会**持着互斥锁阻塞在 empty1 上**，导致 `compute` 永远无法进入 B1 取走数据 → 死锁。口诀：**先申请资源（同步 P），再申请使用权（互斥 P）**；V 的顺序则可任意（不产生阻塞）。

### 综 2 · 资源分配图化简与死锁检测（第 4 章）

**题**：系统有 2 类资源 `R1(2 个实例)`、`R2(1 个实例)`，进程 P1、P2。当前：R1 的两个实例分别被 P1、P2 各占 1 个；R2 被 P2 占有；P1 正请求 R2，P2 正请求 R1。判断是否死锁。

**解**：画资源分配图——
`R1 → P1`、`R1 → P2`（分配边），`P1 → R2`、`P2 → R1`（请求边），`R2 → P2`（分配边）。
化简：P1 的请求 `R2` 无法满足（唯一实例被 P2 占有）；P2 的请求 `R1` 也无法满足（两个实例都已分配）→ **没有任何进程能获得全部资源并"孤立"出来，图不可完全化简 → 已死锁**，涉及 P1、P2 与 R1、R2。
解除：剥夺 P2 的 R2 给 P1（P1 完成后释放 R1 与 R2），或终止 P2 并回滚。

**对照**：若 R1 有 3 个实例（尚有 1 个空闲），则 P2 可先完成、释放 R1 与 R2，P1 再完成 → 图可完全化简 → **无死锁**（有环但每类资源有多个实例时不必然死锁）。

::: danger 结论
「资源分配图有环」**不等价于**死锁：只有当**每类资源都只有 1 个实例**时，环才是死锁的充要条件；多实例时环只是必要条件，必须做**化简**或跑检测算法（Work 扫描）。
:::

### 综 3 · 分页 + 快表 + 页表容量综合（第 5 章）

**题**：32 位逻辑地址、页大小 4 KB、页表项 4 B；TLB 查询 10 ns，一次访存 80 ns，TLB 命中率 95%。求：① 页内偏移位数与页号位数；② 单级页表大小；③ 引入 TLB 后的 EAT；④ 若改用两级页表且不用 TLB，EAT 又是多少；⑤ 逻辑地址 `0x0000 1234` 的页号与页内偏移（十六进制）。

**解**：
```text
① 4 KB = 2^12 → 页内偏移 12 位，页号 32−12 = 20 位
② 页表项数 = 2^20 = 1 048 576，大小 = 2^20 × 4 B = 4 MB（每进程一份、需连续）
③ EAT = 0.95×(10+80) + 0.05×(10+80+80) = 85.5 + 8.5 = 94 ns
④ 两级页表无快表 = 3 次访存 = 3 × 80 = 240 ns
⑤ 0x00001234 → 低 12 位 0x234 为偏移，高 20 位 0x1 为页号（即第 1 页，偏移 564 B）
```
**权衡结论**：多级页表把「连续 4 MB」降为「4 KB 外层 + 若干 4 KB 二级」，代价是每次访存多 1 次；**只有配合高命中率 TLB 才划算**（94 ns vs 240 ns）。

### 综 4 · 请求分页置换 + Belady + EAT 综合（第 6 章）

**题**：页面走向 `4 3 2 1 4 3 5 4 3 2 1 5`，分别求 3 块 / 4 块下 FIFO 与 LRU 的缺页次数；若 `ma = 100 ns`、一次缺页处理 `8 ms`，求 4 块 LRU 的 EAT，并判断有无 Belady 异常。

**解**（逐次追踪驻留集，方括号内按 FIFO 队列 / LRU 使用新旧排列）：

| 访问 | FIFO(3 块) | LRU(3 块) | FIFO(4 块) | LRU(4 块) |
| --- | --- | --- | --- | --- |
| 4 | 缺 `[4]` | 缺 `[4]` | 缺 `[4]` | 缺 `[4]` |
| 3 | 缺 `[4,3]` | 缺 `[4,3]` | 缺 `[4,3]` | 缺 `[4,3]` |
| 2 | 缺 `[4,3,2]` | 缺 `[4,3,2]` | 缺 `[4,3,2]` | 缺 `[4,3,2]` |
| 1 | 缺 淘汰4 `[3,2,1]` | 缺 淘汰4 `[3,2,1]` | 缺 `[4,3,2,1]` | 缺 `[4,3,2,1]` |
| 4 | 缺 淘汰3 `[2,1,4]` | 缺 淘汰3 `[2,1,4]` | **命中** | 命中 |
| 3 | 缺 淘汰2 `[1,4,3]` | 缺 淘汰2 `[1,4,3]` | **命中** | 命中 |
| 5 | 缺 淘汰1 `[4,3,5]` | 缺 淘汰1 `[4,3,5]` | 缺 淘汰4 `[3,2,1,5]` | 缺 淘汰2 `[1,4,3,5]` |
| 4 | 命中 | 命中 | 缺 淘汰3 `[2,1,5,4]` | 命中 |
| 3 | 命中 | 命中 | 缺 淘汰2 `[1,5,4,3]` | 命中 |
| 2 | 缺 淘汰4 | 缺 淘汰5 | 缺 淘汰1 | 缺 淘汰1 |
| 1 | 缺 淘汰3 | 缺 淘汰4 | 缺 淘汰5 | 缺 淘汰5 |
| 5 | 命中 | 缺 淘汰3 | 缺 淘汰4 | 缺 淘汰4 |
| **合计** | **9 次** | **10 次** | **10 次** | **8 次** |

```text
Belady 异常：FIFO 3 块 9 次 → 4 块反而 10 次 ✔ 出现；LRU 10 → 8 ✔ 正常
4 块 LRU 缺页率 p = 8/12 ≈ 0.667
EAT = (1−p)×100 ns + p×8×10^6 ns ≈ 5.33×10^6 ns ≈ 5.33 ms
```
**结论**：缺页率高达 66.7% 时系统实际已接近**抖动**状态，EAT 比无缺页慢约 5 万倍——此时增加物理块数（或降低多道程序度）比换置换算法更有效。

### 综 5 · 磁盘调度 + 访问时间综合（第 7、9 章）

**题**：磁盘 0–199 道，磁头在 **143**，请求队列（到达序）`86, 147, 91, 177, 94, 150, 102, 175, 130`；初始向磁道号增大方向。求 FCFS / SSTF / SCAN（到 199 折返）/ C-SCAN（回程不计）的总移动与平均寻道；若平均寻道 5 ms、转速 10 000 rpm、读 8 KB 的传输率 100 MB/s，估算单次访问时间。

**解**：

| 算法 | 服务序列 | 总移动 | 平均寻道 |
| --- | --- | --- | --- |
| FCFS | 143→86→147→91→177→94→150→102→175→130 | 565 | 62.78 |
| SSTF | 143→147→150→130→102→94→91→86→175→177 | **162** | 18.00 |
| SCAN | 143→147→150→175→177→199→130→102→94→91→86 | 169 | 18.78 |
| C-SCAN | 143→147→150→175→177→199→(0)→86→91→94→102→130 | 186 | 20.67 |

```text
平均旋转延迟 = 60 / 10000 / 2 = 3 ms
传输时间     = 8 KB / 100 MB/s ≈ 0.08 ms
单次访问     ≈ 5 (寻道) + 3 (旋转) + 0.08 (传输) ≈ 8.08 ms
```
**易错**：SSTF 虽总距离最小，但可能在中部磁道"粘着"造成远端饥饿；SCAN/C-SCAN 牺牲总距离换**等待时间上界**。SSD 上无寻道/旋转，本题的调度收益几乎消失。

### 综 6 · 文件索引 + 位示图 + 目录综合（第 8、9 章）

**题**：盘块 4 KB，盘块号 4 B；文件系统 inode 含 12 个直接地址 + 一级/二级/三级间接各 1。磁盘 512 GB。求：① 一个索引块可存多少个块号；② 最大文件长度；③ 访问三级间接中的数据块要几次磁盘 I/O；④ 位示图大小及其占用的盘块数；⑤ 若目录项 32 B、共 4096 个文件，顺序查找平均读多少盘块。

**解**：
```text
① k = 4096 / 4 = 1024 个块号
② (12 + 1024 + 1024² + 1024³) × 4 KB ≈ 12×4KB + 4MB + 4GB + 4TB ≈ 4 TB
③ inode(常驻/缓存) → 三级索引块 → 二级 → 一级 → 数据块：最多 4 次盘 I/O
④ 盘块数 = 512 GB / 4 KB = 2^27 = 134 217 728
   位示图 = 2^27 位 = 16 MB，占 16 MB / 4 KB = 4096 个盘块
⑤ 每块可放 4096/32 = 128 个目录项 → 4096 项需 32 块 → 顺序查找平均 (32+1)/2 = 16.5 块
```
**结论**：`inode 分离 + dentry 缓存 + 目录索引（如 ext4 的 htree / XFS 的 B+ 树）` 正是为了压低 ⑤ 的读盘次数；三级间接让大文件可达 TB 级，但代价是 4 次 I/O，所以现代文件系统用 **extent（连续区段）** 记录大文件以减少间接层数。

### 综 7 · CPU 时间、加速比与多核（第 3、10 章）

**题**：某程序串行部分占 20%，其余可并行。8 核运行相对单核的加速比是多少？若核数无限，上限是多少？若并行部分还因缓存一致性带来 10% 额外开销，8 核加速比变为多少？

**解**：
```text
Amdahl: S(N) = 1 / ((1−f) + f/N) = 1 / (0.2 + 0.8/8) = 1/0.3 ≈ 3.33
N→∞   : S ≤ 1/(1−f) = 1/0.2 = 5        （串行部分 20% 决定天花板）
含 10% 并行开销：并行段时间变为 (0.8/8)×1.1 = 0.11
S = 1/(0.2 + 0.11) ≈ 3.23
```
**结论**：加核收益**迅速递减**，且伪共享、锁竞争、NUMA 远端访存都会把 `f/N` 项抬高；工程上要先**减少串行段与共享写**，再考虑加核（Gustafson 定律则从"固定时间、放大问题规模"角度看扩展性）。

### 综 8 · 系统调用全过程简答模板（第 1、2、7 章）

**题**：描述用户进程执行 `read(fd, buf, n)` 到数据返回的全过程，并指出其中发生了几次态切换、可能在哪阻塞。

**答题要点**（按序）：
1. 用户态：库函数 `read` 准备参数（fd、buf、n），把**系统调用号**与参数放入约定寄存器/栈，执行陷入指令（`syscall` / `int 0x80` / `svc`）。
2. **用户态 → 内核态**（第 1 次切换，硬件完成）：按中断/异常向量查系统调用表，转 `sys_read`；同时保存用户现场（PC、PSW、通用寄存器）到内核栈。
3. 内核态：`sys_read` 校验 fd 与用户缓冲区合法性 → VFS → 具体文件系统/设备驱动 → 查**页缓存**：命中则直接拷贝；未命中则向磁盘发 I/O 请求。
4. **可能阻塞**：若数据未就绪，进程状态由**运行 → 阻塞**，挂入该设备的等待队列，调用**进程调度**切换到别的就绪进程（一次完整的上下文切换）。
5. 磁盘完成 → **DMA/中断** → 中断处理（上半部登记、下半部处理）→ **唤醒**阻塞进程（阻塞 → 就绪）→ 调度再次选中它（就绪 → 运行）。
6. 内核把数据从内核缓冲区拷到用户 `buf`（`copy_to_user`，须校验地址），设置返回值，**内核态 → 用户态**（第 2 次切换）恢复现场，库函数返回。
7. **态切换至少 2 次**（陷入 + 返回）；若发生阻塞，还额外有 2 次以上的**进程上下文切换**（切走 + 切回），且可能伴随 TLB 刷新/缓存冷启动。

::: tip 高频追问
- 为什么 `copy_to_user` 不能直接解引用用户指针？（用户地址可能未映射、可被换出、可能是恶意内核地址，须用带异常表的安全拷贝）
- 系统调用与库函数的区别？（前者陷内核、有态切换；后者可能完全在用户态，如 `strlen`；`malloc` 只在堆不够时才 `brk`/`mmap`）
- `read` 返回 0 表示 EOF，返回 −1 表示出错并置 `errno`；**短读**（返回值 < n）是合法的，须循环读。
:::

| 3 | 带权周转 | `W = T / 服务时间 Ts ≥ 1`，平均 `W` 越小越好 |
| 4 | 等待时间 | `T − Ts`（不含运行时间）；响应时间＝首次请求到首次响应 |
| 5 | 响应比 | `R = (等待 + 服务) / 服务 = 1 + 等待/服务` |
| 6 | SJF 最优性 | 非抢占 SJF 使**平均周转与平均带权周转最小**（可证明） |
| 7 | 切换开销占比 | `s/(q+s)`（s＝一次上下文切换耗时，q＝时间片） |
| 8 | RMS 可调度上界 | `U ≤ n(2^(1/n) − 1)`，`n→∞` 时 `→ ln2 ≈ 0.693` |
| 9 | 松弛度 | `LLF = 必须完成时刻 − 尚需运行时间 − 当前时刻` |
| 10 | Amdahl 定律 | `S = 1 / ((1−f) + f/N)`，上限 `1/(1−f)` |
| 11 | 信号量值 | `S>0`：可用资源数；`S<0`：\|S\| 为阻塞进程数；`V` 后 `≤0` 才唤醒 |
| 12 | 银行家判据 | `Need = Max − Allocation`；`Need_i ≤ Work` 才可假想完成并归还 `Allocation_i` |
| 13 | 死锁必要条件 | 互斥、请求和保持、不可剥夺、环路等待（全部满足才可能死锁） |
| 14 | 地址拆分 | 页大小 `L = 2^k` 时 `p = A / L`（高若干位）、`d = A mod L`（低 k 位） |
| 15 | 分页物理地址 | `PA = 块号 × L + d`；分段 `PA = 段基址 + 段内偏移`（须校验 `偏移 < 段长`） |
| 16 | 页表项数 | `2^(逻辑地址位数 − log2 L)`；页表大小 = 项数 × 每项字节数 |
| 17 | 单级页表例 | 32 位 / 4 KB / PTE 4 B → `2^20 × 4 B = 4 MB`（每进程） |
| 18 | TLB 有效访问时间 | `EAT = λ(t + ma) + (1−λ)(t + 2ma)`；无快表 `= 2ma`；两级页表 `= 3ma`；段页式 `= 3ma` |
| 19 | 例题数值 | `t=20 ns, ma=100 ns, λ=0.9 → EAT = 130 ns` |
| 20 | 虚存最大容量 | `min(2^(地址位数), 内存 + 外存可用空间)` |
| 21 | 虚存三特征 | 多次性、对换性、虚拟性 |
| 22 | 缺页率 | `p = 缺页次数 / 总访问次数`；`缺页率 = 1 − 命中率` |
| 23 | 请求分页 EAT | `EAT = (1−p)·ma + p·缺页处理时间`（p=1% 时约放大 1000 倍） |
| 24 | 置换算法性能 | OPT 最优（理论下界）< LRU ≈ Clock < FIFO；OPT/LRU 无 Belady 异常 |
| 25 | Belady 异常 | FIFO 在 `1 2 3 4 1 2 5 1 2 3 4 5` 上：3 块 9 次、4 块 10 次 |
| 26 | 改进型 Clock | 淘汰优先级 `(A,D) = (0,0) → (0,1) → (1,0) → (1,1)`，优先免写回 |
| 27 | 工作集 | `W(t, Δ)` = 最近 Δ 时间窗口内访问过的页集合；分配块数应 ≥ \|W\| |
| 28 | 单/双缓冲 | 单缓冲 `max(C,T)+M`；双缓冲 `max(C+M, T)` |
| 29 | 磁盘访问时间 | `Ta = Ts + 1/(2×转速) + 字节数/传输速率 + 控制器开销` |
| 30 | 磁盘例题 | 7200 rpm → `Tτ ≈ 4.17 ms`；4 KB / 200 MB/s → `Tt ≈ 0.02 ms` |
| 31 | 平均寻道长度 | `总移动磁道数 / 请求数`；SCAN/CSCAN 须先声明是否计入到端点与回程 |
| 32 | 磁盘调度例题 | 100 起步、9 请求：FCFS 498 / SSTF 248 / SCAN 280 / C-SCAN 189 |
| 33 | 索引分配块号容量 | `k = 盘块大小 / 盘块号字节数`（1 KB / 4 B → 256） |
| 34 | 混合索引最大文件 | `(直接数 + k + k² + k³) × L`；例 10 直接 → `≈ 16 GB`（k=256, L=1 KB） |
| 35 | 位示图大小 | `盘块总数 / 8` 字节；1 GB / 1 KB 块 → 128 KB |
| 36 | 位示图换算 | 从 0 起：`b = n·i + j`；从 1 起：`b = n(i−1) + j` |
| 37 | RAID 容量 | RAID0 = 100%；RAID1/10 = 50%；RAID5 = `(N−1)/N`；RAID6 = `(N−2)/N` |
| 38 | 事务 ACID | 原子性、一致性、隔离性、持久性；检查点缩短恢复重放范围 |
| 39 | IPC 开销 | 共享内存（映射后无内核中转拷贝）> 管道/消息队列 > 套接字 |
| 40 | 死锁处理代价 | 预防（最保守）→ 避免（需预知）→ 检测+解除（事后） |
| 41 | 加速与并行 | 多核加速受串行比例与缓存一致性/伪共享制约，非随核数线性增长 |
| 42 | 虚拟化 | EPT/NPT 做 GVA→GPA→HPA 两级硬件翻译；容器＝namespace 隔离 + cgroup 限额 |

::: tip 记忆口诀
**调度**：「先来短作高响应，轮转反馈实时忙」；**同步**：「先同步后互斥，P 减 V 加，V 不阻塞」；**死锁**：「互请不环，破一即可」；**存储**：「分页一维段二维，快表命中省一次」；**置换**：「OPT 看未来、LRU 看过去、FIFO 看资历、Clock 看访问位」；**磁盘**：「先寻道、再旋转、后传输」。
:::

## 附录 B 易错点速查

1. **并发 ≠ 并行**：单 CPU 只有并发；并行必须多核/多处理机。
2. 多道批处理追求**利用率与吞吐**，分时追求**响应时间**，实时追求**截止时间**。
3. 四大特性中「并发」是前提；共享分互斥共享与同时访问两种。
4. 异步不代表结果不可再现：同步正确时结果必须可再现。
5. 特权指令只能在内核态执行；用户程序**不能自行修改** PSW 模式位。
6. 系统调用是**陷入（trap）**，不是外部中断；但处理时可能关中断。
7. 中断与当前指令无关、指令结束后响应；异常由当前指令引起，缺页处理后要**重新执行**该指令。
8. 微内核「微」指功能少、IPC 多导致**性能更低**；Linux 是宏内核 + 模块。

9. 进程是**资源分配**单位（传统 OS 也是调度单位），线程是 **CPU 调度**单位。
10. PCB 是进程存在的唯一标志，常驻内核；上下文切换只保存处理机状态。
11. 阻塞→运行、就绪→阻塞都**不可能**；阻塞是主动、唤醒是被动。
12. 挂起 ≠ 阻塞：挂起已换出到外存；挂起进程不能被直接调度。
13. `fork` 后父子共享**代码段**但各自独立地址空间（COW）；`exec` 才替换映像。
14. 僵尸＝子终止父未 `wait`（占 PCB）；孤儿＝父先亡，被 1 号进程收养。
15. `printf` 无换行且重定向到文件时，`fork` 会因 stdio 缓冲复制而重复输出。
16. ULT 一个线程阻塞→**整个进程阻塞**，且无法多核并行；KLT 切换需陷入内核。
17. 共享内存「最快」指映射建立后免内核中转拷贝，**不自带同步**。

18. 周转时间含运行 + 等待；等待时间**不含运行**；`W = T/Ts ≥ 1`。
19. 响应比用于**调度决策**，带权周转用于**事后评价**，二者别混。
20. SJF 平均周转最优，但需预知服务时间且长作业饥饿；SRTF 按**剩余**时间抢占。
21. RR 时间片过大退化为 FCFS，过小则切换开销占比 `s/(q+s)` 过高。
22. 抢占发生时被抢占进程回**原队列队尾**（MFQ 中通常不降级）；MFQ 时间片逐层递增。
23. HRRN 每次调度都要重新计算响应比，等待越久 `R` 越大，长作业不会无限饥饿。
24. 优先级倒置的解法是**优先级继承 / 优先级天花板**，不是简单提高中断优先级。
25. EDF 是动态优先级、单处理器最优；RMS 是静态优先级，周期越短越优先。
26. 「调度时机」中，处于内核临界区、执行原语、处理中断时**不能**调度。

27. 临界区四准则：空闲让进、忙则等待、有限等待、让权等待；忙等方案违反最后一条。
28. Peterson 用 `flag + turn` 满足前三准则，但只适两进程且忙等。
29. 关中断法只适用**单 CPU**，且绝不能交给用户进程。
30. 整型信号量忙等；记录型信号量才通过阻塞队列实现让权等待。
31. `S.value < 0` 时 `|S.value|` 是阻塞进程数；`V` 后 `≤ 0` 才需唤醒。
32. **P/V 顺序**：生产者-消费者中必须先 `P(empty)` 后 `P(mutex)`，颠倒会死锁。
33. `V` 永不阻塞；`P` 才可能阻塞。
34. 读者优先会导致**写者饥饿**；写者优先需额外信号量阻止新读者进入。
35. 哲学家进餐三解法：限人数（room=4）、奇偶号反向取叉、AND 型信号量原子取两叉。
36. 条件变量检查条件必须用 `while` 而非 `if`（防虚假唤醒）。
37. 死锁四必要条件**全部满足**才可能死锁；破任一即可预防。
38. 资源按序申请破坏的是**环路等待**，不是互斥条件。
39. 安全状态一定无死锁；不安全状态**不一定已死锁**。
40. 银行家安全检查中，假想完成的进程归还的是 **Allocation**，不是 Max 或 Need。
41. 安全序列**不唯一**；找出一个即可判定安全。
42. 银行家算法是理论模型，通用 OS 因「最大需求难预知 + 开销大」基本不实现。

43. 静态重定位装入后地址**不能再变**；紧凑必须依赖动态重定位。
44. 内存保护由**硬件**在每次访存时检查，OS 只负责设置基址/限长与页表项。
45. 固定分区产生**内部碎片**，动态分区产生**外部碎片**。
46. 最佳适应 BF 留下最多难以利用的极小碎片；「最佳」并非全局最优。
47. 回收分区四种情况：前邻、后邻、前后都邻、都不邻。
48. 分页**只有页内碎片**（最后一页），无外部碎片；分段有段间外部碎片。
49. 分页地址一维、段内偏移**原样保留**；分段地址二维、需做「基址 + 偏移」加法。
50. 两级页表省内存但**多一次访存**；段页式访问数据需 3 次访存。
51. 页表大小随**虚拟地址位数**指数增长，与进程实际占用内存无关。
52. 反置页表按物理块组织、全系统一张，但**难以实现共享内存**。

53. 虚存容量上限受**地址位数**约束（32 位 → 4 GB），不能只看磁盘大小。
54. 虚存必须建立在**离散分配**基础上；连续分配无法实现。
55. 缺页中断在指令**执行期间**产生，一条指令可触发多次，处理后**重新执行**。
56. 修改位 D=0 的牺牲页**无需写回**；改进型 Clock 优先淘汰 (0,0)。
57. 缺页率哪怕 1%，EAT 也会放大约 1000 倍（磁盘 I/O 是 ns 与 ms 的差距）。
58. FIFO 有 **Belady 异常**（块数增加缺页反而上升）；LRU/OPT 是栈式算法，不会出现。
59. 抖动根因是多道程序度过 + 全局置换；局部置换与工作集可缓解。
60. 预调页用于首次装入、请求调页用于运行期按需；预调不准反而浪费 I/O。
61. `mmap` 的 `MAP_SHARED` 修改**不保证即时落盘**，需 `msync`/`fsync`。
62. Windows XP / 早期 Linux 虚存实例的 32 位结论已不适用于 64 位现代系统。

63. DMA 传送数据**不经过 CPU**，但 CPU 要负责启动与收尾中断。
64. DMA 争用总线用「周期窃取」，CPU 被短暂暂停而**不是**被中断。
65. I/O 通道能执行通道程序，比 DMA 更高一级；现代已被智能控制器取代。
66. 中断上半部要极短（关中断），耗时工作放下半部（softirq/工作队列）。
67. 设备分配顺序「设备 → 控制器 → 通道」，失败要**回溯释放**。
68. SPOOLing 把独占设备虚拟为共享设备，但**不缩短单个作业响应时间**。
69. 缓冲区解决速度/粒度不匹配，缓存解决慢设备重复访问（局部性）。
70. 单缓冲 `max(C,T)+M`；双缓冲 `max(C+M, T)`，后者才让设备与 CPU 完全重叠。
71. 机械盘 `Ta` 中寻道 + 旋转占绝大部分；SSD 无机械定位，SCAN/SSTF 意义下降。
72. SSTF 可能饥饿；SCAN 可能"刚扫过要等一趟"；LOOK 只到最远请求可省空走。

73. 隐式链接组织**不能随机访问**；显式链接（FAT）需要整表常驻内存。
74. 索引分配的最大文件长度按 **k 的幂次相乘**（不是相加）。
75. 访问二级间接块需 3 次磁盘 I/O；直接地址只需 1 次。
76. 位示图换算要**先确认从 0 还是从 1 编号**，两套公式不同。
77. inode 分离减小目录项、降低查目录的磁盘 I/O；硬链接即多个目录项指向同一 inode。
78. 硬链接不能跨文件系统、一般不能链目录；符号链接可跨、可链目录，但会悬空。
79. ACL 按列（对象）存，capability 按行（域/进程）存、便于传递但难撤销。
80. `write` 成功通常只表示进入页缓存，**`fsync`** 才保证落盘；日志/COW 保证崩溃一致性。

81. RAID 0 无容错；RAID 5 校验**分布**在各盘；RAID 不能替代备份。
82. 事务持久性靠稳定存储 + 日志；检查点缩短恢复重放范围。
83. SSD 写前擦除导致写放大；TRIM 通知无效块以减轻 GC。
84. RAID5 利用率 `(N−1)/N`、RAID6 `(N−2)/N`、RAID10 50%。

85. UMA 各核访存时间相同；NUMA 访问远端内存更慢，须做亲和绑定。
86. 自旋锁只适合持锁时间**短于两次上下文切换**且多核的场景；单 CPU 自旋无意义。
87. RCU 让读者零开销、写者承担复制与宽限期回收；适合读多写少。
88. 伪共享源于多个核写同一 Cache 行的不同变量，用缓存行填充规避。

89. VMM 裸金属型（Type 1）跑在硬件上；宿主机型（Type 2）跑在宿主 OS 上。
90. EPT/NPT 由**硬件**完成两级地址翻译，替代高开销的影子页表。
91. 容器共享宿主内核，靠 namespace 隔离 + cgroup 限额；隔离性弱于 VM。
92. 加密用接收方**公钥**、签名用发送方**私钥**；「缓冲区溢出」属程序漏洞而非内外攻击维度。
