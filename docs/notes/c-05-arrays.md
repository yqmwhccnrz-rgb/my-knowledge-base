# 第5章 数组

## 5.1 定义数组

```c
<类型> 变量名称[元素数量];

int grades[100];
double weight[20];
```

- 元素数量必须是整数
- C99 之前：元素数量必须是编译时刻确定的字面量

## 5.2 数组的特点

数组是一种容器（放东西的东西），特点是：

- 其中所有的元素具有相同的数据类型
- 一旦创建，大小不能改变
- 数组中的元素在内存中是连续依次排列的
- 数组的每个单元就是该类型的一个变量，可以出现在赋值的左边或右边（在赋值左边的叫做**左值**）

```c
int a[10];              /* 10 个单元：a[0], a[1], ... a[9] */
a[2] = a[1] + 6;        /* 下标做左值，也可以做右值 */
```

使用数组时放在 `[ ]` 中的数字叫做**下标**或**索引**，下标从 0 开始计数：`grades[0]`、`grades[99]`、`average[5]`。

## 5.3 下标越界

::: danger 易错点
编译器和运行环境都**不会检查**数组下标是否越界（无论读还是写都不检查）。一旦程序运行时越界，可能造成数据被改写、导致程序崩溃（segmentation fault），但也可能运行得好好的、没造成严重后果 —— 所以保证下标在 `[0, 数组长度-1]` 之内是程序员的责任。
:::

原笔记还提到 `int a[0];` 可以存在。

::: warning 订正 · 零长数组不是标准 C
标准 C 要求数组长度是**大于 0** 的整型常量表达式（VLA 同理）。`int a[0];` 是 GCC / Clang 的扩展，加上 `-pedantic` 就会告警，在 MSVC 等编译器上会直接报错。结构体末尾的「柔性数组成员」要写 `int a[];`（C99），而且它只能作为结构体的最后一个成员、且不能单独定义对象 —— 这跟 `a[0]` 不是一回事。
:::

::: info 补充 · 越界为什么难以发现
它属于**未定义行为**，不是「一定会崩」。可用工具帮忙：`gcc -fsanitize=address`（ASan）会在越界访问时立刻报告文件名和行号；Valgrind、Clang 的 UBSan 也有效。调试阶段养成打开 sanitizer 的习惯，比事后找随机崩溃划算得多。
:::

## 5.4 数组初始化

**集成初始化**：

```c
int a[10] = {0};   /* 其余位置自动补零 */
```

**C99 支持定位初始化（C99 ONLY）**：

```c
int a[10] = { [0] = 2, [2] = 3, 6, };
```

- 用 `[n]` 在初始化数据中给出定位
- 没有定位的数据接在前面的位置之后（上例的 `6` 落在 `a[3]`）
- 其他位置的值补零
- 也可以不给出数组长度，让编译器去数：`int a[] = {1, 2, 3};`
- 特别适合初始数据稀疏的数组

**数组的大小**：`sizeof` 给出数组所占的字节数，元素个数 = `sizeof(a) / sizeof(a[0])`。

**数组的赋值**：一个数组不能直接赋值给另一个数组，只能逐个单元复制。

```c
for (i = 0; i < length; i++) {
    b[i] = a[i];   /* 复制数组 */
}
```

**const 数组**：

```c
const int a[] = {1, 2, 3, 4, 5, 6,};
```

::: danger 订正 · "数组变量已经是 const 的指针"
原笔记用「数组变量是 const 的指针」来解释为什么 `const int a[]` 表示每个单元都是 `const int`，这个说法不严谨：

- **数组名不是指针变量**。它是数组类型的表达式，在大多数上下文里会**退化**（decay）为指向首元素的指针值，这个值不是可修改的左值，所以不能赋值。
- 正因为是退化而不是"本身是指针"，`sizeof(a)` 在数组所在作用域得到**整个数组的字节数**，而一旦作为函数参数传进去，`sizeof(a)` 就变成指针大小了。
- `const int a[]` 里的 `const` 修饰的是**元素类型**，所以每个单元都是 `const int`，必须在初始化时赋值，之后不能改。

把「退化」和「指针变量」分清楚，后面第 6 章的指针运算才不会绕。
:::

::: info 补充 · 复制数组的正确姿势
除了循环，还可以用 `memcpy(b, a, sizeof(a))`（需 `<string.h>`），前提是目标空间足够且两块内存不重叠；重叠时用 `memmove`。注意 `sizeof(a)` 只在数组作用域内有效，传进函数后要显式传长度。
:::

## 5.5 遍历数组

通常都是使用 `for` 循环，让循环变量 `i` 从 0 到 **< 数组长度**，这样循环体内最大的 `i` 正好是数组最大的有效下标：

```c
for (i = 0; i < length; i++) {
    if (a[i] == key) {   /* 查找 */
        ret = i;
        break;
    }
}
```

**完整例：统计数字出现次数**

```c
const int number = 10;
int x;
int count[number];      /* 定义数组 */
int i;

for (i = 0; i < number; i++) {
    count[i] = 0;      /* 初始化数组 */
}

scanf("%d", &x);
while (x != -1) {
    if (x >= 0 && x <= 9) {
        count[x]++;    /* 数组参与运算 */
    }
    scanf("%d", &x);
}

for (i = 0; i < number; i++) {
    printf("%d:%d\n", i, count[i]);
}
```

::: danger 易错点
常犯的两个错误：

1. 循环结束条件写成 `<= 数组长度`（越界）；
2. 离开循环后，继续用 `i` 的值来做数组元素的下标（此时 `i` 已经等于数组长度，正好越界）。
:::

::: info 补充 · 让长度自己算
尽量别把长度写死成魔法数字：

```c
int a[] = {3, 1, 4, 1, 5};
size_t n = sizeof(a) / sizeof(a[0]);
for (size_t i = 0; i < n; i++) { ... }
```

`sizeof` 返回 `size_t`（无符号），循环变量也用 `size_t` 可避免有符号/无符号比较告警。
:::

## 5.6 二维数组

```c
int a[3][5];   /* 三行五列的矩阵 */
```

`a[i, j]` 是**错误**的 —— 逗号运算让整个表达式最后只表达为 `a[j]`（详见 2.11），二维数组必须写 `a[i][j]`。

**初始化**：

```c
int a[][5] = {
    {0, 1, 2, 3, 4},
    {2, 3, 4, 5, 6},
};
```

- 列数是必须给出的，行数可以由编译器来数
- 每个 `{ }` 一行，逗号分隔
- 最后的逗号可以存在，有古老的传统
- 如果省略，表示补零
- 也可以定位初始化（C99 ONLY）

::: info 补充 · 内存是"一维"的
二维数组在内存里仍然是**按行连续排列**的一整块：`a[0][0], a[0][1], ..., a[0][4], a[1][0], ...`。因此可以用 `a[0]` 当作指向首元素的指针做线性遍历，也解释了为什么声明时**只有第一维可以省略** —— 编译器必须知道一行有多长才能算出 `a[i]` 的偏移。

传二维数组给函数时，除第一维外的维度必须写全：

```c
void fill(int a[][5], int rows);        /* 等价写法：int (*a)[5] */
```
:::
