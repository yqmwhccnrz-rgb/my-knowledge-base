# 第6章 指针

## 6.1 取地址运算 &

`scanf("%d", &i);` 中的 `&`：获得变量的地址，它的操作数必须是**变量**。

- `&` 不能对别的东西取地址（如 `a++`、`++i` 不是变量）
- 想要输出地址，用 `%p` 作占位符
- 地址的大小是否与 `int` 相同取决于编译器和平台
- 相邻数组元素的地址差正好是元素类型的大小（`int` 数组相邻元素相差 4 个字节）

```c
int i;
printf("%p", &i);
```

::: warning 订正 · %p 需要 void*
`%p` 期望的参数类型是 `void *`，而 `&i` 是 `int *`。虽然多数平台上两者表示相同，但可变参数不做类型转换，严格来说是未定义行为。正确写法：

```c
printf("%p\n", (void *)&i);
```
:::

::: info 补充 · 指针大小由数据模型决定
32 位程序通常 4 字节，64 位程序通常 8 字节，与 `int`（通常恒为 4 字节）无关。需要能容纳指针的整数类型用 `<stdint.h>` 的 `uintptr_t`，不要强转进 `int`。
:::

## 6.2 指针变量

**指针就是保存地址的变量。**

```c
int i;
int *p = &i;
```

::: danger 易错点
`int* p, q;` 中**只有 `p` 是指针**，`q` 是普通的 `int`！星号只修饰最近的变量名（写成 `int *p, q;` 与之等价）。建议每次只定义一个指针，或用 `typedef` / 分行声明。
:::

**示意图**：

```
普通变量的值是实际的值：
count  ┌─────┐
       │  7  │
       └─────┘

指针变量的值是另一个变量的地址：
countPtr ────► count
```

指针变量的值是「具有实际值的变量的地址」。

## 6.3 解引用 *

`*` 是一个单目运算符，用来访问指针的值所表示的地址上的变量。可以做右值也可以做左值（在左边是写，在右边是读取）：

```c
int k = *p;      /* 读取：k 得到 p 所指变量的值 */
*p = k + 1;      /* 写：p 所指的变量被改成 k+1 */
```

`*p` 是一个 `int`。

::: danger 补充 · 解引用前必须确认指针有效
对 `NULL`、未初始化、已 `free`、或指向已失效栈帧的指针解引用，都是未定义行为。养成两习惯：定义时立即初始化（`int *p = NULL;`），使用前判断（`if (p != NULL)`）。
:::

## 6.4 指针的应用场景

**1. 交换两个变量的值（配合函数，实现真正的交换）**

```c
void swap(int *pa, int *pb) {
    int t = *pa;
    *pa = *pb;
    *pb = t;
}
```

::: tip 提示
对照 4.6 的失败版本：函数拿到地址后，通过 `*` 访问到的就是调用处真正的变量，所以能修改它们。
:::

**2. 函数返回多个值**：函数返回运算的**状态**，结果通过指针返回。

常用的套路是让函数返回特殊的不属于有效范围内的值来表示出错：`-1` 或 `0`。但是当任何数值都是有效的可能结果时，就得把「状态」和「结果」分开返回了。

**3. 其他典型场景**：

- 需要传递较大的数据时作参数（省去复制）
- 传数组后对数组做操作
- 函数返回不止一个结果
- 需要函数来修改不止一个变量
- 动态申请的内存

## 6.5 const 与指针

**指针是 const**：表示一旦得到了某个变量的地址，不能再指向其他变量。

```c
int * const q = &i;
*q = 26;   /* OK */
q++;       /* ERROR */
```

**所指是 const**：表示不能通过这个指针去修改那个变量（**并不能使那个变量本身成为 const**）。

```c
const int *p = &i;
*p = 26;   /* ERROR（*p 是 const） */
i = 26;    /* OK */
p = &j;    /* OK */
```

::: tip 核心结论
> 规律：`const` 在 `*` 的**前面** → 所指的东西不能修改；`const` 在 `*` 的**后面** → 指针本身不能被修改。

```c
const int *p;        /* 所指只读 */
int const *p;        /* 同上，写法等价 */
int * const p;       /* 指针只读 */
const int * const p; /* 两者都只读 */
```
:::

**转换**：总是可以把一个**非 const** 的值转换成 const 的（反过来要显式强转，且可能引发 UB）。

**保护数组值**：因为把数组传给函数时传递的是地址，所以函数内部可以修改数组的值。为了保护数组不被函数破坏，可以把参数设为 const：

```c
void f(const int *x);
int sum(const int a[], int length);   /* 等价：a 的元素只读 */

int a = 15;         f(&a);        /* OK */
const int b = a;    f(&b);        /* OK */
b = a + 1;                       /* Error! */
```

当要传递的参数的类型是地址的时候，这是常用的手段：既能用较少的字节数传递值给参数，又能避免函数对外面的变量的修改。

## 6.6 指针运算

给一个指针加 1 表示要让指针指向**下一个变量**（地址增加 `sizeof(类型)`）：

```c
int a[10];
int *p = a;
*(p + 1);   /* -> a[1] */
```

- 如果指针不是指向连续分配的空间（如数组），则这种运算没有意义
- 可以对指针做的算术运算：给指针加、减一个整数（`+`、`+=`、`-`、`-=`）；递增递减（`++` / `--`）；两个指针相减（得到它们之间相差的**元素个数**）
- `*p++`：取出 p 所指的那个数据来，完事之后顺便把 p 移到下一个位置去
- `*` 的优先级虽然高，但是没有 `++` 高
- 指针比较：`<`、`<=`、`==`、`>`、`>=`、`!=` 都可以对指针做，比较的是它们在内存中的地址；数组中的单元的地址肯定是线性递增的
- 常用于数组类的连续空间操作，在某些 CPU 上可以直接被翻译成一条汇编指令

::: warning 补充 · 指针比较的边界
标准只保证**同一数组内**（以及"恰好越过末尾一个位置"）的指针比较和相减有定义；两个不相关对象的指针互相比较大小是未指定的。另外 `p + n` 越出数组范围（除了末尾后一位）本身就是 UB，即使不解引用。
:::

## 6.7 数组与指针

**0 地址**：内存中有 0 地址，但 0 地址通常是个不能随便碰的地址，所以指针不应该随意具有 0 值。因此可以用 0 地址来表示特殊的事情：返回的指针是无效的；指针没有被真正初始化（先初始化为 0）。`NULL` 是一个预定义的符号，表示 0 地址。

::: warning 订正 · 空指针不等于"物理地址 0"
`NULL` 是**空指针常量**，标准只保证它与任何有效对象/函数的指针都不相等，并不要求它在机器层面就是全 0 位模式（虽然绝大多数实现如此）。写 `NULL` 或 C23 的 `nullptr`，不要写 `0` 或 `(void*)0` 之外的魔法值；判断时用 `if (p == NULL)` 或简写 `if (!p)`。
:::

**指针的类型**：

- 无论指向什么类型，所有指针的**大小**都是一样的，因为都是地址
- 但是指向不同类型的指针是不能直接互相赋值的，这是为了避免用错指针
- `void *` 表示「不知道指向什么的指针」，可以和其他对象指针互相转换（无需强转）
- 指针也可以转换类型：

```c
int *p = &i;
void *q = (void *)p;
```

这并没有改变 `p` 所指的变量的类型，只是让后面用不同的眼光通过 `q` 看它所指的变量。

::: danger 订正 · void* 不能做算术
原笔记写「`void *` 计算时与 `char *` 相同」。标准 C 里 `void *` 是**不完整类型**，不能解引用、也不能做 `+` / `++` 等指针算术（GCC 把它当 `char *` 是非标准扩展，`-pedantic` 会告警）。要做字节级偏移，显式转成 `unsigned char *` 或 `char *`。
:::

**数组与指针的关系**：

数组变量本身表达地址，所以：

```c
int a[10];
int *p = a;        /* 不需要 & 取地址 */
```

但是数组的单元表达的是变量，需要 `&` 取地址。

- `a == &a[0]`
- `[ ]` 运算符可以对数组做，也可以对指针做：`p[0] <==> a[0]`
- `*` 运算符可以对指针做，也可以对数组做：`*a = 25;`
- 数组名不能赋值（详见第 5 章「退化」的订正）

**函数参数表中的数组实际上是指针**：`sizeof(a) == sizeof(int *)`，但是可以使用数组的运算符 `[ ]` 进行运算。

```c
int isPrime(int x, int knownPrimes[], int numberofKnownPrimes) {
    int ret = 1;
    int i;
    for (i = 0; i < numberofKnownPrimes; i++) {
        if (x % knownPrimes[i] == 0) {
            ret = 0;
            break;
        }
    }
    return ret;
}
```

以下四种函数原型是等价的：

```c
int sum(int *ar, int n);
int sum(int *, int);
int sum(int ar[], int n);
int sum(int [], int);
```

## 6.8 动态内存分配

```c
#include <stdlib.h>

void *malloc(size_t size);
```

- 向 `malloc` 申请空间的单位是**字节**
- 返回的结果是 `void *`，需要转换为需要的类型：`(int *)malloc(n * sizeof(int))`
- 如果没空间，则 `malloc` 会返回 `0` 或者 `NULL`
- 申请过的空间，最终都应该要还（借出来，迟早都是要还的）
- 只能还申请来的空间的**首地址**

**`free()`**：把申请得来的空间还给「系统」。

::: danger 易错点 · 常见问题
1. 申请了没 `free` —— 长时间运行内存逐渐下降（新：忘了；旧：找不到合适的 `free` 时机）
2. `free` 过了再 `free`（double free）
3. 地址变过了，直接去 `free`（传入的不是当初返回的首地址）
:::

::: info 补充 · 现代写法与配套函数
`malloc` 的返回类型在 C 里**不需要强转**（`void *` 会自动转换），强转反而可能掩盖漏写 `#include <stdlib.h>` 的错误。推荐写法：

```c
int *a = malloc(n * sizeof *a);   /* 跟着变量类型走，改类型时不会漏改 */
if (a == NULL) { /* 处理失败 */ }
/* ... 使用 ... */
free(a);
a = NULL;                          /* 避免悬垂指针被误用 */
```

配套：`calloc(n, size)` 会把内存清零；`realloc(p, new_size)` 调整大小（失败时返回 NULL 且**原内存仍有效**，别直接把返回值赋回 `p`）。另外 `malloc` 出来的内存**未初始化**，直接读是 UB。检测泄漏可用 ASan 的 LeakSanitizer 或 Valgrind。
:::
